# V860III-C 验证记录与实机清单

本文是 **Godox V860III-C V1.3** 私有密钥补丁（C.Fn `LIGHT` 开关版）的
**离线验证记录**与**实机测试清单**。逆向结论与补丁规格见 [`../README.md`](../README.md)。

> ⚠️ 现状：**离线 `verify()` 35 项 PASS、Lead `call_harness.py` 交叉验证 PASS；
> 整机模拟器未建立；实机未验证。**
> 判定口径：补丁只看 **`settings[8]` = RAM `0x20001092`**（C.Fn item 8 `LIGHT` 的值）。
> **`LIGHT = ON`（值 2）= 密钥模式**；`12sec`（值 0，出厂默认）/ `OFF`（值 1）= 原厂普通模式。

## 1. 离线验证：`verify()` 做了什么（35 项）

[`keypatch/devices/v860iiic.py`](../../../keypatch/devices/v860iiic.py) 的
`verify(patched, key)` 分四层、共 **35 项**（本机实测 35 PASS / 0 FAIL）：

| 层 | 项数 | 断言 | 说明 |
|---|---|---|---|
| 静态-函数 | 4 | 长度 87,612 B；补丁区 56 B 与期望函数体完全一致；结束于 `0x08012320` 不越界；三个字面量 KEY/FLAG/50024 落位 | 原位补丁 + 边界 |
| 静态-补丁点 | 6 | 注入代码 @`0x080179C2`（10 B）；两个 gate（`0x0800630C`/`0x0800D53E`）已是 `BL` 注入；三个读者/保护点（`0x080036AE`/`0x080036D6`/`0x0800A7EA`） | 新增的 6 处补丁点 |
| 静态-差异范围 | 2 | 与原厂差异集合 ==（7 处补丁点，共 **71 B**）；差异之外 0 处 | 证明没有改到别处 |
| Unicorn-补丁版 | 14 | 说明行 1 + flag=2（LIGHT=ON）ID=0/5/99 → KEY（3）+ flag=0（12sec）ID=0/1/5/37/99（5）+ flag=1（OFF）ID=0/1/5/37/99（5） | Cortex-M0 直接执行补丁后机器码，桩替换 `WriteReg`/`strobe`/`delay` |
| Unicorn-注入 hook | 4 | item=6(ID)/8(LIGHT)/5/11 改值 → 各调用同步字函数 1 次、r0=ID、r0..r4 原样恢复 | C.Fn 改值即时生效 |
| Unicorn-原厂自证 | 5 | 同一 harness 跑原厂函数（ID=0/1/5/37/99）→ 原厂公式 + `delay(20)+SCAL(0x33)+delay(1000)` | 证明「补丁只改了该改的」 |

### 1.1 复现命令

```powershell
# 仓库根
# ① 单设备补丁 + 离线验证（输出到 %TEMP%，不覆盖正式成品）
tools\python\python.exe keypatch\keypatch.py patch --device v860iiic --key 0x6B21 --verify --out %TEMP%\kp_v860iiic

# ② 总自检（逐台跑 Lead 交叉验证 + 模块 verify）
tools\python\python.exe keypatch\selftest.py --key 0x6B21

# ③ Lead 的独立调用级交叉验证（原厂 / 开关 ON / 开关 OFF 三路对比）
tools\python\python.exe keypatch\dev\lead\call_harness.py
```

> 注：本轮交付实测 ①（35 项）与 ③（Lead harness PASS）；② 是聚合命令，本轮未跑。

产物命名（`DEVICE["out_name"]` / `DEVICE["container_name"]`）：

- 裸镜像：`V860IIIC_V1.3_key{key:04X}.bin`（长度同原厂 87,612 B，G3 直接刷）；
- 容器备用件：`V860IIIC_V1.3_key{key:04X}_container.bin`（G3 报「固件与设备不匹配」时兜底）。

> 产物 sha256 随密钥变化，需以实际生成为准；`verify()` 对任意合法密钥都成立。

## 2. 离线验证覆盖不到的部分

1. **整机启动 / 主循环**：V860III-C **没有整机模拟器**，启动链、外设、看门狗都没回归；
2. **空口同步过滤**：Unicorn 只验证「写了正确的 SYNC1/SYNC0」，真正的射频同步必须真机；
3. **C.Fn 菜单/显示**：item 8 `LIGHT` 的菜单文本、三档显示（`12sec/OFF/ON`）、可选中/改值，
   只有静态渲染证据（`0x08004F92 cmp #8` + 三档字形选择），**未实机确认**；
4. **造型灯行为**：原厂 LIGHT 三档控制造型灯模式；补丁把两个功能读者固定为 0（12sec 档），
   需确认造型灯输出与预期一致；
5. **无线设置同步覆盖**：已 NOP `0x0800A7EA`（紧凑解包写 `settings[8]`），
   但另有一处整体写 `settings[8]` 的路径（`0x0800E18A`，位于 `0x0800DDB4` 函数内）未屏蔽，需实测；
6. **持久化**：`settings[8]`（LIGHT 值 0/1/2）重启后是否保持（依赖原厂 flash 记录保存/加载）；
7. **显示/UI**：本轮完全没碰 UI/字库，只复用原厂 C.Fn 菜单项；
8. **其它功能回归**：改 ID、频道、BEEP 等 C.Fn 项与原厂菜单行为是否一致。

## 3. 实机测试清单（风险自负，按顺序做）

前置：官方 **G3 V2.0** 能识别设备；手上有
`devices/v860iiic/firmware/V860IIIC_V1.3.bin` 可回滚；**密钥模式需要引闪器也刷同一把密钥**。

- [ ] 刷 `V860IIIC_V1.3_key<KEY>.bin` 后能正常开机、菜单显示正常、版本号仍是 V1.3；
- [ ] 进 **C.Fn 菜单**确认第 3 页第 1 行 **`LIGHT`**，可在 `12sec/OFF/ON` 三档间切换；
      新刷/恢复出厂后应为 `12sec`（`settings[8]=0`）；
- [ ] **普通模式**：`LIGHT = 12sec`（或 `OFF`），ID=1..99，与同 CH/ID 的原厂引闪器/灯能正常引闪；
- [ ] **密钥模式**：`LIGHT = ON` + 已打补丁的引闪器（同一把密钥）→ 能引闪；
- [ ] **隔离验证**：引闪器切回普通模式后，`LIGHT = ON` 的灯**不被引闪**（密钥生效）；
- [ ] **即时生效**：不动其它设置，仅来回切 LIGHT `ON ↔ 12sec`，确认同步字立即切换；
- [ ] **造型灯（LIGHT 代价）**：确认造型灯输出保持原厂 `12sec` 档行为；C.Fn 里改 LIGHT
      不再改变造型灯模式（用户接受的取舍见 [`../README.md`](../README.md) §6.6）；
- [ ] **持久化**：重启设备后 `LIGHT` 仍为 `ON`；恢复出厂后回到 `12sec`（普通模式）；
- [ ] **无线设置同步覆盖检查**：用 G3/引闪器做一次「设置同步/远程设置」，确认 `settings[8]`
      不被清回 0/1；
- [ ] **改 ID 回归**：普通模式下改 ID，确认每次改值都立即重设同步字（hook 未破坏原厂 ID 行为）；
- [ ] **其它 C.Fn 项回归**：频道/CH、BEEP、LCD 等改值与原厂一致；
- [ ] 任意一步异常 → 立刻刷回原厂（救砖流程见 [`../../../keypatch/README.md`](../../../keypatch/README.md)）。

### 3.1 异常排查提示

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 密钥模式下偶发首包丢失 / 配对不稳 | 删掉的 `SCAL(0x33)+1ms`（另含原厂 20µs） | 记录现象；回退方案见 [`../README.md`](../README.md) §6.6（保留 strobe/延时的变体） |
| 密钥模式完全不响应 | 引闪器是否也打了同一把密钥 / `settings[8]` 是否真为 2 且已保存 | 先确认引闪器侧与开关值 |
| LIGHT 值一开机又变回 0 | 无线设置同步覆盖 `settings[8]`（另有一处整体写路径未屏蔽） | 记录现象，评估进一步保护该写点（待办） |
| 造型灯不亮 / 行为异常 | 造型灯读者屏蔽（`0x080036AE` / `0x080036D6`）副作用 | 对照原厂刷回确认，必要时回退这 2 字节 |
| 普通模式异常 | 补丁点越界或固件版本不符 | 核对 sha256 / 各补丁点原始字节，重新生成 |
| 刷坏后 G3 找不到设备 | — | 先正常开机 → 按一下侧拨轮 → 插 USB（救砖见 `keypatch/README.md`） |
