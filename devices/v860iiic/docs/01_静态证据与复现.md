# V860III-C 静态证据与复现（补丁点定位过程）

本文记录 **Godox V860III-C V1.3**（`V860IIIC_V1.3.bin`，87,612 B，
sha256 `8530a7e85ce1098d64d72d7ea4a28f3fdfb489e3d39da49be1ffa166f6ba270d`）
的补丁点定位过程、可复现脚本与证据表，供复核/换版本时重新定位。

结论汇总见 [`../README.md`](../README.md)；补丁实现见
[`../../../keypatch/devices/v860iiic.py`](../../../keypatch/devices/v860iiic.py)。

> 前置：仓库根便携 Python（capstone / unicorn）`tools\python\python.exe`；
> 原厂固件放在 `devices/v860iiic/firmware/V860IIIC_V1.3.bin`。
> 全部地址都是**虚拟地址**，文件偏移 = 地址 − `0x08003000`。

---

## 1. 定位方法（从常量 50024 = 0x0000C368 入手）

1. 在镜像里搜 4 字节小端字面量 `68 c3 00 00`（= 50024）；
2. 找到引用它的 `ldr rX, [pc, #imm]`，回溯到函数入口；
3. 反汇编该函数：应能看到
   `adds r1, r0, #1`（除数 = ID+1）→ `bl __aeabi_uidiv` → 两次 `WriteReg(4/5, …)` →
   `delay(0x14)` → `strobe(0x33)`（SCAL）→ `delay(1000)`；
4. 确认「全镜像只出现一次 `0xC368` 字面量」且「只有该函数在运行期写寄存器 4/5」。

V860III-C 的结果：

| 项 | 值 |
|---|---|
| `0xC368` 字面量位置 | `0x0801231C`（文件偏移 `0x0F31C`，即函数区 `+0x34`） |
| 字面量数量 | 全镜像 **1 处**（`apply()` 里 `data.count(50024) != 1` 直接拒绝） |
| 同步字函数入口 | **`0x080122E8`** |
| 下一函数起点 | **`0x08012320`** |
| 函数体长度 | **56 字节**（`0x080122E8..0x0801231F`） |
| 原厂 56 字节 | `0c 4a 10 b5 41 1c 10 46 f0 f7 fe fe 04 46 01 0a 04 20 03 f0 78 fa e1 b2 05 20 03 f0 74 fa 14 20 03 f0 2a f9 33 20 03 f0 cf fa 7d 20 c0 00 03 f0 23 f9 10 bd 68 c3 00 00` |

原厂反汇编（56 B，含尾部字面量池）：

```asm
0x080122E8  0c 4a        ldr   r2, [pc, #0x30]   ; r2 = 0x0801231C 处字面量 = 0x0000C368 = 50024
0x080122EA  10 b5        push  {r4, lr}
0x080122EC  41 1c        adds  r1, r0, #1          ; r1 = ID + 1
0x080122EE  10 46        mov   r0, r2             ; r0 = 50024
0x080122F0  f0 f7 fe fe  bl    #0x080030F0         ; __aeabi_uidiv(50024, ID+1)
0x080122F4  04 46        mov   r4, r0             ; r4 = 16 位同步字
0x080122F6  01 0a        lsrs  r1, r0, #8          ; SYNC1 = sync >> 8
0x080122F8  04 20        movs  r0, #4
0x080122FA  03 f0 78 fa  bl    #0x080157EE         ; CC2500_WriteReg(4, SYNC1)
0x080122FE  e1 b2        uxtb  r1, r4             ; SYNC0 = sync & 0xFF
0x08012300  05 20        movs  r0, #5
0x08012302  03 f0 74 fa  bl    #0x080157EE         ; CC2500_WriteReg(5, SYNC0)
0x08012306  14 20        movs  r0, #0x14           ; 20
0x08012308  03 f0 2a f9  bl    #0x08015560         ; delay_us(20)
0x0801230C  33 20        movs  r0, #0x33           ; SCAL
0x0801230E  03 f0 cf fa  bl    #0x080158B0         ; strobe(0x33)
0x08012312  7d 20        movs  r0, #0x7d
0x08012314  c0 00        lsls  r0, r0, #3          ; r0 = 0x3E8 = 1000
0x08012316  03 f0 23 f9  bl    #0x08015560         ; delay_us(1000)
0x0801231A  10 bd        pop   {r4, pc}
0x0801231C  68 c3 00 00                                ; 字面量 50024（0x0000C368）
0x08012320  ...                    ; 下一函数（不是补丁区）
```

> 补丁区**必须止步于 `0x08012320`**：模块里有 `assert SYNC_FN_SIZE == 56` 与
> `SYNC_FN + 56 == SYNC_FN_END` 的运行时检查，`verify()` 也会断言不越界。

## 2. 复现命令（仓库根，PowerShell）

```powershell
# ① C.Fn / settings 子系统分析：7 项断言，退出码 0
tools\python\python.exe devices\v860iiic\re\cfn.py

# ② 关键代码段对照反汇编（造型灯读者 / C.Fn 渲染 / CC2500 初始化表 / WriteReg 调用点）
tools\python\python.exe devices\v860iiic\re\compare.py

# ③ 任意区间反汇编（示例：同步字函数 + 调用点）
tools\python\python.exe devices\v860iiic\re\disasm_range.py devices\v860iiic\firmware\V860IIIC_V1.3.bin 0x08003000 0x080122E8 0x40

# ④ 辅助函数/调用点探针
tools\python\python.exe devices\v860iiic\re\probe_helpers.py

# ⑤ 模块级补丁 + 离线验证（35 项，输出到 %TEMP% 避免覆盖成品）
tools\python\python.exe keypatch\keypatch.py patch --device v860iiic --key 0x6B21 --verify --out %TEMP%\kp_v860iiic

# ⑥ Lead 的独立调用级交叉验证（原厂 / 开关 ON / 开关 OFF 三路对比）
tools\python\python.exe keypatch\dev\lead\call_harness.py
```

`cfn.py` 与 `compare.py` 的真实输出已归档为
[`re/log_cfn.txt`](../re/log_cfn.txt) 与 [`re/log_compare.txt`](../re/log_compare.txt)
（均为 UTF-8；`log_compare.txt` 的部分中文标题是原始脚本控制台输出的编码瑕疵，
**地址/字节/指令不受影响**；`log_cfn.txt` 正常）。

> 说明：`re/fwlib.py` 是从 `devices/v1c/re/audit_static.py` 裁剪出的**通用分析库**
> （镜像/地址常量 + `Code` 反汇编与数据流辅助），V1C 专用的补丁点复核主体已删除，
> 不会对 V860III-C 产生任何“结论”。本设备的证据以 `re/cfn.py`、`re/compare.py`
> 与模块 `verify()` 为准。

## 3. 关键证据表

### 3.1 镜像身份 / 向量表 / 辅助函数

来源：`re/cfn.py` 第 1 节（`re/log_cfn.txt` 第 8–24 行）。

| 项 | 值 |
|---|---|
| 镜像长度 / sha256 | 87,612 B / `8530a7e85ce1098d64d72d7ea4a28f3fdfb489e3d39da49be1ffa166f6ba270d` |
| 镜像基址 | `0x08003000` |
| 向量表[0] 初始 SP | **`0x20001558`** |
| 向量表[1] Reset | **`0x080030D5`** → 处理函数 `0x080030D4` |
| `__aeabi_uidiv` | `0x080030F0` |
| `CC2500_WriteReg` | `0x080157EE` |
| `CC2500_ReadReg` | `0x0801574E` |
| `strobe`（WriteCmd） | `0x080158B0` |
| `delay_us` | `0x08015560` |
| CC2500 初始化表函数 | `0x08015590` |
| RF 初始化函数 | `0x080066FC` |
| C.Fn 递减处理函数 | `0x0800627C` |
| C.Fn 递增处理函数 | `0x0800D4A8` |
| save（设置持久化） | `0x08005FA0` |
| load（上电恢复设置） | `0x080159D0` |
| item9（LCD）专用处理 | `0x08015018` |

> 镜像初始 SP 是 `0x20001558`；模块 Unicorn harness 自己把栈顶设为 `0x20001400`
> （`UC_STACK`，8 字节对齐）并映射 `0x20000000` 起 16 KB RAM，两者不要混淆。

### 3.2 同步字函数的 5 个调用点（入参都是 `settings[+6]` = 当前 ID）

`re/log_cfn.txt` 第 24 行：`BL -> SYNC_FN 调用点: 0x08006324 / 0x08006762 / 0x0800D554 / 0x0800E1A8 / 0x0800E23C`。
每处调用前都有 `ldrb r0, [rX, #6]` 取设置区 +6 字节（ID）：

| 调用点 | 所在函数 | 调用前取 ID 的指令 | 场景 |
|---|---|---|---|
| `0x08006324` | C.Fn 递减处理 `0x0800627C` | `0x08006322 ldrb r0,[r0,#6]` | 改 C.Fn 值后重设同步字 |
| `0x08006762` | RF 初始化 `0x080066FC` | `0x08006760 ldrb r0,[r0,#6]` | 初始化按当前 ID 覆盖同步字 |
| `0x0800D554` | C.Fn 递增处理 `0x0800D4A8` | `0x0800D552 ldrb r0,[r0,#6]` | 改 C.Fn 值后重设同步字 |
| `0x0800E1A8` | 设置流程 `0x0800DDB4` | `0x0800E1A6 ldrb r0,[r4,#6]` | 设置/恢复路径 |
| `0x0800E23C` | 同上 | `0x0800E23A ldrb r0,[r4,#6]` | 同上（r4 未改写） |

> 结论：全镜像只有这一个函数在运行期写 SYNC1/SYNC0，5 个入口共享它；
> 因此整函数改写（而不是逐个调用点打补丁）是正确且最省的选择。

### 3.3 写 CC2500 寄存器 4/5 的全部位置

`re/compare.py` 全镜像扫描 `WriteReg=0x080157EE` 调用点，`r0` 立即数为 4/5 的只有：

| 调用点 | 寄存器 | 写入值 | 场景 |
|---|---|---|---|
| `0x080155BE` | 4 | `0xC3` | CC2500 初始化表（缺省值，随后被覆盖） |
| `0x080155C6` | 5 | `0x68` | 同上 |
| `0x080122FA` | 4 | `sync >> 8` | 同步字函数（**唯一运行期写入**） |
| `0x08012302` | 5 | `sync & 0xFF` | 同上 |

其它 `WriteReg` 调用写的是配置寄存器 `0x00–0x2E`（初始化表）、`0x06`、`0x18`、
`0x0D/0x0E/0x0F`（频率）、`0x3E`（PATABLE）等，**都不写同步字**。
`0xC3/0x68` 正是 `0xC368 = 50024` 的高/低字节，也就是 ID=0 时的原厂同步字。

### 3.4 初始化覆盖顺序

```text
RF_Init(0x080066FC)
 ├─ bl 0x08015590          ; CC2500 初始化表：写 reg0x00–0x2E（含 reg4=0xC3、reg5=0x68）+ PATABLE + SCAL/SIDLE
 ├─ ...
 └─ bl 0x080122E8（0x08006762）  ; 按当前 settings[6](ID) 与 C.Fn LIGHT 开关写 reg4/reg5（覆盖缺省值）
```

所以只改 `0x080122E8` 就能覆盖全部「设置同步字」路径，不需要 hook 初始化路径。

### 3.5 C.Fn 设置区与 LIGHT 开关项

来源：`re/cfn.py` 第 2/3/4 节（`re/log_cfn.txt` 第 26–685 行）与
[`CFN.md`](../../../keypatch/dev/v860iiic/CFN.md)。

| 项 | 值 |
|---|---|
| settings 基址 | **`0x2000108A`**（item n = `settings[n]`；字面量 `0x2000108A` 全镜像 51 处引用） |
| ID = item 6 | `settings[6]` = **`0x20001090`**（R=8 W=3） |
| **LIGHT = item 8** | **`settings[8]` = `0x20001092`**（R=6 W=4） |
| 最大值/回绕表 | **`0x080181AA`**，12 字节 `01 01 01 01 01 1f 63 01 02 06 01 01` |
| 每项 max | `1,1,1,1,1,31,99,1,2,6,1,1`（item0..item11） |
| 表引用点 | `0x08006304`（递减）、`0x0800D508`（递增）、`0x0801029E`（设置应用） |
| LIGHT 功能读者 | **`0x080036AE`**（`00 7a`）、**`0x080036D6`**（`01 7a`），均在造型灯任务 `0x080036A8..0x0800379F` |
| 无线设置同步解包写点 | **`0x0800A7EA`**（`08 72`，`strb r2,[r1,#8]`；解包函数 `0x0800A7CC..0x0800A7F7`） |
| 出厂默认 | `0x08006780..0x0800687B` 内 `0x080067DC` 写 `settings[8]` = **0**（12sec） |
| 持久化 | save `0x08005FA0`（settings[8] 读者 `0x080060DE`，写记录 `+0x34`）→ load `0x080159D0`（`0x08015B10` 写回 settings[8]） |

C.Fn 菜单证据（`re/log_compare.txt`）：

- 渲染函数 `0x080048B0..0x0800538F`；item 索引来自 `0x200004F2`；
- `0x08004E46 cmp r0,#6` → item6 = ID（`0x08004E50` 起 ID==0 单独分支，即 ID 菜单 OFF）；
- `0x08004F92 cmp r0,#8` → **item8 = LIGHT 渲染块**；
- 该块右栏按 `settings[8]` 选字形：`0x08005012 ldrb r0,[r7,#8]` → `lsls r0,#1` → `adds r0,#4` →
  `uxtb` → 绘制（`bl 0x08007340`）。即字形索引 = `2*值 + 4`，**三档值 0/1/2 → 字形 4/6/8**；
- `0x08005022` 再读一次 `settings[8]` 交给显示辅助 `0x080053DC`（编辑态/箭头）。

> 这组「三档值 + 三档字形」与 V1C 的 LIGHT 渲染块同构（V1C 的 UI 报告由真实渲染确认右栏为
> `12sec / OFF / ON`，值 `0/1/2`）。**V860III-C 本轮没有单独做 UI 报告**，项名沿用同表结构 +
> item6/8/9 的直接地址证据；菜单文本的最终确认见 [`../docs/02_验证与实机清单.md`](../docs/02_验证与实机清单.md)。

### 3.6 改值即时生效的 gate（原厂字节）

`re/log_cfn.txt` 第 723–729 行：

| 位置 | 原厂 4 B | 语义 |
|---|---|---|
| `0x0800630C`（递减处理 `0x0800627C` 内） | `06 29 08 d0` | `cmp r1,#6; beq <sync>` —— 只有改 ID 才重设同步字 |
| `0x0800D53E`（递增处理 `0x0800D4A8` 内） | `06 29 07 d0` | 同上 |

两处 gate 前的数据流都解析出 `r0 = 0x2000108A`（settings 基址，值 `536875146`），
所以注入代码可以直接按 `[r0,#6]` 取 ID，再用 `settings[8]` 判断密钥开关。

### 3.7 代码洞（注入区）

`re/log_cfn.txt` 第 685–721 行：

| 地址 | 连续 0 长度 | 引用检查 | 结论 |
|---|---|---|---|
| **`0x080179C2`** | **234 B（到 `0x08017AAB`）** | 无 BL/分支/LDR 字面量/全镜像绝对地址（含 thumb 置 1 变体） | **可用**（本补丁用前 10 B） |
| `0x08017C3A` | 222 B（到 `0x08017D17`） | 同上（在「无引用」列表内） | 可用（备用） |
| `0x080175BE`（57 B）/ `0x0801702A`（36 B）/ `0x08017062`（29 B） | — | 有字面量/分支引用 | **不可用** |

补丁后原地反汇编（key = `0x6B21`）：

```text
0x080179C2  1f b5        push {r0, r1, r2, r3, r4, lr}
0x080179C4  80 79        ldrb r0, [r0, #6]          ; 入口 r0 = settings 基址 → r0 = ID
0x080179C6  fa f7 8f fc  bl   0x080122E8            ; 同步字函数（内部读 settings[8] 开关）
0x080179CA  1f bd        pop  {r0, r1, r2, r3, r4, pc}
```
