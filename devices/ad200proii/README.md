## 1. 它做了什么

AD200 Pro II 和神牛其它 2.4 GHz 设备一样，用 `sync = 50024 / (ID + 1)` 把「引闪 ID」
换算成 CC2500 的 16 位硬件同步字（ID = 0..99，全球只有这 100 个值）。

本补丁不改这个公式，而是在它前面插一个判断：

```text
设置字节 +0x13 <  2  ->  sync = 50024 / (ID + 1)   （和原厂一模一样）
设置字节 +0x13 >= 2  ->  sync = 你的 16 位 KEY      （例如 0xD4EC）
```

灯和引闪器**两边都刷同一把 KEY、都切到私钥档**，才能互相引闪；别人拿原厂引闪器来，
发的还是那 100 个公开值，硬件层对不上，灯不会闪。

> ⚠️ 这是「对不上同步字」层面的隔离，**不是密码学认证**。知道 KEY 或专门扫描的人
> 仍可以干扰/触发。
>
> ⚠️ 切到私钥档后，原厂引闪器**完全触发不了**这台灯。拍照时切回普通档即可。

### 为什么用设置字节，而不是菜单项

AD200 Pro II 的菜单里**没有 C.Fn 项**（已用字符串表 + ADR 交叉比对确认），
所以无法照搬 AD200 Pro 用「C.Fn 第 8 项 F8」当开关的做法。本版改用设置结构体
`0x200009B4 + 0x13` 这个字节，它：

- 不属于任何菜单项，不占菜单位置；
- 会被参数读取流程从 Flash 参数区载入，切换后能持久保存；
- 只在开机初始化时被读一次，所以**运行中改它不会立即生效**。

## 2. 补丁点

函数入口 `0x0800D224` 的 `push {r4,lr}` 不动；从 `0x0800D230` 起是原厂的
`lsrs r1,r4,#8` → 写 reg4/reg5 → `delay(20)` → `SCAL(0x33)` → `delay(1000)`，
**这 40 字节完全没改**。

| 地址 | 长度 | 内容 |
|---|---|---|
| `0x0800D226` | 10 B | `B.W 0x0805BF1A` + `movs r0,r0` + `nop`×2（替换原厂 `movw r1,#0xC368`） |
| `0x0805BF1A` | 34 B | 判定代码洞：读 `+0x13`，`>= 2` 用 KEY，否则算原厂公式，再跳回 `0x0800D230` |

代码洞反汇编：

```asm
0805BF1A  07 4B          ldr  r3,[pc,#0x1c]      ; -> 0x0805BF38
0805BF1C  DB 7C          ldrb r3,[r3,#0x13]      ; 设置结构体 +0x13
0805BF1E  02 2B          cmp  r3,#2
0805BF20  03 D3          blo  0x0805BF2A         ; 小于 2 → 原厂公式
0805BF22  4D F2 EC 44    movw r4,#0xD4EC         ; ← 只有这 4 字节随密钥变
0805BF26  B1 F7 83 B9    b.w  0x0800D230
0805BF2A  4C F2 68 31    movw r1,#0xC368
0805BF2E  40 1C          adds r0,r0,#1
0805BF30  B1 FB F0 F4    udiv r4,r1,r0
0805BF34  B1 F7 7C B9    b.w  0x0800D230
0805BF38  B4 09 00 20    .word 0x200009B4
```

代码洞位于 `0x0805BF1A`，该区域原本是 942 字节连续 `0xFF` 的空白区，无任何字面量指向它。

## 3. 用法

```bash
# 1) 生成（只需要标准库）
python tools/build_mask.py --key 0xD4EC --image /path/to/AD200ProII_V1.05.bin

# 2) 加离线验证（需要 capstone + unicorn）
python tools/build_mask.py --key 0xD4EC --image /path/to/AD200ProII_V1.05.bin --verify

# 产物
out/AD200ProII_V1.05_keyD4EC_mask.bin
```

用官方 G3 升级软件（Godox V2.0）刷入：「本地文件」→ 选 bin → 等日志
`打开文件成功` → 「升级」。

仓库内集成后也可以走统一入口：

```bash
python keypatch/keypatch.py patch --device ad200proii_mask --key 0xD4EC --verify
```

要换 KEY：改 `--key` 重新生成，**灯和引闪器一起重刷**。

## 4. 怎么切档

进设备菜单，把**蒙版**项设成目标值，然后**关机再开机**：

| 蒙版 | 行为 |
|---|---|
| 2 | 普通模式（原厂同步字，同 ID 的原厂灯都会闪） |
| 4 | 加密模式（私有 KEY，只有同 KEY 的灯会闪） |

> 代码里的判断是「读到的字节 `>= 2` 走密钥」。菜单显示 2/4、实测 2 对应普通，
> 说明菜单显示值与存储值之间存在偏移（显示 2 时存的是 0 或 1）。这一点是实机观察，
> 不是从代码推出来的，欢迎复核。

看不到档位提示是正常的：本方案**不新增任何 UI**。判断方法——试闪一次看谁亮：
只有刷过同 KEY 的灯亮 = 加密档；同 ID 的原厂灯也亮 = 普通档。

---

## 5. 回滚

- 软回滚：菜单把蒙版改回 2，重启；
- 硬回滚：用官方 G3 刷回原厂 `AD200ProII_V1.05.bin`。

补丁不碰 bootloader（`0x08000000`–`0x08004800` 之外才是 App），只要 G3 还能识别设备就能救回。

## 6. 离线验证

`verify()` 会先用 Unicorn 直接执行**打完补丁的真机器码**（桩掉写寄存器/delay/strobe
三个 helper），再配合静态检查，共 9 项：

| 检查 | 结果 |
|---|---|
| 输出长度 | 387,248 B，与原厂一致 |
| `0x0800D226` | 10 B 跳转正确 |
| `0x0805BF1A` | 34 B 注入正确 |
| 函数体 `0x0800D230` 起 40 B | 与原厂一致 |
| 字面量 | 指向 `0x200009B4` |
| 差异范围 | 44 B，全部落在补丁区 |
| 设置字节=0、ID=5 | → `0x2091`（`50024/6`） |
| 设置字节=2、ID=5 | → KEY |
| 设置字节=2、ID=99 | → KEY（与 ID 无关） |

用 `0xD4EC` 生成的结果与实机验证过的文件**逐字节相同**：

```
sha256 8818198aac4c2d5378df231876dd14b8ae13bfc7b988dc39883bba56b2dfefda
```

## 7. 风险

- **切档必须重启**：那个字节只在开机初始化时被读一次，运行中改不重算同步字；
- **不新增 UI**：没有菜单项、没有屏幕提示，档位只能靠“哪些灯会被引闪”判断；
- **`+0x13` 语义未完全公开**：只知道它由参数读取流程载入、初值为 0；与菜单显示值的
  对应关系属实测推断；
- **未由上游项目实机验证**：实机结论来自第三方在自有 AD200 Pro II（V1.05）上的测试；
- 同步字不是密码学认证：SDR 抓包可分析，只能挡住「正常原厂设备误触发」。

## 8. 集成到仓库

### 方式 A：独立模块（最简单）

把 `ad200proii_mask.py` 放进 `keypatch/devices/`，在 `DEVICE_IDS` 里追加
`"ad200proii_mask"`。它与同设备的 `ad200proii.py`（ID=99 版）**补丁点不同，互不干扰**，
两份可以共存、各自生成。

### 方式 B：并进 `ad200proii.py` 作为变体

1. 把 `build_head()` / `build_cave()` / `_t_movw()` 搬进 `ad200proii.py`；
2. `DEVICE["variants"]` 增加：

```python
{"id": "mask", "name": "设置字节版",
 "desc": "蒙版=2 普通 / 4 加密；切换后需重启生效"}
```

3. `apply(data, key, mode="mask")` 走本补丁；`verify()` 里按 `build_cave(key)` 的字节
   判定分派到 `verify_mask()`；
4. **不要**把 `default_variant` 设成本版——它依赖一个语义未公开的字节，不适合当默认。

`studio/server.py` 已支持 `variants` 透传，前端在 `dev.variants.length > 1` 时自动
渲染下拉框，按方式 B 集成后网页端无需改代码。
