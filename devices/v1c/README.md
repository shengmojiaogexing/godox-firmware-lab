## 0. 一句话结论

V1C 的「ID → 同步字」函数是 **`0x080121BC`**（56 字节，到下一函数 `0x080121F4` 为止），
它是**全镜像唯一**在运行期写 CC2500 `SYNC1/SYNC0`（寄存器 4/5）的地方（另有一处是初始化表，会被它覆盖）。

**密钥开关用 C.Fn 菜单**：复用 **C.Fn 第 3 页（page2）第 1 行 `LIGHT`（原厂造型灯模式，
`settings[8]` = RAM `0x2000108E`，三档：`0=12sec`、`1=OFF`、`2=ON`）** ——

- **`LIGHT = ON`（值 2）** → 同步字 = 私有 KEY（密钥模式）；
- **`LIGHT = 12sec`（值 0，出厂默认）或 `OFF`（值 1）** → 同步字 = `50024/(ID+1)`
  （原厂普通模式，ID 菜单恢复原厂含义）。

补丁共 **7 处**：①同步字函数 56 B 整函数改写；②`0x08017944` 全 0 死区注入 10 B 改值即时生效 hook；
③④两个 C.Fn 改值 gate（`0x0800625C`/`0x0800D46E`）改 `BL` 注入；⑤⑥造型灯任务的两个 `settings[8]`
读者屏蔽（`0x080036DA`/`0x08003702`，造型灯输出固定原厂 12sec 档）；
⑦无线设置同步解包不再覆盖 `settings[8]`（`0x0800A6FA`）。

## 2. 核心补丁点：同步字函数 `0x080121BC`

### 2.1 原厂反汇编（56 字节）

`0x080121BC` 起、到下一函数 `0x080121F4` 为止，共 **56 字节**：
其中代码 `0x080121BC..0x080121EF`（52 B）+ 字面量 `0x080121F0..0x080121F3`（4 B，`0x0000C368`）。

```asm
0x080121BC  0c 4a        ldr   r2, [pc, #0x30]   ; r2 = 字面量 @0x080121F0 = 0x0000C368 = 50024
0x080121BE  10 b5        push  {r4, lr}
0x080121C0  41 1c        adds  r1, r0, #1          ; r1 = ID + 1
0x080121C2  10 46        mov   r0, r2             ; r0 = 50024
0x080121C4  f0 f7 94 ff  bl    0x080030F0         ; __aeabi_uidiv(50024, ID+1)
0x080121C8  04 46        mov   r4, r0             ; r4 = 16 位同步字
0x080121CA  01 0a        lsrs  r1, r0, #8          ; SYNC1 = sync >> 8
0x080121CC  04 20        movs  r0, #4
0x080121CE  03 f0 7e fa  bl    0x080156CE         ; CC2500_WriteReg(4, SYNC1)
0x080121D2  e1 b2        uxtb  r1, r4             ; SYNC0 = sync & 0xFF
0x080121D4  05 20        movs  r0, #5
0x080121D6  03 f0 7a fa  bl    0x080156CE         ; CC2500_WriteReg(5, SYNC0)
0x080121DA  14 20        movs  r0, #0x14           ; 20
0x080121DC  03 f0 30 f9  bl    0x08015440         ; delay_us(20)   ← 建立时间
0x080121E0  33 20        movs  r0, #0x33           ; SCAL
0x080121E2  03 f0 d5 fa  bl    0x08015790         ; strobe(SCAL)
0x080121E6  7d 20        movs  r0, #0x7d
0x080121E8  c0 00        lsls  r0, r0, #3          ; r0 = 0x3E8 = 1000
0x080121EA  03 f0 29 f9  bl    0x08015440         ; delay_us(1000)
0x080121EE  10 bd        pop   {r4, pc}
0x080121F0  68 c3 00 00                                ; 字面量 50024（0x0000C368）
0x080121F4  ...                    ; 下一函数（不是补丁区）
```

原厂 56 字节（`apply()` 逐字节校验用的基准）：

```text
0c 4a 10 b5 41 1c 10 46 f0 f7 94 ff 04 46 01 0a
04 20 03 f0 7e fa e1 b2 05 20 03 f0 7a fa 14 20
03 f0 30 f9 33 20 03 f0 d5 fa 7d 20 c0 00 03 f0
29 f9 10 bd 68 c3 00 00
```

### 2.2 函数边界与邻居

- 函数**前面**（`0x0801217C`）是**频率/信道设置**函数：从 settings 取通道号，写 CC2500 寄存器
  `0x0D/0x0E/0x0F`（FREQ2/FREQ1/FREQ0），尾部同样是 `delay(20) + SCAL(0x33) + delay(1000)`。
  它**不写** SYNC1/SYNC0，所以与本次补丁无关（但它说明「改频率就要 SCAL」的惯例）。
- 函数**后面**（`0x080121F4`）是一个计数器/超时递减函数，与本补丁无关。
- 补丁区**必须止步于 `0x080121F4`**：`keypatch/devices/v1c.py` 里有 `assert SYNC_FN_SIZE == 56`
  与「函数体结束地址 == 下一函数起点」的运行时检查。
- 独立审计确认 `0x080121F4` 是真实函数起点（存在 `0x0800DCE2` 的 `BL` 调用），且无其它入口落进
  56 字节函数体（见 [`../../keypatch/dev/v1c/AUDIT.md`](../../keypatch/dev/v1c/AUDIT.md) §3）。

## 3. 5 个调用点（入参都是 `settings[+6]` = 当前 ID）

全镜像对 `0x080121BC` 的 `bl` 调用共 **5 处**。每处在调用前都用 `ldrb r0, [rX, #6]` 取「设置区偏移 +6」
的字节作为 ID；独立审计用「CFG 前驱 + 反向数据流」确认 5 处解析出的设置区基址都是
**`0x20001086`**，即 ID 字节 = **`RAM[0x2000108C]`**（早期 `re/scan4.py` 的
`0x200004F5` 候选是回溯 bug，已由 `re/audit_static.py` 更正，见 §7.5）：

| 调用点 | 所在函数 | 取参指令 | settings 基址来源 |
|---|---|---|---|
| `0x08006274` | `0x080061CC..0x0800664B` | `0x08006272 ldrb r0,[r0,#6]` | `0x0800620E ldr r0,=0x20001086` |
| `0x080066B2` | RF 初始化 `0x0800664C` | `0x080066B0 ldrb r0,[r0,#6]` | `0x080066AE ldr r0,=0x20001086` |
| `0x0800D484` | `0x0800D3D8..0x0800D8B7` | `0x0800D482 ldrb r0,[r0,#6]` | `0x0800D41A ldr r0,=0x20001086` |
| `0x0800E0C2` | `0x0800DCDC..0x0800E19B` | `0x0800E0C0 ldrb r0,[r4,#6]` | `0x0800E06C ldr r4,=0x20001086` |
| `0x0800E138` | 同上 | `0x0800E136 ldrb r0,[r4,#6]` | 同上（r4 未被改写） |

即 5 个调用点执行前 `r0 = RAM[0x2000108C]`（当前 ID）。补丁函数只接收 `r0`，
**不需要硬编码这个 RAM 地址**；LIGHT 开关标志地址 `0x2000108E` 作为字面量写在函数体内（见 §6.1）。

补充静态线索：

- 原厂两个「C.Fn 改值」处理函数（`0x080061CC` / `0x0800D3D8`）里只有 `cmp r1,#6`
  （ID 项）命中才重设同步字（`0x0800625C/5E`、`0x0800D46E/70`）；**本补丁已把这两处 gate
  改成 `BL` 注入 hook**，让 C.Fn 改值（含 LIGHT 开关）都立即重设同步字（见 §5.5、§6.3）。
- ID 菜单保持原厂语义：显示代码 `0x08004EA2` 命中项 6 后读 `settings[6]`；ID≠0 走 `/10` 数值显示，
  ID==0 走单独分支 `0x08004F2C`（即 ID=OFF）。**密钥开关在 C.Fn 的 LIGHT 项，不再复用 ID=OFF。**
- 设置持久化 `0x08006026` 会把 `settings[6]` 存进 flash 记录，说明 ID 随原厂设置保存；
  `settings[8]`（LIGHT）同样由原厂 save/load 持久化（见 §5.6）。

> 结论：5 个入口共享同一个「同步字函数」，**不存在**第二个绕开它的同步字设置点；
> 因此整函数改写（而不是逐个调用点打补丁）是正确且最省的选择。

## 4. CC2500 写点与初始化覆盖关系

### 4.1 辅助函数

| 符号 | 地址 | 说明 |
|---|---|---|
| `__aeabi_uidiv` | `0x080030F0` | 无符号整数除法；`r0/r1` 入、`r0` 商 |
| `CC2500_WriteReg` | `0x080156CE` | 写寄存器：`r0`=寄存器地址、`r1`=值（内部走 `0x080157A8` 的 SPI 突发写） |
| `CC2500_ReadReg` | `0x0801562E` | 读寄存器（RF 初始化自检用，审计确认） |
| `strobe` | `0x08015790` | 发命令选通（`r0`=命令字节，如 `0x33`=SCAL、`0x36`=SIDLE、`0x34`=SRX） |
| `delay_us` | `0x08015440` | 忙等延时（`r0`=计数值；原厂同步字函数里 `20` 与 `1000` 都走它） |
| CC2500 初始化表 | `0x08015470` | 一次写入寄存器 `0x00–0x2E` + PATABLE + SCAL/SIDLE 序列 |

### 4.2 初始化表写的 SYNC1/SYNC0 会被覆盖

初始化表函数 `0x08015470` 在 `0x0801549E/0x080154A6` 写入：

```asm
0x0801549A  c3 21   movs r1, #0xC3
0x0801549C  04 20   movs r0, #4        ; SYNC1 = 0xC3
0x0801549E  bl 0x080156CE
0x080154A2  68 21   movs r1, #0x68
0x080154A4  05 20   movs r0, #5        ; SYNC0 = 0x68
0x080154A6  bl 0x080156CE
```

`0xC3/0x68` 正是 `0xC368 = 50024` 的高/低字节，也就是**原厂 ID=0 时的同步字**。
这组值只是「初始缺省」，**随后** RF 初始化流程会调用同步字函数按当前 ID 覆盖它：

```text
RF_Init(0x0800664C)
 ├─ bl 0x08015470            ; ① 初始化表：写 reg0x00–0x2E（含 reg4=0xC3、reg5=0x68）+ PATABLE + SCAL/SIDLE
 ├─ 反复读 reg0x0D 自检（期望 0x5C，最多 10 次）+ delay(10000)
 ├─ strobe(0x36)             ; ② 命令选通（SIDLE）
 ├─ WriteReg(0x3E, ...)      ; ③ PATABLE（功率表）
 ├─ strobe(0x33) + delay(1000)  ; ④ SCAL
 ├─ bl 0x080121BC（0x080066B2） ; ⑤ 按当前 ID（及 LIGHT 开关）写 SYNC1/0（覆盖 ① 的缺省值）
 └─ bl 0x0800FD04
```

### 4.3 全镜像扫描：只有两处写 SYNC1/SYNC0

对全镜像所有 `CC2500_WriteReg` 调用点做「`r0` 立即数」扫描（独立审计共 59 个调用点），写寄存器 **4/5** 的只有：

| 调用点 | 寄存器 | 场景 |
|---|---|---|
| `0x0801549E` / `0x080154A6` | 4 / 5 | CC2500 初始化表（缺省值 `0xC3/0x68`，随后被覆盖） |
| `0x080121CE` / `0x080121D6` | 4 / 5 | 同步字函数 `0x080121BC`（**唯一运行期写入**） |

其它 `WriteReg` 调用写的是：`0x00–0x2E`（初始化表）、`0x06`、`0x18`、`0x0D/0x0E/0x0F`（频率）、`0x3E`（PATABLE）——
**都不碰同步字**。

> 结论：运行期唯一的同步字写入口就是 `0x080121BC`；初始化表的缺省值会被它覆盖。
> 所以**只改这一个函数**即可覆盖所有「设置同步字」路径，不需要 hook 初始化路径。

## 5. 用户开关语义：C.Fn 第 3 页 `LIGHT` = 密钥开关

### 5.1 为什么用 C.Fn，为什么选 `LIGHT`

用户要求「改用 C.Fn」——用设备自带菜单项当密钥开关，不改 UI。V1C 的 C.Fn 是
**3 页 × 4 行共 12 项、不显示 F 编号**（见 §5.2/§5.7），可复用的候选有 LIGHT / BEEP / FEB ACL 等。

**为什么最终选 `LIGHT`（item 8）**：

| 理由 | 说明 |
|---|---|
| **语义直观** | LIGHT 有三档：`12sec`(0) / `OFF`(1) / `ON`(2)。**把 `ON`（值 2）当密钥模式 = 用户看到 ON 即开密钥**，不需要反相理解 |
| 出厂默认即普通模式 | 出厂默认 `settings[8]=0`（12sec）→ 新刷/恢复出厂 = **普通模式**，符合预期 |
| 功能读者集中、可屏蔽 | 造型灯任务 `0x080036D4` 只有 2 个读者（`0x080036DA`/`0x08003702`），2 字节各 mask 成常数 0 即固定回原厂 12sec 档 |
| 非 0/1 值可控 | `flag == 2` 才进密钥模式；0/1 都走原厂公式，避免把「12sec/OFF」误当开关 |
| 不碰 RF/闪光关键路径 | 只涉及造型灯 GPIO（`0x48001000` 位 13/14），不碰射频/闪光输出 |

> 早期中间版曾用 item2 `STBY`，但 STBY 的菜单显示与 settings 值**反相**（`0=ON、1=OFF`），
> 用户「设 ON=密钥」不直观，故最终改为 `LIGHT`。版本演进见 §10。

### 5.2 C.Fn 子系统与 12 项总表

- 设置区基址 **`0x20001086`**：item n = `settings[n]`（`settings` 数组 51 处字面量引用，
  另见 [`keypatch/dev/v1c/CFN_SETTINGS.md`](../../keypatch/dev/v1c/CFN_SETTINGS.md) §2）；
- 最大值/回绕表 **`0x08018362`**，12 字节：`01 01 01 01 01 1F 63 01 02 06 01 01`
  → item0..11 的 max = `1,1,1,1,1,31,99,1,2,6,1,1`；引用点 `0x08006254`（dec）、
  `0x0800D438`（inc）、`0x08010136`（设置应用）；
- 项索引边界 `cmp #0xB` 遍布 C.Fn 处理/显示/持久化路径（`0x08006260`、`0x0800D472`、
  `0x08005232`、`0x08006408` 等）→ **共 12 项（item 0..0xB），3 页 × 4 行**；
- 固件内没有可直接读的 C.Fn 项名字符串（UI 用字模），项名/显示形式由 UI 报告
  [`keypatch/dev/v1c/CFN_MENU.md`](../../keypatch/dev/v1c/CFN_MENU.md) 用真实渲染函数确认。

| item | 显示名 | max | 出厂默认 | 功能读者（地址） | 与密钥开关的关系 / 备注 |
|---|---|---|---|---|---|
| 0 | m/ft | 1 | 0 | 无（纯显示） | 纯显示，与开关无关 |
| 1 | AF | 1 | 1 | `0x0800366C`（AF 灯 GPIO） | 默认 ON，不适合 |
| 2 | STBY | 1 | 0 | `0x080124DC`（待机任务） | 早期中间版用过；显示与值反相，弃用 |
| 3 | RX STBY | 1 | 0 | `0x08012528`（待机阈值） | 备选 |
| 4 | SCAN | 1 | 0 | `0x0801208E` | 扫描流程会写回 `settings[4]=0`，标志会被自清，**不可用** |
| 5 | CH | 31 | 0x14 | `0x08006154` / `0x0800FA96` | 非 0/1 |
| 6 | ID | 99 | 0 | RF 初始化 `0x080066B0`；dec/inc `0x08006272`/`0x0800D482`；设置路径 `0x0800E0C0`/`0x0800E136` | **保留原厂含义**（普通模式的 ID） |
| 7 | BEEP | 1 | 1 | `0x08003AEE` + 16 处 UI/按键/显示读者 | 读者多；默认 ON；**不是稳定色温** |
| **8** | **LIGHT** | **2** | **0** | **`0x080036DA` / `0x08003702`**（造型灯任务 `0x080036D4` 控制 GPIO） | **★ 选为密钥开关**：OUT 三档 0=12sec / 1=OFF / 2=ON；补丁把两个读者固定为 0（12sec） |
| 9 | LCD | 6 | 3 | `0x08014EF8`（LCD 亮度/对比度） | 非 0/1 |
| 10 | FEB ACL | 1 | 0 | `0x08005548`（GPIO/RF/定时，语义未完全定性） | 暂不推荐 |
| 11 | TX | 1 | 1 | `settings[11]` → 镜像 `0x200004F5`，被 RF/UI 多路读取 | 影响射频发送路径，风险高 |

### 5.3 开关语义（现行）

```c
flag = *(uint8_t *)0x2000108E;     // settings[8] = C.Fn LIGHT 值（0=12sec / 1=OFF / 2=ON）
if (flag == 2) sync = KEY;         // 密钥模式（LIGHT = ON）
else           sync = 50024 / (id + 1); // 原厂普通模式（12sec / OFF）
WriteReg(4, sync >> 8);            // SYNC1
WriteReg(5, sync & 0xFF);          // SYNC0
// 只写同步字：无 SCAL、无延时
```

| C.Fn 第 3 页 LIGHT | settings[8] | 同步字 | 模式 | ID 菜单 |
|---|---|---|---|---|
| **ON（值 2）** | `2` | **私有 KEY**（如 `0xD798`） | **密钥模式**：只接受这把钥匙发来的帧 | 原厂含义 |
| **12sec（值 0，出厂默认）** | `0` | `50024 / (ID+1)` | 普通模式：与未打补丁的原厂一致 | 原厂含义 |
| OFF（值 1） | `1` | `50024 / (ID+1)` | 普通模式（同上） | 原厂含义 |

要点：

- **出厂默认 `settings[8]=0`（12sec）** → 新刷 / 恢复出厂后默认是**普通模式**；
- 用户要开密钥：进 **C.Fn → 第 3 页（page2）→ 第 1 行 `LIGHT` → 设为 `ON`**；
  关密钥：改回 `12sec`（或 OFF）；
- V1C **不显示 F1..F12 编号**，菜单里只有名称；用户操作说明用「第 3 页第 1 行 LIGHT」；
- **原厂 LIGHT 功能代价**：原厂 LIGHT 控制造型灯模式（12sec/OFF/ON）；复用后
  **造型灯输出固定为原厂 12sec 档**（补丁把造型灯任务的两个读者固定为 0），
  用户不能再通过 C.Fn 的 LIGHT 改造型灯模式。菜单里 LIGHT 仍显示三档，但只有「ON=密钥开关」生效。
- UI 显示/按键/保存链路的证据见 `CFN_MENU.md`（见 §7.5）。

### 5.4 读者屏蔽与开关保护（为什么密钥开关不会被原厂逻辑改回）

`settings[8]` 在原厂固件里被多处读/写。本补丁只做**最小必要**处理（`verify()` 逐字节断言）：

| 位置 | 原厂字节 | 补丁后 | 作用 |
|---|---|---|---|
| `0x080036DA`（造型灯任务 `0x080036D4`，读者 1） | `00 7a` = `ldrb r0,[r0,#8]` 的前半 | `00 20` = `movs r0,#0` | 造型灯任务看到 LIGHT=0（12sec），**密钥开关不影响造型灯输出** |
| `0x08003702`（造型灯任务，读者 2） | `01 7a` = `ldrb r1,[r0,#8]` 的前半 | `00 21` = `movs r1,#0` | 同上（第二个读者） |
| `0x0800A6FA`（无线设置同步解包 `0x0800A6DC`） | `08 72` = `strb r2,[r1,#8]` | `00 bf` = `nop` | **不再用收到的紧凑结构覆盖 `settings[8]`** → 防止密钥开关被设置同步静默清 0 |

**保留不屏蔽的读者/写者**（有意为之）：

- 菜单渲染（`0x08005076`/`0x08005086` 等）：继续显示 LIGHT 的 `12sec/OFF/ON`，用户能看到/操作开关；
- save `0x0800602E` / load `0x080159F0`：持久化（必须保留）；
- 出厂默认写入 `0x0800672C`（`settings[8]=0`）：恢复出厂 = 普通模式，符合预期。

**残留风险（需实机验证）**：设置应用路径 `0x0800DCDC` 仍会整体写 `settings[1..11]`
（含 `settings[8]`）；若引闪器/上位机的「设置同步」把 LIGHT 覆盖回 0/1，密钥模式会关闭。
本补丁已 NOP 解包写点 `0x0800A6FA`，但 `0x0800DCDC` 路径未屏蔽（盲目屏蔽会破坏原厂设置同步语义），
**必须实机确认**；恢复出厂/默认重置路径会把 `settings[8]` 置 0（语义合理，但也需实机确认）。

### 5.5 改值即时生效：`BL` 注入 hook

原厂只有「改 ID（item==6）」才立即调用同步字函数；换成 LIGHT 后，**改 LIGHT 也必须立即生效**。
本补丁的做法（不破坏原厂 ID 行为）：

1. 在**全 0 死区 `0x08017944`** 写 10 字节注入代码（§6.2）：
   `push {r0-r4,lr}; ldrb r0,[r0,#6]; bl 0x080121BC; pop {r0-r4,pc}`；
2. 把两个 C.Fn 改值处理函数里的 `cmp r1,#6; beq sync` 门（各 4 B）换成 `BL 0x08017944`：
   - `0x0800625C`（C.Fn 递减处理，`06 29 08 d0` → `11 f0 72 fb`）；
   - `0x0800D46E`（C.Fn 递增处理，`06 29 07 d0` → `0a f0 69 fa`）。

效果：**C.Fn 项改值**（LIGHT 密钥开关、ID、其它可编辑项）都会立即重设同步字并返回原处理函数继续；
hook 入口 `r0` = settings 基址（审计用 CFG 前驱确认），返回时原样恢复 `r0..r4`。
`item9`(LCD) 在原厂就绕过该 gate（`cmp r1,#9` 分支转 LCD 专用处理），不经过 hook，也不会误触发。

> 为什么不简单地把 `cmp #6` 改成 `cmp #8`：那会让**改 ID 不再立即写同步字**（要等下次 RF 初始化），
> 是行为回归；加 10 B 注入 hook 是最小且不破坏原厂 ID 行为的方案。

### 5.6 持久化

- save 记录 builder `0x08005EF0`：把 `settings[0..0xD]` 写入 flash 参数记录
  （record +0x2C..+0x3B；slot = `0x0801F000 + slot*100`，头字节 `0x5C` = 有效标记）；
  `settings[8]` 的 save 点在 `0x0800602E`；
- 上电加载 `0x080158B0` 把 record 展开回 `settings[]`（`settings[8]` 的 load 点在 `0x080159F0`）；
  无有效记录时 `0x080066D0` 写出厂默认（`0x0800672C` 把 `settings[8]` 置 0）；
- 改 C.Fn 值后约 **200 tick 自动写 flash**（UI 报告实测链路），所以 **LIGHT 的值随原厂设置持久化**，
  补丁不需要额外做存储；
- `settings[8]` 在 save/load 中的位置见 `CFN_SETTINGS.md` §5.1。

### 5.7 菜单/UI（未改，仅复用）

- 补丁**不新增**任何 UI/字库/菜单项，也不改显示代码；
- UI 报告 [`../../keypatch/dev/v1c/CFN_MENU.md`](../../keypatch/dev/v1c/CFN_MENU.md)（2026-11-08）确认：
  C.Fn 画面由渲染函数 `0x08004914` 绘制，**12 项 = 3 页 × 4 行**（`page=idx>>2`、`slot=idx&3`），
  固件**不显示 F1..F12 编号**，只显示名称；
  **第 3 页 = `LIGHT, LCD, FEB ACL, TX` → LIGHT 在第 3 页第 1 行**；
  12 项全部真实、可选中，**没有隐藏/预留项**；
- LIGHT 右栏三档 `12sec / OFF / ON`，对应值 `0/1/2`（箭头指示当前档）；密钥模式 = 选 `ON`（2）；
- 操作路径（键名按同代神牛 UI 推断，物理丝印需实机确认）：矩阵 **MENU 键（键码 8）**切换 C.Fn 画面；
  `+/-` 移动项；`SET` 进入/退出编辑；编辑态 `+/-` 改值（按最大值表回绕）；
  改值后约 200 tick 自动写 flash（12 个 C.Fn 字节全部持久化，见 §5.6）；
- 因此复用 LIGHT 项**零 UI 改动**即可被用户看到/操作；**ID 菜单保持原厂含义**。

## 6. 补丁布局（7 处原位补丁，文件长度不变 = 88,032 B）

### 6.1 同步字函数 `0x080121BC`（56 B）

布局（相对 `0x080121BC`；44 B 代码 + 3 个字面量）：

| 偏移 | 长度 | 内容 | 说明 |
|---|---|---|---|
| `+0x00` | 2 | `push {r4, lr}` | 保护现场 |
| `+0x02` | 2 | `ldr r3, =FLAG` | 字面量在 `+0x30`（`0x2000108E`） |
| `+0x04` | 2 | `ldr r2, =50024` | 字面量在 `+0x34`（原厂地址、原值不变） |
| `+0x06` | 2 | `ldrb r3, [r3]` | r3 = LIGHT 开关值（0/1/2） |
| `+0x08` | 2 | `adds r1, r0, #1` | 普通模式除数 = ID+1 |
| `+0x0A` | 2 | `cmp r3, #2` | LIGHT == ON(2)？ |
| `+0x0C` | 2 | `bne go` | 否（12sec/OFF）→ 原厂公式（跳到 `+0x12`） |
| `+0x0E` | 2 | `ldr r2, =KEY` | 密钥模式：字面量在 `+0x2C` |
| `+0x10` | 2 | `movs r1, #1` | 密钥模式除数 = 1（复用同一段除法） |
| `+0x12` | 2 | `go: mov r0, r2` | 被除数 |
| `+0x14` | 4 | `bl __aeabi_uidiv` | 统一走除法：KEY/1 或 50024/(ID+1) |
| `+0x18` | 2 | `mov r4, r0` | r4 = sync |
| `+0x1A` | 2 | `lsrs r1, r0, #8` | SYNC1 = sync >> 8 |
| `+0x1C` | 2 | `movs r0, #4` | — |
| `+0x1E` | 4 | `bl CC2500_WriteReg` | 写 SYNC1 |
| `+0x22` | 2 | `uxtb r1, r4` | SYNC0 = sync & 0xFF |
| `+0x24` | 2 | `movs r0, #5` | — |
| `+0x26` | 4 | `bl CC2500_WriteReg` | 写 SYNC0 |
| `+0x2A` | 2 | `pop {r4, pc}` | 返回（**无 SCAL、无延时**） |
| `+0x2C` | 4 | `.word KEY` | 私有密钥 |
| `+0x30` | 4 | `.word FLAG`（`0x2000108E`） | C.Fn LIGHT 开关字节 |
| `+0x34` | 4 | `.word 50024` | **原厂字面量，保持同址同值** |

以 `key = 0xD798` 为例，补丁后 56 字节（与原厂对比：本区间差异 48 B；其余 8 B 恰与原厂相同，
含 `+0x34` 的 `50024` 字面量）：

### 6.2 改值即时生效注入（10 B @ `0x08017944` 全 0 死区）

```text
0x08017944  1f b5        push {r0, r1, r2, r3, r4, lr}
0x08017946  80 79        ldrb r0, [r0, #6]          ; 入口 r0 = settings 基址 → r0 = ID
0x08017948  fa f7 38 fc  bl   0x080121BC            ; 同步字函数（内部读 LIGHT 标志）
0x0801794C  1f bd        pop  {r0, r1, r2, r3, r4, pc}  ; 返回原 handler 继续
```

- 注入区 `0x08017944`（文件偏移 `0x14944`）是 **234 B 连续 `0x00` 死区**（到 `0x08017A2D`），
  静态检查确认**无 BL/分支/LDR 字面量/全镜像 u32 绝对地址引用**（§8.3）；
- 本补丁只用前 10 B；原厂这 10 B 全 0，`apply()` 会先校验再写入。

| `0x0800D46E`（C.Fn 递增处理 `0x0800D3D8` 内） | `06 29 07 d0` | `0a f0 69 fa` | 同上 |

| 位置 | 原厂 | 补丁后 | 说明 |
|---|---|---|---|
| `0x080036DA` | `00 7a`（`ldrb r0,[r0,#8]`） | `00 20`（`movs r0,#0`） | 造型灯任务读者固定 0 → 输出保持原厂 12sec 档 |
| `0x08003702` | `01 7a`（`ldrb r1,[r0,#8]`） | `00 21`（`movs r1,#0`） | 同上（第二个读者） |
| `0x0800A6FA` | `08 72`（`strb r2,[r1,#8]`） | `00 bf`（`nop`） | 无线设置同步解包不再覆盖 `settings[8]`，保护密钥开关 |

### 6.5 差异统计与安全约束

- 与原厂的总差异 = **71 字节**，**全部**落在上述 7 处补丁点内（`verify()` 用集合比对断言）：
  同步字函数区 48 B + 注入 10 B + 两个 gate 8 B + 三个 mask 5 B；
  （mask `0x080036DA` 只改高字节，故 1 B 变化）
- 补丁点原始字节全部逐字节校验，固件版本不符直接 `raise ValueError`（防刷错）；
- 输出长度 == 输入长度 == 88,032 B（G3 可直接刷）；
- 50024 字面量保持原址原值（普通模式公式仍依赖它）；
- 代码洞只用前 10 B（234 B 死区余量充足，备用洞 `0x08017D28` 222 B）。

### 6.6 为什么去掉 `SCAL(0x33)+delay(1000)`（以及 20 µs）

本补丁只改同步字、不改频率寄存器，CC2500 手册上改同步字不需要重新校准；56 B 空间
被 LIGHT 开关判断占用，**连原厂的 `delay(20µs)` 也不再保留**（只做两次寄存器写），
这是相对原厂**唯一的射频行为差异**。

> **若实机出现「偶发首包丢失 / 配对不稳」，优先怀疑这里**（回退方案：用保留 strobe/延时的
> 变体，或改用注入方案让原厂收尾继续执行）。

- **整机模拟器未建立**：V1C 没有像 AD100/AD200 那样的整机 Unicorn 模拟机，本轮只做到「调用级」验证

## 8. 待办与风险

### 8.1 实机安全阶梯（建议顺序，风险自负）

1. **原厂基线**：先确认官方 G3 能识别设备、能从官网重下同版本 `V1C_V2.0.bin` 用于回滚；
2. **刷补丁版**：刷入 `V1C_V2.0_keyD798.bin`（或重生成的同名文件）后确认能开机、菜单正常、版本号 V2.0；
3. **LIGHT 菜单确认**：进 C.Fn → 第 3 页第 1 行 `LIGHT`，确认可在 `12sec/OFF/ON` 三档间切换；
   新刷/恢复出厂后应为 **12sec（`settings[8]=0`）**；
4. **普通模式**：LIGHT=12sec（或 OFF），ID=1..99，与原厂引闪器/灯同 CH/ID，确认能正常引闪；
5. **密钥模式**：LIGHT=ON + 已打补丁的引闪器（同一把 0xD798）→ 能引闪；
6. **隔离验证**：把引闪器切回普通模式 → LIGHT=ON 的灯应**不被引闪**（密钥生效）；
7. **即时生效**：不动其它设置，仅来回切 LIGHT ON↔12sec，确认同步字立即切换；
8. **造型灯（LIGHT 代价）**：确认造型灯输出保持原厂 12sec 档行为（补丁把造型灯任务读者固定为 0），
   且 C.Fn 里改 LIGHT 不再改变造型灯模式；
9. **持久化**：重启设备后 LIGHT 仍为 ON；恢复出厂后回到 12sec（普通模式）；
10. **无线设置同步覆盖检查**：用 G3/引闪器做一次「设置同步/远程设置」，确认 LIGHT 不被清回 0/1
    （本补丁已 NOP `0x0800A6FA`，但 `0x0800DCDC` 路径需实测）；
11. 任意一步异常 → 立刻刷回 `devices/v1c/firmware/V1C_V2.0.bin`（详见 [`keypatch/README.md`](../../keypatch/README.md)）。

### 8.2 未确认项 / 已知风险

| 项 | 状态 | 说明 |
|---|---|---|
| 实机验证 | ❌ 未做 | 见 8.1；无整机模拟器 |
| **LIGHT 原厂功能代价** | ⚠️ 已知取舍 | 原厂 LIGHT 三档控制造型灯模式；复用后**造型灯输出固定原厂 12sec 档**（读者被 mask），C.Fn 里 LIGHT 只剩「ON=密钥开关」语义 |
| **无线设置同步覆盖** | ⚠️ 部分保护、待实机 | 已 NOP `0x0800A6FA`（解包写 `settings[8]`）；但 `0x0800DCDC` 路径仍整体写 `settings[1..11]`，需实测「设置同步」不会把 LIGHT 清回 0/1 |
| **恢复默认会关密钥** | ℹ️ 预期行为 | `0x0800E0A4`（`0x0800DCDC` 内「恢复 C.Fn 默认」块，条件 GPIO bitmask `0x300` + `[0x200004F0]==1`）会把 `settings[8]` 清 0 → 回到普通模式；与「恢复默认」语义一致，未 patch |
| **升级语义** | ⚠️ 需告知用户 | 原厂 LIGHT 值 `2 = ON` 与补丁「密钥模式」重合：若设备里已保存 LIGHT=ON，刷入补丁后会**自动进入密钥模式**（普通/未打补丁引闪器无法引闪）；出厂默认 `12sec`(0) 为普通模式 |
| **改值即时同步范围** | ℹ️ 说明 | 两个改值 gate 的 hook 覆盖除 `item9`(LCD，原厂走专用处理) 外的 C.Fn 项；LIGHT=item8 不受影响 |
| LIGHT 菜单显示/导航 | ⚠️ 未实机 | 静态/渲染证据见 `CFN_MENU.md`（3 页×4 行、LIGHT 第 3 页第 1 行、不显示 F 编号） |
| 显示/UI（圆形彩屏/触控） | ❌ 未逆向 | 补丁不改 UI；后续若要加独立「KEY」菜单项得先做 UI 逆向 |
| Flash / RAM 容量 | ⚠️ 待确认 | 只确认了向量表与 SP；8 KB RAM 为静态推断 |
| 代码洞 | ✅ 静态确认 | `0x08017944` 234 B 全 0 死区，无引用；备用 `0x08017D28` 222 B（§8.3） |
| 删 `SCAL+1ms`（及 20 µs） | ⚠️ 理论安全 | 只改同步字不改频率；实机首包异常优先怀疑此处（§6.6） |
| 版本绑定 | ✅ 有防护 | `sha256` + 7 处补丁点原始字节双校验，版本不符直接拒绝打补丁 |
| G3 容器 | ✅ 已备 | `--container` 生成 `*_container.bin`（文件名含 `V1C`，G3 才认） |
| 16 位同步字强度 | ⚠️ 非密码学 | 挡的是正常原厂设备误触发；SDR 抓包理论上可克隆 |
| 早期假设修正 | ℹ️ 已记录 | Lead 初扫曾假设 item7 =「稳定色温」；`CFN_SETTINGS.md` §7 证明 item7 是 **BEEP**，V1C 的 C.Fn 表与 AD200 不同 |

### 8.3 代码洞（注入区）说明

- 注入放在 **`0x08017944`**（文件偏移 `0x14944`）：**234 B 连续 `0x00`**（到 `0x08017A2D`）；
- 检查口径：全镜像所有 `BL/BLX` 目标、所有 `B`/条件分支目标、所有 `LDR(literal)` 目标、
  按 2 字节步长扫描的 4 字节绝对地址（含 `|1` thumb 变体）——**0 处引用**；
- 较小全 0 段（`0x0801749E` 57 B、`0x08016F0A` 36 B、`0x08016F42` 29 B）有字面量/分支引用，**不可用**；
- 备用洞 **`0x08017D28`**（222 B，到 `0x08017E05`）同样 0 引用，可作未来扩展；
- **风险**：死区结论只对 `V1C_V2.0.bin`（sha256 `4435dda8…`）有效；换版本必须重跑代码洞扫描
  （`devices/v1c/re/cfn_cave.py`）。
