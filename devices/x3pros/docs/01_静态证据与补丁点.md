# X3 Pro S（X3 Pro S 引闪器）v1.11 —— 静态证据与补丁点

本文记录 **Godox X3 Pro S v1.11** 的「私有密钥」补丁所依赖的静态证据、补丁点定位过程与
可复现脚本，供复核/换版本时重新定位用。结论已汇总进 [`../README.md`](../README.md)，
这里只放**过程证据**。

> 前置：仓库根便携 Python（capstone 5.0.7 / unicorn 2.1.4）`tools\python\python.exe`；
> 原厂固件 `devices/x3pros/firmware/X3pro_S_v1.11_app.bin`（不随仓库分发）。
>
> 文中地址均为**虚拟地址**；文件偏移 = 虚拟地址 − **`0x08020000`**（即 `0x0802F0C0` ↔ 文件 `0x00F0C0`）。

## 1. 镜像与基址判定

### 1.1 基本事实

| 项目 | 值 |
|---|---|
| 文件 | `devices/x3pros/firmware/X3pro_S_v1.11_app.bin` |
| 字节数 | **1,931,868 B（0x1D7A5C）** |
| sha256 | `4b3465cab7975749dd3d109aa1b6f60ee065402869aa88d7b007325def90e103` |
| 镜像基址 | **`0x08020000`** |
| 镜像范围 | `0x08020000–0x081F7A5C`（长度 = 1,931,868 B，正好等于文件长度） |
| 向量表 | `[0]` 初始 SP = **`0x20270000`**；`[1]` Reset = **`0x0803139D`**（Thumb）→ 处理函数 `0x0803139C` |
| 版本/机型串 | file **0x99E50** 附近：`v1.11`（0x99E54）与 ` X3Pro  S`（0x99E5D，Pro 与 S 之间两个空格） |

### 1.2 基址判定证据（三条互相印证）

1. **向量表初值**：镜像前 4 字节 `00 00 27 20` = `0x20270000`，落在 RAM（`0x20000000` 起），
   是合法初始 MSP；第 2 个字 `9d 13 03 08` = `0x0803139D`，最低位为 1（Thumb），
   处理函数 `0x0803139C` 位于 flash 区。只有取基址 `0x08020000` 时，`0x0803139C` 才精确
   落在文件偏移 `0x1139C` 的标准启动序列上；若按 `0x08000000` 解释，同一地址会落到文件
   偏移 `0x3139C` 的另一段代码（不是 Reset_Handler），即可排除；
2. **启动序列自证**：把文件按 `0x08020000` 加载后，`0x0803139C` 处是标准 `Reset_Handler`：

   ```asm
   0x0803139C  df f8 34 d0  ldr.w sp, [pc, #0x34]   ; 重设 SP（字面量 @0x080313D4 = 0x20270000）
   0x080313A0  ff f7 52 fc  bl    0x08030C48        ; SystemInit
   0x080313A4  00 21        movs  r1, #0
   0x080313A6  03 e0        b     0x080313B0
   0x080313A8  0b 4b        ldr   r3, [pc, #0x2c]   ; .data 源
   0x080313AA  5b 58        ldr   r3, [r3, r1]
   0x080313AC  43 50        str   r3, [r0, r1]      ; 拷 .data
   0x080313AE  04 31        adds  r1, #4
   0x080313B0  0a 48        ldr   r0, [pc, #0x28]   ; .data 目的
   0x080313B2  0b 4b        ldr   r3, [pc, #0x2c]   ; .data 结束
   0x080313B4  42 18        adds  r2, r0, r1
   0x080313B6  9a 42        cmp   r2, r3
   0x080313B8  f6 d3        blo   0x080313A8
   0x080313BA  0a 4a        ldr   r2, [pc, #0x28]   ; .bss 起
   0x080313BC  02 e0        b     0x080313C4
   0x080313BE  00 23        movs  r3, #0
   0x080313C0  42 f8 04 3b  str   r3, [r2], #4       ; 清 .bss
   0x080313C4  08 4b        ldr   r3, [pc, #0x20]   ; .bss 止
   0x080313C6  9a 42        cmp   r2, r3
   0x080313C8  f9 d3        blo   0x080313BE
   0x080313CA  7d f0 61 fb  bl    0x080AEA90        ; C 运行时/初始化
   0x080313CE  f9 f7 db fe  bl    0x0802B188        ; main 方向
   0x080313D2  fe e7        b     0x080313D2        ; 不应返回
   ```

   字面量池在 file `0x113D4–0x113EB`：`0x20270000`（SP）、`0x081C8F44`（`.data` 源，落在镜像内）、
   `0x20000000` / `0x20000234` / `0x20000440` / `0x2001A1C8`（`.data` 目的、`.bss` 起止、栈顶，
   均落在 RAM `0x20000000` 起），与 `0x08020000` 基址自洽；
3. **代码/数据自引用**：Reset 调用的 `0x08030C48`、`0x080AEA90`、`0x0802B188` 以及后文
   同步字函数、发送入口、辅助函数的反汇编目标（`bl` 立即数）都落在 `0x08020000–0x081F7A5C`。
   用错误的基址反汇编时，这些 `bl` 目标会散落到区间外，无法自洽。

### 1.4 MCU 判定的静态依据

- **Thumb-2（32 位指令）**：同步字函数里有 `movw r4,#0xC368`（`4c f2 68 34`）、
  `udiv r4,r4,r3`（`b4 fb f3 f4`）、`sub sp,#8`、`mov.w r0,#0x3E8` 等；
  `0x0802F116` 处还有 32 位 `b.w`（`0x0802F11A` 是 `nop`）——Cortex-M0 不支持这些编码，可排除 Thumb-1 内核；
- **硬件除法**：`udiv`（`b4 fb f3 f4`）是 Cortex-M3/M4 的 Thumb-2 指令；
- **FPU**：按静态结论与同族对照，该类镜像为 **Cortex-M4F 类**（Artery AT32F435/437，
  与 C 版 V1.22 同族）；本文档**不逐条枚举** FPU 指令，换版本复核时请重跑 FPU 指令扫描；
- **地址空间**：镜像落在 `0x08020000–0x081F7A5C`，与「2 MB flash 窗口（`0x08000000` 起）」
  自洽；初始 SP `0x20270000` 说明 RAM 从 `0x20000000` 起、至少映射到 `0x20270000`。

### 1.5 版本/机型字符串

```text

file 0x099E40  95 cc 07 08 99 cc 07 08 9d cc 07 08 a1 cc 07 08
file 0x099E50  a5 cc 07 08 76 31 2e 31 31 00 00 00 20 58 33 50   ; ....v1.11... X3P
```

- `v1.11`：file **0x99E54**（虚拟地址 `0x080B9E54`）；
- `X3Pro  S`：file **0x99E5D**（虚拟地址 `0x080B9E5D`，`Pro` 与 `S` 之间**两个空格**）。

## 2. 同步字函数定位 `0x0802F0C0`

### 2.1 定位方法

1. 原厂公式常量 **`50024 = 0xC368`**。Cortex-M4 上编译器通常用 `movw` 立即数（不是字面量池），
   所以直接搜 4 字节编码 `4c f2 68 34`（`movw r4,#0xC368`）；
2. 命中位置：file **0x00F0C6** = 虚拟地址 **`0x0802F0C6`**（该 4 字节编码在全镜像**唯一**）；
3. 向上回溯到函数入口：`0x0802F0C0` 处为 `movs r2,#1 / mov r3,r0 / push {r4,lr}`，
   即标准函数序言；向下确认下一函数起点 **`0x0802F11C`**（`push {r4,lr}`）；
4. 交叉验证：该函数确实按 `50024/(ID+1)` 写 CC2500 reg4/reg5，并带
   `delay(20) → SCAL(0x33) → delay(1ms) → SIDLE(0x36) → delay(700)` 收尾。

### 2.2 原厂反汇编（92 字节）

函数区间 `0x0802F0C0..0x0802F11B`，共 **92 字节**：

```asm
0x0802F0C0  01 22        movs  r2, #1
0x0802F0C2  03 46        mov   r3, r0             ; r3 = 入参 ID
0x0802F0C4  10 b5        push  {r4, lr}
0x0802F0C6  4c f2 68 34  movw  r4, #0xC368        ; 50024（原厂分子）
0x0802F0CA  13 44        add   r3, r2             ; r3 = ID + 1
0x0802F0CC  b4 fb f3 f4  udiv  r4, r4, r3         ; r4 = 50024 / (ID+1)
0x0802F0D0  82 b0        sub   sp, #8
0x0802F0D2  23 0a        lsrs  r3, r4, #8         ; SYNC1 = sync >> 8
0x0802F0D4  0d f1 07 01  add.w r1, sp, #7
0x0802F0D8  04 20        movs  r0, #4
0x0802F0DA  8d f8 07 30  strb.w r3, [sp, #7]
0x0802F0DE  ff f7 5d fb  bl    0x0802E79C         ; write_reg(4, [sp+7], 1)
0x0802F0E2  01 22        movs  r2, #1
0x0802F0E4  0d f1 07 01  add.w r1, sp, #7
0x0802F0E8  05 20        movs  r0, #5
0x0802F0EA  8d f8 07 40  strb.w r4, [sp, #7]      ; SYNC0 = sync & 0xFF
0x0802F0EE  ff f7 55 fb  bl    0x0802E79C         ; write_reg(5, [sp+7], 1)
0x0802F0F2  14 20        movs  r0, #0x14
0x0802F0F4  fc f7 c0 fa  bl    0x0802B678         ; delay_us(20)
0x0802F0F8  33 20        movs  r0, #0x33
0x0802F0FA  ff f7 07 fc  bl    0x0802E90C         ; strobe(SCAL 0x33)
0x0802F0FE  4f f4 7a 70  mov.w r0, #0x3E8
0x0802F102  fc f7 b9 fa  bl    0x0802B678         ; delay_us(1000)
0x0802F106  36 20        movs  r0, #0x36
0x0802F108  ff f7 00 fc  bl    0x0802E90C         ; strobe(SIDLE 0x36)
0x0802F10C  4f f4 2f 70  mov.w r0, #0x2BC
0x0802F110  02 b0        add   sp, #8
0x0802F112  bd e8 10 40  pop.w {r4, lr}
0x0802F116  fc f7 af ba  b.w   0x0802B678         ; 尾调用 delay_us(700)
0x0802F11A  00 bf        nop
0x0802F11C  10 b5        push  {r4, lr}          ; 下一函数（不是补丁区）
```

原厂 92 字节（逐字节校验基准）：

```text

23 0a 0d f1 07 01 04 20 8d f8 07 30 ff f7 5d fb 01 22
0d f1 07 01 05 20 8d f8 07 40 ff f7 55 fb 14 20 fc f7
c0 fa 33 20 ff f7 07 fc 4f f4 7a 70 fc f7 b9 fa 36 20
```

### 2.3 关键观察

- 函数**没有字面量池**：`50024` 是 `movw` 立即数，所以 10 字节补丁点
  `0x0802F0C6..0x0802F0CF` 恰好覆盖 `movw + add + udiv` 三条指令；
- 函数入口前 6 字节（`0x0802F0C0..0x0802F0C5`：`movs r2,#1` / `mov r3,r0` / `push {r4,lr}`）
  **必须保留**：注入代码从 `0x0802F0C6` 进入时依赖 `r2=1`、`r3=ID`、`{r4,lr}` 已入栈；
- 收尾 `delay(20)+SCAL(0x33)+delay(1000)+SIDLE(0x36)+delay(700)` 是 CC2500 改同步字后的
  原厂校准/置闲序列，**补丁完整保留**（不删 SCAL、不删延时）。

## 3. 10 字节补丁（`0x0802F0C6`）

| 项 | 内容 |
|---|---|
| 地址 | `0x0802F0C6`（文件偏移 `0x00F0C6`） |
| 长度 | 10 字节 |
| 原厂 | `4c f2 68 34 13 44 b4 fb f3 f4`（`movw r4,#0xC368; add r3,r2; udiv r4,r4,r3`） |
| 补丁后 | `B.W <inj_sync>`（4 B）+ `00 bf` × 3（6 B） |
| 恢复点 | `0x0802F0D0`（`sub sp,#8`，原厂收尾序列起点） |

注入逻辑（进入 `inj_sync` 时 `r0 = ID`、`r2 = 1`、`r3 = ID`）：

```asm
inj_sync:
    cmp   r0, #99            ; 当前 ID == 99（密钥模式）？
    bne   inj_sync_orig
    movw  r4, #KEY           ; 是：r4 = 私有 KEY（16 位）
    b.w   0x0802F0D0         ; 回到原厂：写 SYNC1/SYNC0 + SCAL/延时
inj_sync_orig:
    movw  r4, #0xC368        ; 否：原厂 10 字节原样重放
    add   r3, r2             ; r3 = ID + 1
    udiv  r4, r4, r3         ; r4 = 50024/(ID+1)
    b.w   0x0802F0D0
```

因此补丁后：

- **ID=99**：`SYNC1/SYNC0 = KEY>>8 / KEY&0xFF`；
- **ID=0..98**：`SYNC1/SYNC0 = (50024/(ID+1))>>8 / &0xFF`，与原厂逐位一致；
- 两条路径都回到 `0x0802F0D0`，原厂 `delay(20)+SCAL+delay(1ms)+SIDLE+delay(700)` **照常执行**。

> 为什么不用「改 `movw` 立即数」的极简方案：`movw` 立即数只有 16 位，改它只能让
> **所有 ID 恒为 KEY**（像 X3-S v1 那样没有开关）；要按 ID=99 分流必须换成分支，
> 而原函数 92 字节里没有多余空间，故用「10 B 跳转 + 注入区分流」。

## 4. 两个低层发送入口（TX4 / TX2）

| 项 | TX4 | TX2 |
|---|---|---|
| 函数入口 | `0x0802EE44` | `0x0802EEAC` |
| 帧类型 | 4 字节帧（`0x7F` FIFO burst + STX + 600µs + SFTX/SIDLE） | 2 字节短命令（`0x7F` FIFO burst + STX + 500µs + SFTX/SIDLE） |
| 入口原厂 4 B | `10 b5 ff f7`（`push {r4,lr}; bl 0x0802ECE4`） | `10 b5 ff f7`（同上） |
| 函数体恢复点 | `0x0802EE4A` | `0x0802EEB2` |
| 补丁后入口 | `B.W <inj_tx4>` | `B.W <inj_tx2>` |
| 静态调用点数 | 18 处 `bl 0x0802EE44` | 10 处 `bl 0x0802EEAC` |

TX4 函数体（反汇编摘要）：

```asm
0x0802EE44  10 b5        push  {r4, lr}
0x0802EE46  ff f7 4d ff  bl    0x0802ECE4        ; radio_wake（置忙）
0x0802EE4A  01 22        movs  r2, #1          ; ↓ GPIO/状态切换（3 次 bl 0x08032ABC）
0x0802EE4C  14 4c        ldr   r4, [pc, #0x50]   ; 帧缓冲/寄存器基址
...
0x0802EE60  04 22        movs  r2, #4
0x0802EE62  10 49        ldr   r1, [pc, #0x40]
0x0802EE64  7f 20        movs  r0, #0x7f        ; FIFO burst 写 4 字节
0x0802EE66  ff f7 99 fc  bl    0x0802E79C        ; write_reg(0x7F, buf, 4)
0x0802EE6A  35 20        movs  r0, #0x35        ; STX
0x0802EE6C  ff f7 4e fd  bl    0x0802E90C        ; strobe(0x35)

0x0802EE7A  ff f7 47 fd  bl    0x0802E90C        ; strobe(0x3B)

0x0802EE80  ff f7 44 fd  bl    0x0802E90C        ; strobe(0x36)

0x0802EE9E  10 bd        pop   {r4, pc}
```

TX2 函数体（反汇编摘要）：

```asm
0x0802EEAC  10 b5        push  {r4, lr}
0x0802EEAE  ff f7 19 ff  bl    0x0802ECE4        ; radio_wake（置忙）
0x0802EEB2  01 22        movs  r2, #1          ; ↓ GPIO/状态切换
...
0x0802EEC8  28 20        movs  r0, #0x28        ; 40
0x0802EECA  fc f7 d5 fb  bl    0x0802B678        ; delay_us(40)
0x0802EECE  02 22        movs  r2, #2
0x0802EED0  10 49        ldr   r1, [pc, #0x40]
0x0802EED2  7f 20        movs  r0, #0x7f        ; FIFO burst 写 2 字节
0x0802EED4  ff f7 62 fc  bl    0x0802E79C        ; write_reg(0x7F, buf, 2)
0x0802EED8  35 20        movs  r0, #0x35        ; STX
0x0802EEDA  ff f7 17 fd  bl    0x0802E90C        ; strobe(0x35)
0x0802EEDE  4f f4 fa 70  mov.w r0, #0x1f4       ; 500
0x0802EEE2  fc f7 c9 fb  bl    0x0802B678        ; delay_us(500)
0x0802EEE6  3b 20        movs  r0, #0x3b        ; SFTX
0x0802EEE8  ff f7 10 fd  bl    0x0802E90C        ; strobe(0x3B)
0x0802EEEC  36 20        movs  r0, #0x36        ; SIDLE
0x0802EEEE  ff f7 0d fd  bl    0x0802E90C        ; strobe(0x36)
...
0x0802EF0A  1a 70        strb  r2, [r3]         ; 清忙标志
0x0802EF0C  10 bd        pop   {r4, pc}
```

**为什么改入口 4 字节而不是函数体**：

- 两个函数入口的开头 4 字节完全相同（`push {r4,lr}; bl radio_wake` 的前半），
  可以用同一种 `B.W` 注入 + 蹦床恢复的手法；
- 注入包装自己控制「先写 SYNC=KEY → 发原厂第一帧 → 写 SYNC=0x01F4 → 发原厂第二帧 →
  写回 SYNC=KEY」；原厂函数体（组帧/FIFO/发射/清忙）一个字节都不改；
- 同步字必须在 `radio_wake` **之后**写（射频未唤醒时写 CC2500 寄存器可能失效），
  所以蹦床里重建 `push {r4,lr}; bl radio_wake` 再写同步字，最后 `b.w` 回函数体恢复点。

## 5. 辅助函数

| 符号 | 地址 | 说明 |
|---|---|---|
| `write_reg` | `0x0802E79C` | `r0`=寄存器地址、`r1`=缓冲区指针、`r2`=长度；`reg \| 0x40` 为 burst（如 `0x44` = 从 SYNC1 起连写 2 字节） |
| `strobe` | `0x0802E90C` | 命令选通：`0x33`=SCAL、`0x35`=STX、`0x36`=SIDLE、`0x3B`=SFTX |
| `delay_us` | `0x0802B678` | 忙等延时；同步字函数用 `20/1000/700`，TX4 用 `600`，TX2 用 `40/500` |
| `radio_wake` | `0x0802ECE4` | 射频唤醒/置忙；TX4/TX2 入口第一条 `bl` 就是它 |
| GPIO 辅助 | `0x08032A64` / `0x08032A58` | GPIO 写/读辅助（发送路径状态切换会用到） |

> 注入侧的 `set_sync(r0 = 16 位同步字)` 用 **burst `0x44`** 一次写 SYNC1/SYNC0：
> 在栈上准备 `[SYNC1, SYNC0]` 两字节缓冲，`write_reg(0x44, buf, 2)`。

## 6. 设置结构与 ID 上限

### 6.1 设置结构

- 基址 **RAM `0x20001768`**：`[+0] = 频道`、`[+1] = ID`（`[+1]` 的字段语义由
  `0x08029A0E` 的 ID 加减 handler 与 `0x08025E30` 的组帧代码印证）；
- 同步字函数的入参 `r0` 是**当前 ID**（ID 字段在设置区 `[+1]`；换版本时请用 §10 脚本
  核对调用点的取参指令与来源）；
- 无线帧组包（`0x08025E30` 附近）会把设置区字节派生的字段打进帧头，
  即**第二帧的 ID 语义仍是原厂的**，补丁只换同步字。

### 6.2 ID 上限钳位（`0x08029A1C`）

ID 加减 handler 在 `0x08029A0E` 附近；`0x08029A1C` 处是钳位指令（含 `+1` / `+10` 两种步进）：

```asm
0x08029A0E  07 4b        ldr   r3, [pc, #0x1c]      ; r3 = 某按键/状态字节指针
0x08029A10  07 4a        ldr   r2, [pc, #0x1c]      ; r2 = 设置结构（ID = [r2,#1]）
0x08029A12  19 78        ldrb  r1, [r3]
0x08029A14  53 78        ldrb  r3, [r2, #1]       ; r3 = 当前 ID
0x08029A16  31 b1        cbz   r1, 0x08029A26
0x08029A18  0a 33        adds  r3, #0xa          ; +10 步进
0x08029A1A  db b2        uxtb  r3, r3
0x08029A1C  63 2b        cmp   r3, #0x63          ; 99
0x08029A1E  88 bf        it    hi
0x08029A20  63 23        movhi r3, #0x63          ; 上限 = 99
0x08029A22  53 70        strb  r3, [r2, #1]
0x08029A24  10 bd        pop   {r4, pc}
0x08029A26  01 33        adds  r3, #1             ; +1 步进
0x08029A28  db b2        uxtb  r3, r3
0x08029A2A  f7 e7        b     0x08029A1C
```

结论：**ID 菜单值域 0..99，`ID=99` 是菜单可达的合法值**，所以补丁可以把 `ID=99`
复用为密钥模式而不改 UI；代价是密钥模式下 `ID=99` 不再是普通 ID。

> 注意：本轮**没有**逆向 ID/设置的 flash 持久化链（save/load），重启后 ID 是否保持需实机确认。

## 7. 全镜像 SYNC 写点唯一性

### 7.1 扫描口径

线性反汇编（capstone `CS_MODE_THUMB | CS_MODE_MCLASS`，`skipdata=True`，扫完整镜像到 `0x081F7A5C`），
匹配 `bl 0x0802E79C`（`write_reg`），并解析调用前对 `r0` 的立即数赋值。结果：

- `write_reg` 调用点共 **80 处**；
- 其中 `r0` 为 **4** 的 **2 处**、为 **5** 的 **2 处**，其余为 `0/2/3/6/8..46/62/126/127`
  或无法静态确定（`None`，9 处）。

### 7.2 写寄存器 4/5 的全部位置

| 调用点 | 写入 | 场景 |
|---|---|---|
| `0x0802E9D0` | reg 4 ← `0xC3` | CC2500 初始化表（**缺省值**，随后被同步字函数覆盖） |
| `0x0802E9E2` | reg 5 ← `0x68` | 同上（`0xC3/0x68` = `50024` 的高/低字节，即 ID=0 的同步字） |
| `0x0802F0DE` | reg 4 ← `sync>>8` | 同步字函数（**唯一运行期写入**） |
| `0x0802F0EE` | reg 5 ← `sync&0xFF` | 同步字函数（同上） |

初始化表反汇编（`0x0802E9C2` / `0x0802E9D4` 处装立即数）：

```asm
0x0802E9C2  c3 22        movs  r2, #0xC3
0x0802E9C4  0d eb 08 01  add.w r1, sp, r8
0x0802E9C8  8d f8 07 20  strb.w r2, [sp, #7]
0x0802E9CC  04 20        movs  r0, #4
0x0802E9CE  22 46        mov   r2, r4
0x0802E9D0  ff f7 e4 fe  bl    0x0802E79C        ; SYNC1 = 0xC3
0x0802E9D4  68 22        movs  r2, #0x68
0x0802E9D6  0d eb 08 01  add.w r1, sp, r8
0x0802E9DA  8d f8 07 20  strb.w r2, [sp, #7]
0x0802E9DE  05 20        movs  r0, #5
0x0802E9E0  22 46        mov   r2, r4
0x0802E9E2  ff f7 db fe  bl    0x0802E79C        ; SYNC0 = 0x68
```

**结论**：运行期唯一写 SYNC1/SYNC0 的入口就是 `0x0802F0C0`；初始化表的 `0xC3/0x68` 只是
缺省值，会被随后的同步字函数覆盖。所以补丁只需改写这一个函数的 10 字节（+ 发送入口的双发包装），
**不需要**动初始化表。

## 8. 同步字函数调用点

线性反汇编 + `bl` 目标匹配：`bl 0x0802F0C0` 共 **6 处**：

| 调用点 | 说明 |
|---|---|
| `0x0802F1B4` | 同步字函数之后的射频封装族 |
| `0x0802F1C4` | 同上 |
| `0x0802F2AE` | RF 初始化/重同步路径 |
| `0x0802F786` | 设置/同步路径 |
| `0x0802F7A6` | 同上 |
| `0x0802F962` | 同上 |

> 口径说明：这是**线性反汇编扫描**结果（不是 CFG/数据流证明）；换版本后必须重扫。
> 6 处共享同一函数，且 §7 证明运行期只有它写 SYNC —— 因此改这一个函数即可覆盖全部设置路径。

## 9. 注入区选址与热靴 blob 边界

### 9.1 主固件尾部空间

| 区间（文件偏移） | 虚拟地址 | 长度 | 内容 |
|---|---|---|---|
| `0x1A9378–0x1D4000` | `0x081A9378–0x081D4000` | 175,240 B | **连续 `0xFF` 擦除态**（最后非 `FF` 字节在 file `0x1A9377` / vaddr `0x081A9377`） |
| **`0x1CA000–0x1CA400`** | **`0x081CA000–0x081CA400`** | **0x400 B** | **本补丁注入区**（原厂全 `FF`，已逐字节确认） |
| `0x1D4000–0x1D7A5C` | `0x081D4000–0x081F7A5C` | 14,940 B | **热靴子镜像 blob**（Sony 热靴 MCU 固件，**不动**） |

注入区距代码尾约 **0x20C88** 字节、距热靴 blob 起点约 **0x9C00** 字节，两侧余量充足。

### 9.2 引用检查

对本镜像做三类静态检查（本目录复核，2026-11-11）：

1. 线性反汇编的所有 `B`/`B.W`/条件分支目标：**0 处**落进 `0x081CA000–0x081CA400`；
2. 按 2 字节步长扫描全镜像 4 字节小端字（含 `|1` Thumb 变体）：**0 处**等于注入区地址；
3. 注入区 `0x400` 字节：**全部为 `0xFF`**。

> 完整独立复核（CFG/数据流口径）由 Lead / 补丁模块的审计结论负责；本文档的检查脚本见 §10，
> 换版本后请重跑。

### 9.3 热靴 blob 边界

- blob 起点 file **0x1D4000**（vaddr `0x081D4000`），到文件尾 `0x1D7A5C`，共 **14,940 B（0x3A5C）**；
- 它有自己的向量表：SP = `0x200004F8`、Reset = `0x080020CD` —— 说明它是**独立链接在 `0x08000000`**
  的另一个 MCU 固件（Sony 热靴子 MCU），与主程序地址空间不重叠；
- **本补丁不改它、不引用它**：注入区在它之前 0x9C00 字节处结束。

### 10.3 检查注入区引用（分支 / 绝对地址）

```powershell
tools\python\python.exe -c @"
import struct
from capstone import Cs, CS_ARCH_ARM, CS_MODE_THUMB, CS_MODE_MCLASS
FW, BASE = r'devices/x3pros/firmware/X3pro_S_v1.11_app.bin', 0x08020000
d = open(FW, 'rb').read()
LO, HI = 0x081CA000, 0x081CA400
md = Cs(CS_ARCH_ARM, CS_MODE_THUMB | CS_MODE_MCLASS); md.skipdata = True
br = []
for ins in md.disasm(d, BASE):
    if ins.mnemonic.startswith('b') or ins.mnemonic in ('beq','bne','bcc','bcs','bhi','blo'):
        try: tgt = int(ins.op_str.split('#')[-1], 16)
        except ValueError: continue
        if LO <= tgt < HI: br.append((hex(ins.address), hex(tgt)))
abs_refs = [hex(BASE+o) for o in range(0, len(d)-3, 2)
            if LO <= struct.unpack_from('<I', d, o)[0] - (struct.unpack_from('<I', d, o)[0] & 1) < HI]
print('branch into inj:', br)
print('u32 absolute refs into inj:', abs_refs[:10], 'count', len(abs_refs))
print('inj all FF:', all(b == 0xFF for b in d[LO-BASE:HI-BASE]))
"@
```
