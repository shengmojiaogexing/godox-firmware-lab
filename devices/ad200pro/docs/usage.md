# GODOX AD200 Pro 固件调试模拟机 · 使用说明

> 适用项目：`devices\ad200pro`（Windows / PowerShell）
> 前端实现：`webui/`（纯静态、无构建、无 CDN、无网络依赖）
> 后端契约：`docs/SIM-SPEC.md` §4 / §6
> 本文档面向使用者，说明如何启动、如何操作调试器界面、虚拟外设怎么用，以及常见问题与限制。

---

## 1. 这是什么

本项目把 `firmware/AD200pro_V1.60.bin`（GODOX AD200 Pro 闪光灯固件，Cortex-M0，基址 `0x08003000`）放进 Unicorn 模拟器中运行，并提供两种入口：

| 入口 | 说明 |
|---|---|
| **CLI**（`sim.cli`） | 交互式命令行调试（run / bp / step / mem / dis / dev / trace） |
| **Web UI**（`sim.server` + `webui/`） | 浏览器里的单页调试器：寄存器、反汇编、内存、断点、trace、调用栈、虚拟整机面板 |

本目录中的 `webui/mock_server.py` 是一个**独立的假后端**：不依赖 Unicorn / capstone，用确定性假数据实现 SIM-SPEC §6 的全部 HTTP 端点，用于在真实模拟器后端就绪之前自测前端。它和真实后端的使用方式一致（只是数据是假的）。

调试器前端的功能概览：

- 顶部：复位 / 运行 / 暂停 / 单步 / 步进 N 条 / 连接与运行状态灯 / 当前 PC（符号名 + 地址）/ 指令数 / uptime。
- 左栏：R0–R15、xPSR、PRIMASK；NVIC 中断使能与挂起；断点列表（点击删除）。
- 中栏：反汇编（当前 PC 高亮，点击行设置/清除断点）+ 内存 hex 视图（跳转、翻页、点击字节编辑写入，每行 16 字节）。
- 右栏：虚拟整机 —— 电池电压（mV）/ 电容电压（V）/ 温度滑条，POWER/TEST/MENU/SET/UP/DOWN 按键，RF 接收十六进制注入，GPIO A/B/C/D/F 各 16 位引脚状态，ADC 通道读数。
- 底部：Trace 日志（按 call / mmio / irq / gpio_change / unimpl / fault 过滤，自动滚动）、调用栈、固件控制台。

## 2. 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows（示例命令为 PowerShell） |
| Python | `..\..\tools\python\python.exe`（Python 3.12，含 capstone 5.0.7 / unicorn 2.1.4） |
| 浏览器 | 任意现代浏览器（Edge / Chrome / Firefox 均可；需支持 ES2017+、`fetch`、CSS Grid） |
| 网络 | **全程不需要联网**；前端不引用任何 CDN/外网资源，字体使用系统字体 |
| 构建 | 无构建步骤；`webui/` 直接由后端静态托管 |

以下命令均假设从仓库根开始，先进入本设备目录：

```powershell
cd devices\ad200pro
```

为方便书写，下文把 `..\..\tools\python\python.exe` 简称为 `python.exe`。如果你的终端可直接使用 `python`，把 `..\..\tools\python\python.exe` 替换成 `python` 即可。

> 说明：仓库根 `tools\python` 是 Windows embeddable 版，`sys.path` 不含当前目录，
> `python -m sim.xxx` 会找不到 `sim` 包。因此本目录提供 `run_sim.py` 转发模块方式：
> `..\..\tools\python\python.exe run_sim.py sim.server …`。用系统 Python 时仍可 `python -m sim.server …`。

## 3. 快速开始

### 3.1 真实模拟器 + Web UI（推荐）

启动后端（它会同时提供 `/api/*` 与 `webui/` 静态文件）：

```powershell
cd devices\ad200pro
..\..\tools\python\python.exe run_sim.py sim.server firmware\AD200pro_V1.60.bin --port 8765
```

然后浏览器打开：

```
http://127.0.0.1:8765
```

> 说明：`sim/server.py` 与 `webui/` 通过 SIM-SPEC §6 契约解耦，命令行参数与静态托管行为以实际 `--help` 与运行输出为准。若后端尚未提供 `server.py`，请使用 3.2 的 mock 后端先体验前端；若后端没有托管 `webui/`，请使用 3.4 的跨端口方式。
> 若默认端口 8765 已被其它程序占用，可以改用其它端口启动（例如 `--port 8899`），然后浏览器打开对应端口即可（页面同源访问 API，无需额外配置）。

### 3.2 仅启动 Mock 后端（前端自测 / 演示）

在没有真实后端、或只想验证前端交互时：

```powershell
cd devices\ad200pro
..\..\tools\python\python.exe webui\mock_server.py --port 8766
```

浏览器打开：

```
http://127.0.0.1:8766
```

可用参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址 |
| `--port` | `8766` | 监听端口（真实后端默认 8765，二者可同时运行） |
| `--webui` | 脚本所在目录 | 静态文件目录 |
| `--verbose` | 关 | 打印每个 HTTP 请求，便于排查 |

Mock 后端的特点：

- 假数据：反汇编是确定性生成的“像样”Thumb 指令流；寄存器、trace、内存、设备状态均为模拟值；
- 支持全部 §6 端点（含 POST 运行/单步/断点/内存写入/设备注入）；
- **不能**反映真实固件行为，不能替代真实后端；
- 页面中所有交互（断点、内存编辑、滑条、按键、RF、trace 过滤等）都可以正常自测。

停止：在运行它的终端按 `Ctrl+C`。

### 3.3 CLI 调试入口

```powershell
cd devices\ad200pro
..\..\tools\python\python.exe run_sim.py sim.cli firmware\AD200pro_V1.60.bin
```

常用命令（以 SIM-SPEC §5 为准，实际命令名以 `sim/cli.py` 实现为准；若 CLI 尚未提供，Web 调试器不依赖它）：

| 命令 | 作用 |
|---|---|
| `run` | 连续运行，直到断点 / 指令上限 / 到达主循环 |
| `c` / `s [n]` | 继续 / 单步 n 条 |
| `bp 0x800CDB0` | 设置断点（无参数可列出） |
| `regs` | 打印寄存器 |
| `mem 0x20000000 64` | 读内存 |
| `dis 0x800CDB0 16` | 反汇编 |
| `irq` | NVIC 使能 / 挂起状态 |
| `mmio` | 最近的 MMIO 访问 |
| `dev set battery=3.7 cap=330` | 设置虚拟设备量 |
| `rf 01 23 45` | 注入 RF 接收数据 |
| `trace 50` | 打印最近 trace |
| `quit` | 退出 |

### 3.4 跨端口联调（前端 8766 / 后端 8765）

当页面不由 `sim.server` 托管时，可以让页面连接另一个端口：

1. 用 mock 的静态页面启动前端（3.2），或任选一个静态服务器托管 `webui/`；
2. 点击右上角 **⚙** 打开“连接设置”；
3. 在“后端 API 地址”填入 `http://127.0.0.1:8765`，点 **应用并重连**；
4. 想恢复默认时点 **恢复同源**（设置保存在浏览器 `localStorage`）。

注意：

- 跨端口访问要求后端在响应中允许 CORS（`Access-Control-Allow-Origin`）；`sim/server.py` 若未开启 CORS，请直接访问 8765 由后端托管页面，避免跨域。
- 页面标题栏的“模拟器已连接”以实际 `/api/status` 是否成功为准；失败时会显示启动提示。

## 4. 界面说明

### 4.1 顶部工具条

| 控件 | 说明 |
|---|---|
| **⟲ 复位** | `POST /api/reset`，把固件恢复到复位向量（PC=0x080030D4，SP=0x200008B0），清空 trace 视图并重新读取寄存器/反汇编/内存。 |
| **▶ 运行** | `POST /api/run`（默认 `max_insns = 2,000,000`）。运行到断点、指令上限、卡死或故障为止；期间状态灯显示“运行中”。实测每次运行约 200 万条指令、约 1 秒，连续多次点击会在 `adc_task`、`display_task`、`rf_spi_write_byte` 等任务间推进 PC。 |
| **⏸ 暂停** | `POST /api/pause`，请求后端停止运行（后端支持协作式暂停时生效）。 |
| **⤼ 单步** | `POST /api/step {n:1}`，执行 1 条指令。 |
| **步进 [N] 执行 N** | 执行 N 条指令（1 ≤ N ≤ 1,000,000），适合快速跨过循环。 |
| **↻ 刷新** | 重新拉取状态、符号、反汇编、内存、设备、调用栈、trace、控制台。 |
| 连接灯 | 绿色常亮 = 已连接；灰色 = 未连接（同时显示黄色提示条与启动命令）。 |
| 状态 pill | `运行中`（绿）/ `暂停`（蓝）/ `卡死`（黄）/ `故障`（红），其它值显示为 `未知`。 |
| **PC** | 当前 PC 的“符号名+偏移 @ 地址”，例如 `main @ 0x0800CDB0`；没有符号时只显示地址。 |
| **指令数 / uptime** | 已执行指令数与模拟运行时间（毫秒），来自 `stats.insn_count` / `stats.uptime_ms`。 |
| 停止原因 | 运行/暂停后显示 `命中断点`、`达到指令上限`、`外设卡死`、`固件故障`、`用户暂停` 等；兼容后端返回的 `stop_reason` 与 `stop_reason_detail` 字段。 |

### 4.2 左栏

**寄存器**：R0–R12、SP(R13)、LR(R14)、PC(R15)、xPSR、PRIMASK。数值变化时会短暂闪烁；PC 行使用高亮色。

**NVIC 中断**：

- “使能”与“挂起”两组 chip，显示 `enabled` / `pending` 列表；
- 悬停 chip 可看中断名（如 `IRQ 5 · EXTI0_1`、`IRQ 22 · TIM17`）；
- SysTick 以 `-1` / `SysTick` 表示。

**断点**：显示所有断点的符号名与地址。**点击任意一行即删除该断点**（`POST /api/breakpoints {remove:[addr]}`）。

### 4.3 中栏

**反汇编视图**

- 表格列：断点标记、地址、字节、指令文本；
- 当前 PC 所在行高亮并显示 `◀ PC`；
- 函数符号地址会在指令前显示紫色符号名；
- **点击指令行**：设置 / 清除该地址断点；
- **跟随 PC**：勾选时，PC 变化（单步、暂停、复位、命中）会自动把视图移到 PC 附近；手动在地址框跳转会**自动取消跟随**，方便静态浏览；
- **地址跳转**：输入 `0x0800CDB0`（也接受 `800CDB0`、`0x800CDB0` 等）后回车或点跳转；
- **刷新**：按当前起始地址重新抓取。

**内存视图**

- 每行 16 字节，带地址列与 ASCII 列；一页 256 字节；
- **跳转**：输入地址（`0x20000000`）；**◀ / ▶** 翻页（±0x100）；**到 PC / 到 SP** 快速定位；
- **编辑写入**：点击任意字节单元格 → 出现输入框 → 输入两位十六进制（如 `AB`）→ **Enter** 提交写入（`POST /api/mem`），**Esc** 取消；
- PC 所在字节以蓝色描边标记；零字节显示为暗色；
- 写入后可刷新页面数据，或直接观察反汇编/寄存器变化。

### 4.4 右栏：虚拟整机

| 区域 | 用法 |
|---|---|
| **电池电压** | 滑条 2000–18000 mV（兼容单节 3.7 V 与整包 14.4 V 两种设备模型），步进 10 mV；修改后约 200 ms 防抖写入后端（同时发 `battery`（单位 V）与 `battery_mv`（单位 mV））。 |
| **电容电压** | 滑条 0–400 V，步进 1 V，写 `cap_voltage`（单位 V）。 |
| **温度** | 滑条 -20–80 °C，步进 0.5 °C，写 `temp`（单位 °C）。 |
| **按键** | POWER / TEST / MENU / SET / ▲ UP / ▼ DOWN。**按住 = 注入按下事件，松开 = 注入释放事件**（`POST /api/device/event {kind:"button", payload:{name, pressed}}`）。 |
| **RF 接收** | 十六进制输入，例如 `01 23 45 67`（也接受 `0x01,0x23...`、连续 `01234567`），点“发送”注入 `kind:"rf_rx"` 事件；下方显示 RX/TX 次数与最近一次数据。 |
| **GPIO 引脚** | 每个端口（A/B/C/D/F）一行 16 位（从左到右 P15…P0），头部显示 `MODER / ODR / IDR` 十六进制值。颜色图例：**输入**（灰蓝）、**输出**（绿）、**复用**（紫）、**模拟**（灰）；高电平引脚带亮点/高亮，GPIO 变化事件会闪烁提示。 |
| **ADC 通道** | 两列紧凑显示 8 个通道：通道号、名称、原始值（0–4095）、估算电压（mV）与条形图。默认通道映射见 §6.4。 |

### 4.5 底部

**Trace 日志**

- 事件行格式：`#序号 [类型徽标] PC(符号) 描述`；
- 过滤 chip：`调用`（call/ret）、`MMIO`（mmio_read/write）、`中断`（irq_enter/irq_exit/exception）、`GPIO`（gpio_change）、`未实现`（unimpl）、`故障`（fault）、`其他`（uart/note）；
- 过滤状态保存在浏览器 `localStorage`；
- **自动滚动**：默认开启；关闭后可自由回看历史；
- **清空视图**：只清浏览器端显示，后端仍保留历史，新事件会继续追加（若要彻底重置序号，请复位固件）；
- 最多渲染 1200 行；前端内部缓冲 2500 条事件。

**调用栈**：显示 `#帧号 地址 符号`；**点击帧**会关闭“跟随 PC”并跳到该地址反汇编；右上角按钮手动刷新（`GET /api/backtrace`）。

**固件控制台**：显示后端 `/api/console` 的固件侧日志文本（若后端能从 UART/GPIO 解出）；清空只清显示。

### 4.6 设置与帮助

- **⚙ 连接设置**：修改 API 地址、应用并重连、恢复同源。地址存储在本机浏览器。
- **? 帮助**：快捷键与操作提示。

## 6. 虚拟外设怎么用

### 6.1 电池 / 电容 / 温度

1. 拖动右侧对应滑条（或点击滑条某一位置）；
2. 停止拖动约 200 ms 后，前端发送 `POST /api/device`：
   ```json
   {"battery": 4.2, "battery_mv": 4200, "cap_voltage": 350, "temp": 40, "temp_c": 40}
   ```
   （电池同时携带 V 与 mV 两种字段名，温度同时携带 `temp` 与 `temp_c`，以兼容不同后端字段命名）
3. 后端设备模型更新后，`GET /api/device` 返回新值，ADC 读数随通道映射变化（mock 中 CH0 电池、CH1 电容、CH2 温度会立即变化）。

### 6.2 按键

- 按住按钮（鼠标/触屏均可）→ 发送 `pressed:true`；松开 → `pressed:false`；
- 键盘聚焦到按钮后，空格/回车也可按下/释放；
- 后端会把按键映射到对应 GPIO 输入（映射关系由后端设备模型定义），可在 GPIO 面板与 trace 中观察 `gpio_change`。

### 6.3 RF 接收注入

- 在“RF 接收（十六进制）”输入框填写字节，如 `01 23 45 67`；
- 点“发送”或回车：前端把十六进制解析成字节数组，发送
  ```json
  {"kind":"rf_rx","payload":{"bytes":[1,35,69,103],"hex":"01 23 45 67"}}
  ```
- 观察点：右侧 RX 次数/最近数据、固件控制台、GPIO/trace 中与 RF/解码相关的活动、反汇编断点处的状态变化。

### 6.4 GPIO / ADC 面板

- GPIO 面板显示后端设备模型中的 `moder / odr / idr`。真实后端的 `Device.state()` 传的是 `gpio_inputs` / `gpio_outputs`（没有方向位）；前端会在缺少方向信息时用 ODR 推断输出脚，因此个别“输入但 ODR 恰好为 1”的引脚可能显示为输出，属于展示近似，以固件实际写入的 MODER 为准。
- 若后端未提供 GPIO 数据，头部显示 `—`，引脚为“无数据”样式。
- ADC 面板显示 `adc.channels` 数组（或 `adc` 字典，如 `{"0": 765, "1": 2048, ...}`），字段兼容 `value` / `raw` / `mv` / `volts`；通道数多时面板内部可滚动。
- SIM-SPEC 默认通道映射：**CH0 = 电池电压，CH1 = 电容电压，CH2 = 温度**，其它通道默认 0x800；该映射可在后端设备配置中修改。面板本身不假设固定映射，按后端返回的名字显示。

## 7. 典型调试流程示例

1. **启动并确认连接**：启动后端 → 打开页面 → 顶部显示“模拟器已连接”、状态“暂停”。
2. **复位**：点“复位”，PC 回到 `Reset_Handler (0x080030D4)`。
3. **找主循环**：在反汇编地址框输入 `0x0800CDB0`（main）→ 跳转查看。
4. **设断点**：点击 `main` 附近某条指令行（行首出现红点，断点列表出现条目）。
5. **运行**：点“运行”或按 F5；命中后状态回到“暂停”，顶部显示“命中断点”，PC 高亮在断点行。
6. **检查现场**：左栏寄存器、底部调用栈、trace（过滤 MMIO/中断）观察关键外设访问。
7. **单步/步进 N**：F8 单步，或步进输入 100 后点“执行 N”跨过循环；取消/勾选“跟随 PC”控制视图行为。
8. **改内存**：内存视图跳到 `0x20000000`，点击某个字节改为 `01` 回车，再单步观察分支变化（例如主循环标志 `0x200001CF`）。
9. **注入外设**：拖动电池/电容/温度滑条、按住 TEST 按键、发送 RF 十六进制，观察 GPIO/ADC/trace/控制台变化。
10. **收尾**：点“暂停”或“复位”；需要重启后端时在终端 Ctrl+C。

## 8. 前端使用的 HTTP API（SIM-SPEC §6 摘要）

| 方法 / 路径 | 前端用途 |
|---|---|
| `GET /api/status` | 300 ms 轮询：状态、PC、寄存器、统计、断点、NVIC |
| `POST /api/reset` | 复位 |
| `POST /api/run` | 运行（`max_insns`） |
| `POST /api/pause` | 暂停 |
| `POST /api/step` | 单步 `{n}` |
| `GET/POST /api/breakpoints` | 断点增删/列表 |
| `GET /api/mem?addr=&len=` | 内存读取 |
| `POST /api/mem` | 内存写入 |
| `GET /api/disasm?addr=&n=` | 反汇编 |
| `GET /api/trace?since=&limit=` | 300 ms 轮询 trace |
| `GET /api/symbols` | 符号表（PC/反汇编/断点显示名字） |
| `GET/POST /api/device` | 虚拟整机状态与设置 |
| `POST /api/device/event` | 按键 / RF 注入 |
| `GET /api/backtrace` | 调用栈 |
| `GET /api/console` | 固件控制台 |
| `GET /api/mmio` | （可选）该地址最近 MMIO 访问 |

错误响应约定：非 2xx 返回 `{"error": "..."}`；前端会把错误显示为 toast（右下角）或连接提示条。后端不可达时显示“模拟器未连接”，并每 300 ms 自动重试。

## 9. 常见问题（FAQ）

**Q1：页面提示“模拟器未连接”，所有数据都是 — / 0。**
1) 确认后端已启动且端口正确：真实后端默认 8765，mock 默认 8766；
2) 确认浏览器地址与后端同源（例如 `http://127.0.0.1:8765`），不要用 `file://` 直接打开 HTML；
3) 若使用跨端口，检查 ⚙ 中 API 地址与后端 CORS；
4) 打开浏览器开发者工具 → Network，查看 `/api/status` 是否 200；Console 是否有跨域/网络错误。

**Q2：连接正常，但某些区域一直为空。**
说明对应端点未实现或返回字段形状不同：
- 反汇编/内存空 → 检查 `/api/disasm`、`/api/mem`（地址是否合法、是否超出后端映射范围）；
- 调用栈空 → 后端暂无法启发式还原栈；
- 控制台空 → 后端尚未从 UART/GPIO 解出日志；
- GPIO/ADC 显示“无数据/—” → 后端 `/api/device` 未提供对应字段。
前端对常见字段名做了兼容，但仍以 SIM-SPEC §6 为准；可用 Network 面板查看实际 JSON。

**Q3：点“运行”后很久没返回，页面还在动。**
运行请求会阻塞到停止条件（断点/指令上限/卡死/故障）或前端 120 秒超时。默认每次运行最多 200 万条指令，在真实后端上通常约 1 秒返回；如果想推进更远，连续多点几次“运行”即可（PC 会在各任务之间推进）。若后端响应慢，状态轮询可能变慢；可等待断点命中或点“暂停”，也可重新点“刷新”查看最新状态。超时后 toast 会提示，后端可能仍在运行，稍后刷新即可。

**Q4：断点设置了不命中。**
- 断点地址必须是**指令起始地址**（Thumb 指令 2/4 字节边界），请在反汇编行上点击而不是手动输入任意地址；
- 后端在运行时分片检查断点，跨过极长的直线代码可能延迟命中；
- 若刚改过内存/代码，确认后端未缓存旧反汇编。

**Q5：点击反汇编跳转后，下一秒视图又跳回 PC。**
“跟随 PC”在起作用：手动跳转会**自动取消**跟随。若仍希望跟随，重新勾选即可；浏览静态代码时建议保持取消。

**Q6：Trace 没有新事件 / 过滤后什么都没有。**
- 检查过滤 chip 是否全部关闭（chip 变暗表示隐藏）；
- 后端 trace 可能只在新事件产生时返回；复位后事件序号归零，前端会自动清空并重新收集；
- “清空视图”只清显示，不会让后端重新发历史；想重新拉取历史请刷新页面。

**Q7：滑条/按键/RF 发送没有效果。**
- 检查后端是否实现了 `/api/device`、`/api/device/event`；
- 后端设备模型可能未把对应量映射到固件读取的寄存器/引脚（例如某些通道未接入）；
- 关注 toast 错误与 Network 响应；mock 后端中这些都能看到即时反馈。

**Q8：快捷键 F5 没刷新页面，反而开始运行。**
这是刻意的：F5/F6/F7/F8 被调试器接管（运行/暂停/复位/单步）。刷新页面请用 `Ctrl+R` 或地址栏回车。

**Q9：页面在窄屏/笔记本上显示不全。**
布局按宽屏设计（约 ≥1500 px 最舒适）；窗口变窄时页面允许横向滚动，各面板内部可独立滚动。把浏览器最大化或调高窗口高度可获得最佳效果。

**Q10：中文显示乱码。**
前端文件为 UTF-8；后端 JSON 应为 UTF-8。若 PowerShell 终端显示乱码，可先执行 `chcp 65001`；浏览器页面本身不受影响。

**Q11：可以把页面开放到局域网/公网吗？**
不建议。后端默认只监听 `127.0.0.1`，且无鉴权；暴露到网络等于允许任何人控制模拟器/读取固件数据。若确实需要，请自行加反向代理与鉴权。

**Q12：mock 后端和真实后端有什么区别？**
mock 完全用假数据（假反汇编/假 trace/假设备状态），只保证“前端交互与 API 契约”一致；真实固件行为、时序、外设副作用及 stall 诊断只有真实后端才有。mock 的启动命令与端口见 §3.2。

**Q13：默认端口 8765 被占用怎么办？**
用 `--port` 换一个端口启动后端（例如 `..\..\tools\python\python.exe run_sim.py sim.server firmware\AD200pro_V1.60.bin --port 8899`），然后浏览器打开 `http://127.0.0.1:8899` 即可；页面默认同源访问 `/api`，不需要额外配置。若采用“页面在一个端口、API 在另一个端口”的方式，见 §3.4。

## 10. 已知限制

1. **外设模型为行为级近似**：不追求周期级精确；ADC 转换时间、FLASH 擦写、定时器节拍等可能被简化。
2. **bootloader 未包含**：镜像从 `0x08003000` 开始，`0x08000000–0x08002FFF`（12 KiB bootloader）不存在，因此 USB 升级流程不可模拟。
3. **外设覆盖范围**：当前设计覆盖 RCC / FLASH / GPIO / EXTI / SYSCFG / ADC / DMA / TIM / PWR / IWDG / RTC / SCS(SysTick/NVIC)；固件 APP 未使用 USART/SPI/I2C/USB，因此这些没有模型。
4. **卡死诊断**：后端对“等待外设”的忙等会做自动诊断与恢复（`stall_report.json`）；前端在状态为“卡死”时只负责展示，不自动修复。
5. **断点/单步**：基于指令边界与运行时检查，不是硬件调试器的精确断点；条件断点/数据断点未实现。
6. **Trace 环形缓冲**：后端会丢弃过旧事件；前端最多保留 2500 条、渲染 1200 行，长时间运行后早期事件会缺失。
7. **ADC 通道映射可配置**：默认 CH0=电池、CH1=电容、CH2=温度，其它 0x800；实际以后端设备配置为准，前端按返回的名字显示。
8. **虚拟按键/GPIO 映射**：按键到引脚的映射、RF 引脚时序由后端设备模型定义；前端只负责注入事件与展示，不假设具体引脚用途。
9. **轮询开销**：状态与 trace 各 300 ms 一次；暂停时反汇编/内存按需刷新（避免无意义请求）。后端响应慢时界面会相应变慢。
10. **Web UI 无鉴权**：仅建议在本机使用。
11. **mock 后端不是模拟器**：不能推进真实固件，只用于前端联调与演示。

## 12. 浏览器自测安全须知

> 2026-11-07 补充：用户可能正在使用 Edge 浏览器窗口。无头 Edge/CDP 自测**禁止**使用 `Get-Process msedge | Stop-Process`、`taskkill /IM msedge.exe` 或按安装路径批量结束浏览器进程——这类全局清理会把用户正在用的浏览器一起关掉（曾多次导致用户浏览器被关闭）。
>
> 正确做法：用唯一临时配置目录（`--user-data-dir="$env:TEMP\<唯一名>"`）和独立调试端口启动无头 Edge，用 `-PassThru` 记录 PID；测试结束只清理自己启动的进程树（`taskkill /PID <pid> /T /F`）。详见工作区根目录 `AGENTS.md`。
