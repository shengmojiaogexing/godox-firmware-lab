# AD100 Pro V1.2 重点函数精读（人工精修）

> 说明：Ghidra 因网络原因未能落地（见 `out/ghidra/WHY_NOT.md`），这里的"伪 C"是
> `ghidra/decompile.py` 用 capstone 反汇编逐条机械翻译的产物（寄存器级、带原始指令注释）。
> 本文在其基础上对 9 组关键函数做人工精读，给出**修正后的函数边界**与可信的语义解释。
> 所有地址、字面量、寄存器访问均可在 `out/disasm.txt` 中逐条核对。

全局事实：镜像基址 **0x08003000**（0x08000000–0x08002FFF 是未提供的 bootloader），
向量表在 0x08003000（48 项），Reset_Handler = **0x080030D4**，main = **0x0800CF74**，
初始 SP = 0x20000CD0。外设基址符合 STM32F0：RCC=0x40021000，GPIOB=0x48000400，
SYSCFG=0x40010000，EXTI=0x40010400。

---

## 1. 0x080030D4 Reset_Handler（向量[1]）

`out/decompiled/0x080030D4.c` 只有 2 条指令，但实际边界应到 0x080030DC（functions.json
把它和 0x080030D8 拆成了两个条目，见 ISSUES.md）：

```c
/* 0x080030D4: 0448  ldr r0, [pc, #0x10]   ; 字面量在 0x080030E8 = 0x0800B965 */
r0 = 0x0800B965;          /* SystemInit | Thumb 位 */
/* 0x080030D6: 8047  blx r0 */
SystemInit();             /* 0x0800B964 */
/* 0x080030D8: 0448  ldr r0, [pc, #0x10]   ; 字面量在 0x080030EC = 0x080030C1 */
r0 = 0x080030C1;          /* __start | Thumb 位 */
/* 0x080030DA: 0047  bx r0 */
__start();                /* 尾调用，不复返 */
```

结论：标准 CMSIS 启动流程 —— 先跑 `SystemInit`，再跳 `__start`（启动桩），
之后的 `0x080030DC–0x080030E4` 是 `b .` 死循环填充（5 条 `FE E7`）。

## 2. 0x080030C0 启动桩 __start（0x080030C0–0x080030D4）

functions.json 把它拆成了 3 个碎片条目（0x080030C0 / 0x080030C2 / 0x080030C8），
合并后真实逻辑：

```c
void __start(void) {
    /* 0x080030C0: 0348 ldr r0, [pc,#0xc] -> 字面量 0x080030D0 = 0x20000CD0 */
    sp = 0x20000CD0;              /* 重设栈顶（与向量表[0]一致） */
    /* 0x080030C4: 00f040fa bl 0x08003548 */
    __libc_init_array();          /* 0x08003548，跑 init 表 */
    /* 0x080030C8: 0048 ldr r0,[pc,#0] -> 字面量 0x080030CC = 0x0800CF75 */
    main();                       /* 0x0800CF74 | Thumb 位，尾调用 */
}
```

字面量池：0x080030CC = 0x0800CF75（main|1），0x080030D0 = 0x20000CD0（SP）。
注意 0x080030EC 那两个字节 `C1 30 00 08` 是 `0x080030C1` 字面量，被
Lead 的扫描误当成指令 `adds/lsrs`（ISSUES.md 有记录）。

## 3. 0x08003548 __libc_init_array

```c
r4 = 0x0800F3EC;              /* init 表起始（flash 数据区） */
r5 = 1;                       /* Thumb 位 */
r6 = 0x0800F40C;              /* init 表结束（0x0800F40C-0x0800F3EC = 0x20 = 2 项） */
goto L_0800355C;
L_08003550:
    r3 = *(uint32_t*)(r4 + 0xC);      /* 第 4 个字 = 入口地址 */
    ldm r4!, {r0, r1, r2};            /* 每项 16 字节：r0,r1,r2 + 入口 */
    r3 |= r5;                         /* 补 Thumb 位 */
    r4 -= 0xC;                        /* 回退，然后 */
    ((void(*)())r3)();                /* 逐项调用 */
    r4 += 0x10;                       /* 前进 16 字节到下一项 */
L_0800355C:
    if (r4 < r6) goto L_08003550;
    __start_call_main();              /* BL 0x080030C8 */
```

实质：一张 2 项的 **初始化函数表**（0x0800F3EC–0x0800F40C，每项 16 字节，
最后 4 字节是 Thumb 函数指针），逐项调用后回到 main。这解释了 flash 高地址
0x0800F3EC 附近是参数/函数指针区（见 FINDINGS.md）。

## 4. 0x0800B964 SystemInit

标准 STM32 时钟初始化序列（连续读改写 RCC 寄存器，全部可由 periph 注释核对）：

| 偏移 | 寄存器 | 操作 |
|---|---|---|
| RCC+0x00 | CR | 置位后清位（HSE/HSI 使能、CSS 位操作） |
| RCC+0x04 | CFGR | `& 0x08FFB80C` 清时钟源/预分频域，再 `& ~(0x3F<<16)` 清 PLL 相关位 |
| RCC+0x1C | CFGR2 | `(x>>4)<<4`，清 PREDIV 低 4 位 |
| RCC+0x30 | CFGR3 | `& 0xFFFCFE2C` 清 USART/I2C 时钟选择 |
| RCC+0x08 | CIR | 清中断标志 |
| RCC+0x34 | CR2 | 末尾操作（HSI48/时钟源使能） |

结论：这是 CMSIS 的 `SystemInit()` 本体，把时钟切到目标配置（HSE/PLL 参数见字面量
0x08FFB80C、0xFEF6FFFF 等掩码），与硬件手册 RCC 章节一一对应。它本身不调用其它函数。

## 5. 0x0800CF74 main

结构清晰，83 条指令、35 个直接调用，是整个固件的调度入口：

1. **BSS 清零**：`r2=0x08003000` 起、`r3=0x20000000`，循环 0x30 次按字拷贝
   （把 0x08003000–0x080030C0 的向量表/常量拷到 RAM 0x20000000），
2. `SYSCFG.CFGR1 |= 3`（配置 EXTI 线映射），
3. 依次调用 12 个初始化函数：`0x080075CC, 0x0800B8F0, 0x0800941C, 0x080093F4,
   0x0800967C, 0x08009310, 0x080095CC, 0x080095F8, 0x08009708, 0x08009768,
   0x080096A8, 0x080093A8`（时钟/GPIO/外设初始化组），
4. 使能 RCC.APB1ENR 位（字面量 0x0800D074 = 0x40021000，`r4<<0x10` 得到 0x100040000?
   实际是掩码常量），`msr primask, #1` 关中断后初始化 RAM 标志区，
5. `0x08007F10 / 0x08007544 / 0x080074F0 / 0x0800AD10 / 0x0800AD44 / 0x0800A934 /
   0x0800ABE4` 等模块初始化，
6. `RCC.CSR |= 1<<23`（LSEON / 时钟使能），清 RAM 0x2000021B 标志，
7. 进入 **主循环** `L_0800D010`：
   - `msr primask, #0` 开中断，
   - 轮询 RAM 0x200001E1 处的 u8 标志，`!= 1` 就自旋等待，
   - 清标志后依次调用 `0x08008D00(dispatcher_large), 0x080047CC, 0x080098F8,
     0x080035A8, 0x0800642C, 0x080038C0, 0x0800D098, 0x080065CC, 0x0800896C,
     0x0800B394, 0x0800A230, 0x08003BAC, 0x0800C7D4, 0x0800B7B0, 0x080097F8, 0x0800B80C`
   - `b L_0800D010` 无限循环。

结论：**中断驱动 + 主循环轮询 RAM 标志**的裸机架构；`0x08008D00` 是主循环里的核心
分发器。RAM 0x20000000–0x20000384 是全局状态区（BSS/标志/队列）。

## 6. GPIO 基础 API（0x0800741C / 0x08007426 / 0x08007434）

这三个是整机复用最多的小函数（被调用 27 / 128 / 54 次），是板级 GPIO 抽象层：

```c
/* 0x0800741C  GPIO_ReadPin(base, mask)：读 IDR(+0x10)，返回是否命中 */
uint32_t FUN_0800741C(uint32_t base, uint32_t mask) {
    return (*(uint32_t*)(base + 0x10) & mask) ? 1 : 0;   /* ldr [r0,#0x10]; ands; beq */
}

/* 0x08007426  GPIO_WriteMask(base, mask, mode)：mode!=0 用 BSRR(+0x18) 置位，否则 BRR(+0x28) 清位 */
void FUN_08007426(uint32_t base, uint32_t mask, uint32_t set) {
    if (set) *(uint32_t*)(base + 0x18) = mask;   /* GPIOx_BSRR：置位 */
    else     *(uint32_t*)(base + 0x28) = mask;   /* GPIOx_BRR ：清位 */
}

/* 0x08007434  get_global_word()：返回 *(uint32_t*)0x20000104 指向的字（全局状态/计数值） */
uint32_t FUN_08007434(void) { return **(uint32_t**)0x20000104; }
```

periph_map 把 0x08007426 的 `[r0,#0x18]/[r0,#0x28]` 标成 EXTI 是**误标**：
真实调用点传进来的 r0 都是 GPIO 基址（0x48000400 等），0x18 是 BSRR、0x28 是 BRR，
这是 STM32 标准的置位/清零写口。0x0800741C 的 +0x10 同理是 GPIO IDR。

## 7. 0x0800A480 LCD 串行写（bit-bang）

98 字节 / 45 条指令，被 16 处调用，`callees=0x08007426`（即上面的 GPIO 写位函数）。
逻辑是**软件模拟串行（bit-bang）发送一个字**：

```c
void FUN_0800A480(uint32_t value, uint32_t mode /* r1 */) {
    r4 = GPIOB_BASE;                 /* 0x48000400，MODER 字面量在 0x0800A4E4 */
    r5 = value;
    if (mode == 1) r2 = 1; else r2 = 0;
    /* 先做 GPIO 配置（MODER/BRR），把时钟/数据引脚设成输出 */
    FUN_08007426(r4, 0x80, 0);       /* 清某引脚 */
    FUN_08007426(r4, 1<<9, 0);
    ...
    L_0800A4AC:
    *(uint32_t*)(r4 + 0x28) = 0x40;  /* BRR：SCK/CLK 拉低 */
    r6 = r5 << 0x18;                 /* 取最高字节 */
    if (r6 >= 0) ...                 /* bpl：判断最高位（数据位） */
        *(uint32_t*)(r2 + 0x18) = r3;/* BSRR：按位设置数据线 */
    ...
    /* 循环移位 8 次，每位后翻转时钟，最后拉高片选/锁存 */
}
```

结合 0x0800A480 附近还有 0x0800A30C/0x0800A312/0x0800A31A 等一组小函数（都在
0x0800A2xx–0x0800A4E2 区间）和 0x0800D164 之后的字模表，可判定这一组是
**LCD 显屏的 GPIO 模拟串行驱动**（SCK/SDA/CS 三线），0x0800A480 是"写一个字节/字"。

## 8. 0x0800DA78 大函数（1190 字节）——其实大部分是数据表

functions.json 声明 insns=770，但 `out/gaps.txt` 显示 0x0800DA78–0x0800DF1E 之间
嵌了大量未认领数据（0x0800DB50、0x0800DBC0、0x0800DCC0 … 都是字模/字库形态）。
逐字节看：`14 5a 5a 5a 5a 5a 5a 50 46 46 3c 32 28 28 ac 03 …`，capstone 解码成
`ldrh/str/mov r8/adds/cmp/lsls` 的序列没有合理的控制流，`meta.json` 给的是 **25 条指令**，
且没有任何 `bl` 调用者被找到。

结论：0x0800DA78 是**被误判为函数的数据区**（很可能是 LCD 字模/字库与查找表混合），
不是真正的 ISR。其"块" 0x0800D726/0x0800DAAA/0x0800DB16/0x0800DCC2 也是从数据中
随机解释出来的跳转目标。真正的代码区在 0x0800D164 之前结束（见 ISSUES.md）。
**不要**把它当 RF 收发回调使用；RF 相关线索见 FINDINGS.md（0x0800A8xx–0x0800Bxxx 段）。

## 9. 0x08008D00 主循环分发器（358 条指令，19 个调用）

main 的直接被调用者，800 字节、79 个 basic block，是主循环状态机：

- 入口先 `0x0800B790`（读/初始化全局），取 RAM 0x20000164 处状态结构体
  `r5 = 0x20000164`，`r0 = *(u8*)(r5+0xA)` 计数并 `uxtb`，`> 4` 归零（0xA 是
  一个轮转计数器）；
- 用 `stm r2!, {...}` 在栈上拼参数块（0x08008D00–0x08008D4x 连续 4 次），
  分别以 8/0x10/0x20/0x40 等值调用 `0x080072C4`，像是在按位初始化/写一串
  GPIOB 通道（0x08009024 字面量 = GPIOB 基址）；
- 之后按 `r5+0xA` 的计数器（0..4）经 `cmp/bls` 分支到 5 个处理段
  （`L_08008E14` 等），分别处理按键/灯/显示/RF 状态更新；
- 调用表：`0x080038AC, 0x08004484, 0x0800451C, 0x08004B74, 0x080067EC, 0x080072C4,
  0x0800741C(GPIO_ReadPin), 0x08009198, …` 共 19 个，都是状态/IO 操作。

结论：**主循环内的周期任务调度器/状态机**，每轮根据 RAM 状态字分派到不同子系统，
与 main 的"清标志 -> dispatcher_large -> 各模块"结构吻合。
