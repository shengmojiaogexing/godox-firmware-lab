# AD100 Pro V1.2 固件逆向：子系统与线索（FINDINGS）

> 依据：`firmware/AD100pro_V1.2.bin`（50248 字节，基址 0x08003000）、
> `out/disasm.txt`、`out/periph_map.json`、`out/decompiled/*.c`、
> `out/functions.meta.json`。所有结论标注证据等级：**【实证】**= 指令/字面量可直接核对；
> **【推测】**= 基于调用关系/外设组合，需要硬件或更多分析确认。
> 注意：本固件内**没有可读 ASCII 字符串**（全图扫描 len≥6 且有意义的字符串为 0，
> 0x0800D000+ 的"字符串"全是字模数据），因此没有字符串线索；网上 AD200 等其它
> 型号固件的字符串不能套用到本机。

## 1. 启动链【实证】

```
向量表 0x08003000（48 项）
  [0] SP        = 0x20000CD0
  [1] Reset     = 0x080030D4  Reset_Handler
  [2] NMI       = 0x0800A030  bx lr（空桩）
  [3] HardFault = 0x08008734  b .（死循环）
  [11] SVC      = 0x0800B584  bx lr（空桩）
  [14] PendSV   = 0x0800A918  bx lr（空桩，实际函数在 0x0800A91C）
  [15] SysTick  = 0x0800B8E4  push {r4,lr}; bl 0x080075BC

0x080030D4 Reset_Handler:
    ldr r0,=SystemInit(0x0800B964); blx r0
    ldr r0,=__start(0x080030C0);    bx r0        ; 尾调用
0x080030C0 __start:
    ldr r0,=0x20000CD0; mov sp,r0
    bl __libc_init_array(0x08003548)
    ldr r0,=main(0x0800CF74); bx r0             ; 尾调用
0x08003548 __libc_init_array:
    遍历 0x0800F3EC..0x0800F40C（2 项 × 16 字节），逐项 OR 1(Thumb) 后调用
    bl 0x080030C8（尾调用 main 的桩）
```

## 2. 中断架构：只有 8 个有效 IRQ，主循环靠轮询【实证】

48 项向量表里 32 个 IRQ 全部非零，但其中 24 个指向同一个默认桩 `0x080030E6`
（2 字节 `b .`）。**真正有代码的 IRQ 只有 8 个**：

| IRQ | STM32F0 外设（推测） | 处理函数 | 说明 |
|---|---|---|---|
| IRQ2 | EXTI2_3 | 0x0800ACF8 | 16 字节：置 RAM 0x2000021A=1，bl 0x08007E34 → 按键/外部中断 |
| IRQ5 | EXTI4_15 之一 | 0x08005A78 | 未精读 |
| IRQ6 | TIM1_BRK_UP_TRG_COM 等 | 0x08005B00 | 未精读 |
| IRQ7 | TIM1_CC | 0x08005B0C | 未精读 |
| IRQ9 | TIM3 | 0x08004790 | 未精读 |
| IRQ13 | TIM14 / TIM16/TIM17 之一 | 0x0800BA7C | 未精读 |
| IRQ15 | USART1 / TIM16 | 0x0800BA8C | 未精读 |
| IRQ19 | I2C1 / SPI1 等 | 0x0800BA44 | 未精读 |

- main 的循环结构：`msr primask,#0` 开中断 → 轮询 RAM 0x200001E1 的 u8 标志
  （`!=1` 自旋）→ 清标志 → 调 16 个任务函数 → `b` 回循环。
- 即：**IRQ 只做最少工作（置 RAM 标志/搬数据），主循环轮询处理**，是典型的
  "中断 + 大循环"裸机架构。dispatcher `0x08008D00` 用 `r5+0xA` 计数器在 5 个
  处理段之间轮转，进一步支持"主循环状态机"的判断。

## 3. 外设使用画像（来自 out/periph_map.json 的 862 条命中）【实证统计】

| 外设 | 访问次数 | 解读 |
|---|---|---|
| RCC | 453 | 时钟/外设时钟使能是最大访问对象（SystemInit + 各模块 init） |
| EXTI | 110 | 外部中断配置（注：部分被误标，见 ISSUES #8） |
| GPIOB | 61 | 板级 IO 主用 GPIOB（LCD/按键/指示灯） |
| SYS / SCS | 53 | 系统控制（NVIC/SysTick/SCB） |
| DMA1 | 52 | DMA 通道（ADC/SPI 数据搬运） |
| FLASH_IF | 51 | 内部 Flash 接口 —— **参数读写/掉电保存** 的强线索 |
| ADC | 14 | 电压/电池/闪光能量采样 |
| SysTick | 13 | 系统节拍 |
| GPIOC | 12 | 第二组 IO |
| RTC | 12 | 实时时钟（可能有时间戳/定时） |
| NVIC | 9 | 中断使能/优先级 |
| PWR | 8 | 低功耗/电源控制 |
| TIM1 | 4 | 高级定时器（PWM/闪光触发） |
| TIM3/14/17 | 各 2 | 通用定时器 |
| SCB / SYSCFG | 2 / 2 | 向量表/EXTI 映射 |

结论【推测】：这是一块**带 ADC 采样、DMA、RTC、Flash 参数区、LCD 显示、DMA/定时器
驱动的闪光灯控制固件**；`FLASH_IF` 51 次访问说明有参数存储/校准数据读写模块。

## 4. GPIO 抽象层是全局最热函数【实证】

被调用次数：`0x08007426` **128 次**、`0x08007434` 54 次、`0x0800741C` 27 次。

```c
0x0800741C  GPIO_ReadPin(base, mask)    // (*(u32*)(base+0x10) & mask) ? 1 : 0   -> IDR
0x08007426  GPIO_WriteMask(base,mask,set)// set? *(u32*)(base+0x18)=mask : *(u32*)(base+0x28)=mask
                                          // BSRR 置位 / BRR 清零
0x08007434  get_global_word()           // return **(u32**)0x20000104  (全局计数/节拍)
```

periph_map 把它们误标为 EXTI（见 ISSUES #8），实际是 STM32 标准 GPIO 读写口。
128 次调用说明**几乎所有 IO 操作都走这条统一写口**。

## 5. LCD 显示子系统【实证 + 推测】

- `0x0800A480`（98 字节，16 处调用）是"软件模拟串行写"：操作 GPIOB 的 MODER/BRR/BSRR，
  对入参按位移位、逐位翻转时钟，是 **bit-bang SPI/三线串行**的典型形态；
  同区 0x0800A2xx–0x0800A4E2 还有一组同族小函数（0x0800A30C/0x0800A312/0x0800A31A…）。
- 0x0800D164–0x0800D724、0x0800DB50+ 是大片**点阵字模/字库**（`04 fe 92 92 fe…` 一类
  的 5×7 / 8×8 字模格式），与显示驱动配套。
- 结论：**段码/点阵 LCD 用 GPIO 模拟串行驱动**，0x0800A480 是写字节原语；字模在
  Flash 0x0800D164 之后。RF/显示大函数 0x0800DA78 其实是字模数据（见 ISSUES #2）。

## 6. Flash 参数/初始化表【实证】

- `0x0800F3EC`–`0x0800F40C`：`__libc_init_array` 使用的 **2 项初始化表**，每项 16 字节，
  末 4 字节是 Thumb 函数指针（OR 1 后调用）。这是唯一在代码里被结构化解引用的表。
- 镜像末尾 0x0800F448（0x08003000+0xC448）；0x0800F3EC 之后的 0x5C 字节是表 + 对齐数据。
- `FLASH_IF` 51 次访问 + 表结构 → 固件存在**参数/校准数据区与上电初始化表**；
  后续可重点分析 0x0800F3EC 前后的数据布局（可能含版本/校准/默认值）。
- 高地址 0x0800E000+ 还有大量非代码数据（点阵/表），文档里统称"数据区"。

## 7. RF / 无线相关（仅推测，证据较弱）

- 没有字符串、没有明显的 RF 寄存器（24/25 脚 SPI 形态）直接模式；periph_map 里也
  没有 SPI1/SPI2 的命中（0 次）→ 若存在 RF，更可能是 **GPIO 模拟单总线/SPI**。
- 强候选：`0x0800Bxxx` 段被 main 循环尾部调用（0x0800B394、0x0800B7B0、0x0800B80C），
  且 IRQ13/15/19 的处理函数也在 0x0800BA44/0x0800BA7C/0x0800BA8C —— 这一簇最像
  "无线/通信模块 + 其定时器/外部中断处理"。
- 另一候选：IRQ2（EXTI2_3）0x0800ACF8 → 置标志后 0x08007E34，可能是 RF 的 GDO/IRQ 引脚
  或按键。
- **需要后续**：追 0x0800B394 / 0x0800B7B0 / 0x0800B80C 的寄存器序列与延时循环，
  与常见 2.4G 芯片（nRF24L01/A7121 等）的 SPI 命令时序比对，才能定性。

## 8. 其它模块线索

- **计时/延时**：0x08007434 返回全局字 (RAM 0x20000104)，SysTick 处理 0x0800B8E4 →
  0x080075BC，说明系统有一个基于 SysTick 的 ms 节拍，延时/超时都用它。
- **电源/低功耗**：PWR 8 次访问 + main 里 `msr primask` 开关中断的临界区，
  参考 0x0800D098（main 循环内调用，紧邻数据区，疑似喂狗/休眠）。
- **初始化顺序**（main）：BSS 拷贝 → SYSCFG EXTI 映射 → 12 个外设 init →
  RCC APB1 使能 → 关中断初始化 RAM 标志 → 更多模块 init → RCC.CSR LSEON →
  主循环。可作为后续模块识别的骨架。
- **RAM 布局**：0x20000000 起全局变量区；0x20000104=节拍指针；0x20000164=dispatcher 状态结构；
  0x200001E1=主循环标志；0x2000021A=IRQ2 标志；0x20000274/0x20000384=缓冲/队列指针。

## 9. 对后续分析的建议

1. 先用 ISSUES #1–#3 的修正把函数表收敛到 ~400 个真实函数，再重新生成调用图。
2. 以 main 的初始化调用序列 + periph_map 的寄存器访问为索引，逐个模块命名
   （时钟/GPIO/LCD/ADC/DMA/Flash 参数/RF）。
3. 0x0800D164 之后按"数据"处理，不要反编译；可以用 LCD 字模规律解码出字符集。
4. 有硬件时优先验证：IRQ2（EXTI2_3）与 0x0800ACF8、0x0800Bxxx 段的 GPIO 时序、
   Flash 参数区（0x0800F3EC 附近）是否随设置改变。
