## 1. 离线验证：`verify()` 做了什么（73 项）

[`keypatch/devices/v860iiis.py`](../../../keypatch/devices/v860iiis.py) 的 `verify(patched, key)`
分四层、共 **73 项**（实测 **73 PASS / 0 FAIL**）：

| 层 | 项数 | 断言 | 说明 |
|---|---|---|---|
| 静态-函数 | 4 | 长度 79,300 B；同步字函数 56 B 与期望一致；结束于 `0x080115F0` 不越界；三个字面量（KEY/FLAG/50024）落位 | 原位补丁 + 边界 |
| 静态-补丁点 | 5 | 两个 gate（`0x08005A74`/`0x0800C5BE` = `00 bf`）；三个读者/保护点（`0x08003956`/`0x0800397E`/`0x0800D0A2`） | 6 处补丁点逐字节 |
| 静态-差异范围 | 2 | 与原厂差异集合 ==（6 处补丁点，共 58 B）；差异之外 0 处 | 证明没有改到别处 |
| Unicorn-同步字 | 19 | 说明行 1 + flag=2（LIGHT=ON）ID=0/5/99 → KEY（3）+ flag=0/1（12sec/OFF）ID=0/1/5/37/99 → 原厂公式（10）+ 原厂自证 ID=0/1/5/37/99（5） | Cortex-M0 直接执行补丁后机器码，桩替换 uidiv/WriteReg/strobe/delay |
| Unicorn-handler 级 | 43 | 说明行 1 + 值编辑 item0..8/10/11 的 dec/inc（22）+ 非回绕路径 item5/6/8（6）+ item9 LCD 不触发（2）+ 原厂 handler 自证 12 项（12） | 验证「除 item9 外任意项改值都立即重设同步字」，且原厂行为不变 |

复现命令：

```powershell
# 仓库根
$env:PYTHONIOENCODING='utf-8'
tools\python\python.exe keypatch\keypatch.py patch --device v860iiis --key 0xD798 --verify --out %TEMP%\kp_v860iiis
```

实测结果：**73 项全部 PASS**（0 FAIL）。产物（key=`0xD798`）：

|---|---|---|
| `V860IIIS_V1.1_keyD798.bin` | 79,300 B | `9ef11e8116e07dda30bd08ea407498f373ad3d953effb32258e3104c2ba5753d` |
| `V860IIIS_V1.1_keyD798_container.bin`（`--container`） | 79,361 B（payload 79,300 + footer 61） | `208f001d92d8ac543a8656905a7aac2da10a3454ccdfc12b03dcf4e56bc40b05` |

## 3. 离线验证覆盖不到的部分

1. **整机启动/主循环**：V860III-S 没有整机模拟器，启动链、外设、看门狗未回归；
2. **空口同步过滤**：Unicorn 只验证「写了正确的 SYNC1/SYNC0」，真正的射频同步必须真机；
3. **C.Fn 菜单/显示**：第 3 页第 1 行 **`LIGHT`**（固件不显示 F 编号；3 页 × 4 行、本机 10 项）
   是否存在、可选中/改值、掉电保存，未实机确认。UI 报告 `CFN_MENU.md` 用渲染函数真实执行 +
   帧缓冲重建确认右栏为 `12sec / OFF / ON`（对应 `0/1/2`），**显示极性与物理按键丝印需实机最终确认**；
4. **造型灯行为**：原厂 LIGHT 三档控制造型灯模式；补丁把两个功能读者固定为 0（12sec），
   需确认造型灯输出与预期一致；
5. **无线设置同步覆盖**：补丁已 NOP `0x0800D0A2`（RF 设置复位写 `settings[8]` 处）；
   静态写者只有 3 处（出厂默认/该复位点/load），但运行期动态复制路径需实测；
6. **持久化**：`settings[8]`（LIGHT 值 0/1/2）重启后是否保持（依赖原厂 72 B 记录 save/load；
   改值后约 200 tick 才落盘，期间掉电可能丢失本次改动）；
7. **启动完整性校验**：未穷举 bootloader 是否校验应用 CRC/签名；若校验，原位补丁无法启动；
8. **显示/UI**：本轮不改 UI/字库，只复用原厂 C.Fn 菜单项；显示控制器本身未逆向。

## 4. 实机测试清单（风险自负，按顺序做）

前置：官方 G3 能识别设备；手上有 `devices/v860iiis/firmware/V860IIIS_V1.1.bin`（sha256 一致）可回滚。

> 判定口径：补丁只看 **`settings[8]`**（C.Fn 第 3 页第 1 行 `LIGHT` 的值）。
> **`LIGHT = ON`（值 2）= 密钥模式**；`12sec`（值 0，出厂默认）/`OFF`（值 1）= 原厂普通模式。

- [ ] 刷 `V860IIIS_V1.1_key<KEY>.bin` 后能正常开机、菜单显示正常、版本号仍是 V1.1；
- [ ] 进 **C.Fn 菜单**确认第 3 页第 1 行 **`LIGHT`**（不显示 F 编号），可在 `12sec/OFF/ON` 三档间切换；
      新刷/恢复出厂后应为 `12sec`（值 0）；
- [ ] **普通模式**：`LIGHT = 12sec`（或 `OFF`），ID=1..99，与同 CH/ID 的原厂引闪器/灯能正常引闪；
- [ ] **密钥模式**：`LIGHT = ON` + 已打补丁的引闪器（同一把密钥）→ 能引闪；
- [ ] **隔离验证**：引闪器切回普通模式后，`LIGHT = ON` 的灯**不被引闪**；
- [ ] **即时生效**：不动其它设置，仅来回切 LIGHT `ON ↔ 12sec`，确认同步字立即切换（可用配对/未配对引闪器验证）；
- [ ] **造型灯（LIGHT 代价）**：确认造型灯输出保持原厂 `12sec` 档行为；C.Fn 里改 LIGHT 不再改造型灯模式；
- [ ] **持久化**：重启设备后 `LIGHT` 仍为 `ON`（密钥模式）；恢复出厂后回到 `12sec`（普通模式）；
- [ ] **无线设置同步覆盖检查**：用 G3/引闪器做一次「设置同步/远程设置」，确认 `settings[8]` 不被清回 0/1；
- [ ] **ID 行为回归**：改 ID 来回切几次，确认普通模式下每次同步字都跟着变（2 字节 NOP 不破坏原厂 ID 行为）；
- [ ] **菜单导航**：按键移动项、改其它 C.Fn 项，确认无卡顿/异常（NOP 后光标移动也会触发一次「只写同步字」的调用）；
- [ ] 任意异常 → 立刻刷回原厂（见 §5）。

### 4.1 异常排查提示

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| 密钥模式下偶发首包丢失 | 删掉的 `SCAL+1ms` 与 `delay(20µs)`（[`../README.md`](../README.md) §6.6） | 回退到保留原厂 strobe/延时序列的变体，或先用普通模式确认射频链路 |
| 密钥模式完全不响应 | 引闪器是否也打了同一把密钥 / `settings[8]` 是否真为 2 且已保存 | 先确认引闪器侧与开关值；再看持久化（重启后是否仍 ON） |
| LIGHT 值一开机又变回 0/1 | 恢复出厂 / 无线设置同步覆盖 `settings[8]` | 记录现象；本补丁已保护 `0x0800D0A2` 写点，需实测动态复制路径 |
| 造型灯不亮/行为异常 | 造型灯读者屏蔽（`0x08003956`/`0x0800397E`）副作用 | 对照原厂刷回确认，必要时回退该 2 字节（读者固定 0 = 12sec 档，不主动点亮） |
| 菜单导航变卡 | 光标移动触发同步字函数（方案 a 已知副作用） | 本补丁的同步字函数只做两次寄存器写、无 SCAL/延时，理论上可忽略；若明显异常需回退 |
| 普通模式异常 | 补丁点越界或固件版本不符 | 核对 sha256 / 各补丁点原始字节，重新生成（`apply()` 会先校验） |
| 刷坏后 G3 找不到设备 | — | 先正常开机 → 按一下侧拨轮 → 插 USB（救砖流程见 [`keypatch/README.md`](../../../keypatch/README.md)） |

## 5. 回滚

1. 直接刷回 **原厂** `devices/v860iiis/firmware/V860IIIS_V1.1.bin`（sha256 必须与登记一致）；
2. 或刷回上一版已确认可用的补丁产物；
3. 回滚后用 `keypatch.py list` / `keypatch.py info --device v860iiis` 复核固件身份；
4. 救砖/刷机细节见 [`keypatch/README.md`](../../../keypatch/README.md)（bootloader 在
   `0x08000000–0x08002FFF`，本补丁不碰它；只要 bootloader 完好、G3 能识别就能刷回）。
