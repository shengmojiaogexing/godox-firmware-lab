## 2. settings 基址、12 项边界、item 地址（结论 #1）

- **基址 `0x20001054`**：
  - 全镜像 `ldr` 字面量引用 **42 处**（`cfn_v1s.py:582` 的检查）；同 RAM 窗口内其它基址 `0x20001064`(x7)、`0x2000107E`(x10)、`0x2000108C`(x4)、`0x20001120`(x8) 都是**独立结构**（无线设置 / flash 驱动上下文），不是 settings 别名。
  - **dec handler `0x080059FC`**：`0x08005A3E` = `cb 48` `ldr r0,=0x20001054`；随后 `0x08005A5A` `43 5c` `ldrb r3,[r0,r1]`、`0x08005A62/86` `strb r3,[r0,r1]`（r1 来自 `[0x200004D0]` 当前项）。
  - **inc handler `0x0800C354`**：`0x0800C396` = `d5 48` `ldr r0,=0x20001054`；随后 `0x0800C3B4` `83 5c`、`0x0800C3BA/3C6` `strb [r0,r2]`。
- **12 项（0..0xB）边界**：4 处 `cmp #0xb`：
  - `0x08005C4C` `0b 29`（dec handler 内，项选择/回绕）
  - `0x0800C5B6` `0b 29`（inc handler 内）
  - `0x0800715E` `0b 2a`、`0x0800DEB0` `0b 28`（渲染/按键路径）
  - 配合 max 表 12 字节恰好 12 项。
- **item 地址**：item n = `0x20001054 + n`；**item6(ID)=`0x2000105A`**、**item8(LIGHT)=`0x2000105C`**（`cfn_v1s.py:582` 断言）。
- **当前选中项** `0x200004D0`（dec `0x08005A50`、inc `0x0800C3A8` 读取）；编辑态 `0x200004CE`（两个 handler 在 `0x08005A38 / 0x0800C390` 检查是否 ==1 才进入改值路径——所以 gate 只在**改值**时触发，项导航不会触发同步）。

## 4. item6(ID) / item8(LIGHT) 语义与全部读写点（结论 #3 前半）

### 4.1 item6(ID)：max 99、默认 0、"OFF" 显示、改值即同步

- **功能**：唯一功能读者是 dec/inc handler 的同步块（`0x08005A8E`、`0x0800C3EC` = `ldrb r0,[r0,#6]` + `bl 0x080112DC`），即 ID 变化立即重写 CC2500 同步字。
- **显示**：菜单渲染 `0x0800431C` 中 `0x0800489C` 画 "ID" 标签（字形 `0x12='I'`、`0x0D='D'`）；`0x080048C0 cmp r0,#6` 进入 ID 值渲染：ID==0 → `0x08004942` 画 **"OFF"**（字形 `0x18='O',0x0F='F',0x0F='F'`），否则 `0x080048CC` 除 10、`0x080048DE` 取余画两位十进制。
- **默认**：`0x08005ECA` `81 71 strb r1,[r0,#6]`（r1=0）→ **ID 出厂 0**。
- **持久化**：save `0x08005826`、load `0x08013974`（record+0x34 byte0）。
- **全部读者**：`0x080048C6`、`0x080048DE`（显示）、`0x08005826`（save）、`0x08005A8E`、`0x0800C3EC`（gate 同步块）、`0x08005E48`（频道扫描后重设同步）、`0x0800CEC0`/`0x0800CEEC`（按键工厂复位后的重同步）；
  **全部写者**：`0x08005ECA`=0（默认）、`0x0800CEB0`（按键复位）、`0x08013974`（load）。

### 4.2 item8(LIGHT)：max 2、默认 0、三态（12sec / OFF / ON）

- **max=2**（表 byte8），**默认 0**（`0x08005EC4` `01 72 strb r1,[r0,#8]`，r1=0）。
- **功能读者**：造型灯任务函数 **`0x08003950`**（fn 范围 `0x08003950..0x08003A48`）内只有两处 settings[8] 读取：
  - `0x08003956` `00 7a` `ldrb r0,[r0,#8]`，`0x0800395E cmp r0,#1` → **1 = OFF**（关 GPIO `0x48001000` bit13/14：`0x08003962/68/74` 调 `0x0800A80A`）；
  - `0x0800397E` `01 7a` `ldrb r1,[r0,#8]`，`0x08003982 cmp r1,#2` → **2 = ON**（开灯，`0x080039D8` 起）；**0 = 12sec** 定时模式（`0x080039A8` `0x4B<<5=2400` 写入定时器 `[0x20000474+0x14]`，到点关灯）。
  - 该函数没有其它 settings[8] 访问，因此 mask 这两处即完整屏蔽造型灯行为。
- **菜单显示**：`0x0800431C` 中 `0x08004A08 cmp r0,#8` 进入 LIGHT 专用分支；`0x08004A8E lsls r0,#1` + `0x08004A90 adds r0,#4` → 箭头行 = `2*value+4`；选项文字按字形索引绘制：`0x08004A0E/10/1C/2A/36/42` → "**12sec**"（字形 1,2,s,e,c，行4）、`0x08004A4C/58/66` → "**OFF**"（O,F,F，行6）、`0x08004A70/7C` → "**ON**"（O,N，行8）。
- **全部读者**：`0x08003956`、`0x0800397E`（功能）、`0x08004A8A`、`0x08004A9A`（显示）、`0x0800582E`（save）。
- **全部写者**：`0x08005EC4`（出厂默认 0）、`0x0800CEAA`（按键工厂复位 0）、`0x0801397C`（上电 load 展开，来自 record+0x34 byte2）。

### 4.3 mask 补丁（把 LIGHT 功能读者固定为 12sec 出厂默认）

| 地址 | 原厂字节 | 反汇编 | 替换字节 | 替换后 | 语义 |
|---|---|---|---|---|---|
| `0x08003956` | `00 7a` | `ldrb r0,[r0,#8]` | **`00 20`** | `movs r0,#0` | 第一处功能判定固定为 0 |
| `0x0800397E` | `01 7a` | `ldrb r1,[r0,#8]` | **`00 21`** | `movs r1,#0` | 第二处功能判定固定为 0 |

- 两处都在同一函数 `0x08003950`，替换后 r0/r1 均为 0，后续 `cmp #1/#2` 走 **0 = 12sec 定时**分支；`0x08003980` 紧接着会重载 r0，因此不破坏后续寄存器使用。
- **语义 = 原厂 `settings[8]==0`（12sec 出厂默认）**：造型灯行为完全等同于出厂状态；用户把 C.Fn LIGHT 设为 1/2 不再影响造型灯硬件。
- C.Fn 项本身仍可编辑、显示、持久化（settings[8] 保存值不变），Lead 的同步字补丁可继续读 `settings[8]` 作为私有密钥标志（建议：`settings[8]==2(ON)` → 密钥模式，0/1 → 普通模式；具体语义由 Lead 定）。

## 5. C.Fn 递减/递增 handler 与 item==6 gate（结论 #4，hook 替换点）

### 5.1 gate 现场

| 项 | dec 递减 | inc 递增 |
|---|---|---|
| handler 函数 | **`0x080059FC`**（`push {r3-r7,lr}` 起） | **`0x0800C354`** |
| gate 地址 | **`0x08005A8A`** | **`0x0800C3E8`** |
| 原厂 4 字节 | **`06 29 02 d1`** = `cmp r1,#6` ; `bne 0x08005A94`(pop) | **`06 29 f5 d1`** = `cmp r1,#6` ; `bne 0x0800C3D8`(pop) |
| 同步块（gate 之后） | `0x08005A8E` `80 79` `ldrb r0,[r0,#6]`；`0x08005A90` `0b f0 24 fc` `bl 0x080112DC`；`0x08005A94` pop | `0x0800C3EC` `80 79`；`0x0800C3EE` `04 f0 75 ff` `bl 0x080112DC`；`0x0800C3F2` pop |
| gate 处 **r0** | **= settings 基址 `0x20001054`**（唯一 def：`0x08005A3E ldr r0,=0x20001054`，CFG 反向数据流 resolved） | **= settings 基址 `0x20001054`**（唯一 def：`0x0800C396 ldr r0,=0x20001054`） |
| gate 处 **r1** | **= 当前项索引**：`0x08005A88 ldrb r1,[r2]`，r2 == `0x200004D0`（resolved） | **= 当前项索引**：`0x0800C3E6 ldrb r1,[r1]`，r1 来自 `0x0800C3A8 ldr r1,=0x200004D0`（resolved） |
| 进入条件 | 仅在**改值路径**（`[0x200004CE]==1`，`0x08005A38..4E`）到达；项导航不经过 gate | 同左（`0x0800C390..3A6`） |

> 反向数据流实现见 `cfn_v1s.py:784 check_gates()`；日志 §5 有逐条 def 打印（PASS）。

### 5.2 推荐补丁：4B 原地把 gate 改成「无条件跳进原厂同步块」（无需代码洞）

V1C 方案是「把 4B gate 换成 `bl hook` + 代码洞」。**V1S 没有干净代码洞（见 §10）**，但本固件 gate 的 fall-through 恰好就是原厂同步块，所以可以原地等价改写：

| 地址 | 原厂 4B | 补丁 4B | 反汇编 | 效果 |
|---|---|---|---|---|
| `0x08005A8A` | `06 29 02 d1` | **`00 e0 00 bf`** | `b 0x08005A8E` ; `nop` | 无条件进入原厂同步块（读 settings[6]=ID → `bl 0x080112DC`） |
| `0x0800C3E8` | `06 29 f5 d1` | **`00 e0 00 bf`** | `b 0x0800C3EC` ; `nop` | 同上 |

- 语义：**每次 C.Fn 改值（任意项，item9(LCD) 除外——item9 在原厂就绕过 gate）都会调用同步字函数**，且实参仍是 **ID**（settings[6]），所以同步字公式 `50024/(arg+1)` 的 ID 语义不变；Lead 只需在同步字函数体里读 `settings[8]` 决定 "KEY / 50024//(ID+1)"。
- 相较 V1C 的 `bl hook` 方案：**不重复调用、不改 r0/r1、不需要代码洞、补丁仅 4B/点**（脚本 `cfn_v1s.py:784` 已断言两处补丁字节可反汇编为 `b <同步块>` + `nop`，且同步块入口仍是 `ldrb r0,[r0,#6]`）。
- 如果 Lead 仍希望用 hook（放在代码洞/图像末尾），gate 的 4B 也可换成 `bl <hook>`；但注意 V1S 的 fall-through 是同步块，hook 返回后会**再执行一次原厂同步**（若 hook 内部也同步则双重 SPI 写），因此推荐上面的原地 `b` 方案。

### 5.3 同步字函数

- 函数入口 **`0x080112DC`**（`ldr r2,=50024`）；50024 字面量全镜像**唯一**，@ `0x08011310`；公式与 V1C 同构（`50024/(id+1)`，CC2500 SYNC1/SYNC0 写 4/5）。
- 同步字函数全部调用点（`cfn_v1s.py:866` 断言）：`0x08005A90`、`0x0800C3EE`（两个 gate 同步块）、`0x08005E4A`（频道扫描完成后重设）、`0x0800CEC2`/`0x0800CEEE`（按键工厂复位后重设）。

## 6. 持久化：save / load / 出厂默认（结论 #5）

### 6.1 记录格式（与 V1C 同构，参数不同）

| 项 | 值 | 证据 |
|---|---|---|
| 记录大小 | **0x48 B（0x12 words）** | 写/读/拷贝循环 `cmp #0x12`：`0x080091F8`、`0x08010B3C`、`0x08012CBC` |
| 有效标记 | **record[0] = 0x5C** | `0x080056F4 movs r2,#0x5c` 写记录首字；load 侧 `0x0800EC7E cmp r0,#0x5c` |
| 记录槽 | **`0x0801F000 + slot*0x64`，20 槽**（0..0x13） | `0x0800EC60 movs r0,#0x14`；`0x0800EC6E movs r1,#0x64` + `muls`；`0x08010B40/42` slot*0x64 + `0x0801F000` |
| 备份/校验页 | `0x0801F800`（擦除按 0x800B 页） | `0x0800EC38 ldr r0,=0x0801F800`；`0x080090D4` 擦除上下文 `{addr=0x0801F000, pages=1}` → `0x0800A454` |
| settings 在记录中的偏移 | s0,s1→rec+0x2C byte2/3；s2..s5→rec+0x30；**s6..s9→rec+0x34**；s10..s13→rec+0x38 | save：`0x08005810/24/38/4C` `str [r0,#0x2c/0x30/0x34/0x38]`；load：`0x08013950..94` |

### 6.2 save 链（改值 → 200 tick → 写 flash）

1. dec/inc handler 每次改值调用 **`0x08010754`**：`movs r0,#0xc8; strh [0x20000510]` → **200 tick 倒计时**（`0x08010756/58`）。
2. **`0x08010730`**：递减 `[0x20000510]`，归零时 `0x08010742` 置 `[0x20000512]=1`（save 请求）。
3. save 任务 **`0x0800D7EC`**：`[0x20000512]==1 && [0x20000554]==0` 时：
   - `0x0800D808 bl 0x080056F0`：**记录 builder**，把 settings[0..0xD] 打包进 `0x20000FD0` 处 0x48B 记录（settings 拷贝段 **`0x08005804..0x0800584C`**）；
   - `0x0800D80C bl 0x08012C9C`：与 shadow `0x20000F88` 比较（变了返回 1）；
   - `0x0800D814..D828`：槽号 = `[0x20000424]` 递增，到 0x14 则擦页并归 0；
   - `0x0800D82A bl 0x08010B20`：再 build 一次 → 拷贝 0x12 words 到 shadow → **`0x08010B44..48` 写 `0x0801F000 + slot*0x64`**（`0x080091CC` → 逐 word 调 `0x0800A508` 编程，最后 `0x0800A4F4` 上锁）。

### 6.3 load 链（上电）

- **`0x0800EC58`**：`slot=0x14` 递减，`addr = 0x0801F000 + slot*0x64` → `bl 0x08009164`（flash → shadow `0x20000F88`）→ 校验 `shadow[0]==0x5C`：
  - 有效：`0x0800EC94 bl 0x0801383C`（**展开**：rec+0x2C..0x38 → settings[0..0xD]）；
  - 无有效：`0x0800ECD6 bl 0x08005E68`（**出厂默认**）。
- 展开函数 **`0x0801383C`**：`0x0801383E ldr r1,=0x20000F88`；`0x08013950 ldr r2,=0x20001054`；写 settings 段 **`0x08013954..0x08013994`**，其中 **item8 写点 `0x0801397C` `13 72 strb r3,[r2,#8]`**（来自 rec+0x34 byte2）。

### 6.4 出厂默认函数 `0x08005E68`（逐项）

`0x08005EB8 ldr r0,=0x20001054` 后写 settings（`cfn_v1s.py:904` 断言）：

| settings | 默认 | 指令 |
|---|---|---|
| [0] | 0 | `0x08005EBA 01 70 strb r1,[r0]` |
| [1] | 1 | `0x08005EBC 42 70 strb r2,[r0,#1]` |
| [2] | 0 | `0x08005EBE 81 70` |
| [3] | 0 | `0x08005EC0 c1 70` |
| [4] | 0 | `0x08005EC8 01 71` |
| [5] | 0x14 | `0x08005ECE 43 71 strb r3,[r0,#5]` |
| [6] | **0** | `0x08005ECA 81 71` |
| [7] | 1 | `0x08005EC2 c2 71` |
| [8] | **0** | `0x08005EC4 01 72 strb r1,[r0,#8]` |
| [9] | 3 | `0x08005EC6 43 72` |
| [10]/[11] | 0（未写，BSS） | 默认函数不写；与 V1C item11 默认 1 不同 |

**⇒ LIGHT 开关随原厂 C.Fn 设置持久化**：改值后 200 tick 自动把 settings[8] 写进 flash 记录；上电 load 恢复；恢复出厂则 item8=0。用户无需新增保存代码。

## 7. 无线设置同步 / 覆盖路径（结论 #6）

- **item8 只有 3 个写者**（§4.2），其中没有无线同步/解包写点。
- V1C 的「紧凑结构解包」写回 settings[8]（`0x0800A6FA`）在 V1S **不存在**：
  - V1S 的 `0x0800A454/0x0800A508/0x080090D4/0x080091CC` 是 **STM32 FLASH 控制器（`0x40022000`）擦写例程**，其上下文结构 `0x20001120` 是 flash 驱动上下文，不是无线设置；
  - V1C 式「`settings-0x16` 紧凑结构重叠」在本固件无任何字面量引用（`0x2000103E` 无引用，`cfn_v1s.py:1096` 断言）；
  - 无线设置使用**独立 RAM**：`0x20001064`（=settings+0x10，x7 引用）与 `0x2000107E`（x10），与 settings[] 无重叠写入。
- 其它可能改写 item8 的路径：
  1. **合法性 clamp** `0x0800EE3C` `14 54 strb r4,[r2,r0]`（r4=0）：仅在 `settings[i] > max[i]` 时写 0（`0x0800EE38 cmp / 0x0800EE3A bls`），合法值 0/1/2 不受影响；
  2. **按键工厂复位组合** `0x0800CE9C..0x0800CEB4`（`0x0800CEAA 26 72` 写 settings[8]=0）：用户主动恢复默认，属预期行为。
- 结论：**打补丁后，用户通过 C.Fn 设置的 LIGHT 值不会被 RF 同步/远程路径覆盖**（V1C 的该类风险在 V1S 不存在，风险更低）。

## 8. 菜单 / UI 语义（LIGHT 复用所需）

- C.Fn 菜单渲染函数 **`0x0800431C`**（唯一调用点 `0x08011EC6`）：12 项 3 页 × 4 行，`page=idx>>2`、`slot=idx&3`；选中行整行反显（`0x08004D50` 辅助函数，被 `0x08004A9A` 用 settings[8] 调用）；菜单值区箭头 `0x08004A96 bl 0x08006838`。
- item8 显示 3 个选项：**12sec / OFF / ON**（字形解码见 §4.2），箭头行 = 2×settings[8]+4；item6 显示 "ID" + （0→OFF，否则两位十进制）。
- 用户找 LIGHT：C.Fn 第 3 页第 1 行 "LIGHT"；本机不显示 F1..F12 编号（与 V1C 相同，V1S 固件内无 ASCII 项名，字形索引与 V1C 同表约定，已用 "12sec/OFF/ON" 解码交叉验证）。
- **⇒ 复用 LIGHT 作为私有密钥开关，不需要任何 UI 改动**：用户可直接在 LIGHT 行看到 12sec/OFF/ON 并在三种状态间切换；Lead 用 `settings[8]` 的值决定是否进入密钥模式即可。

## 9. 代码洞（结论 #7）

全镜像扫描（`cfn_v1s.py:1148`）：连续 `0x00` ≥32B 只有 3 段，且**全部被引用**，不可用：

| 地址 | 长度 | 引用 | 结论 |
|---|---|---|---|
| `0x08014DFC..0x08014E20` | 36 B | 分支目标 `0x08014E10` | 不可用 |
| `0x08015336..0x0801536F` | 57 B | 镜像内 u32 绝对地址 `0x0801534A` | 不可用 |
| `0x08015F89..0x08015FF9` | 112 B | ldr 字面量 `0x08015F98`、`0x08015FA0` + u32 `0x08015FF8` | 不可用 |

- 10..31B 的无引用全零段存在（如 `0x08014892` 26B、`0x08014A60` 26B、`0x080148B4` 25B…），但经代码覆盖分析全部位于 **`0x08013D94..0x080155FF` 数据/字形常量区**（不在任何函数 CFG 内），注入会破坏显示字模/表格，**不建议使用**。
- **推荐**：直接使用 §5.2 的 **4B 原地 gate 补丁**（`00 e0 00 bf` ×2），**完全不需要代码洞**。
- 如果 Lead 的设计必须注入一段 hook，唯一相对安全的位置是**镜像末尾 `0x080162A4` 之后**（当前文件尾字节非 0；需验证更新容器是否允许追加、目标 flash 该区域是否空白/不会被擦除）。V1C 的 `0x08017944` 在本固件无对应。

## 10. 风险 / 未验证项

1. **无实机 / 无整机模拟器行为验证**（最高风险）：本报告为纯静态分析 + 数据流断言；未在 V1S 真机或 Unicorn 整机模拟器验证：
   - mask 后造型灯行为确为 12sec（建议用 Unicorn 桩化 GPIO 执行 `0x08003950`，比较 settings[8]=0 原厂 vs 补丁后）；
   - gate 补丁后每次 C.Fn 改值确实调用同步字函数（建议 Unicorn 执行 dec/inc handler，断言 `0x080112DC` 被调用、实参=ID）；
   - Lead 改造后的同步字函数（读 settings[8]）在 KEY/普通两种模式下的 SPI 时序可被 CC2500 接受。
2. **同步字公式的 ID 语义依赖**：推荐补丁保留实参=settings[6]（ID），由同步字函数内部读 settings[8] 决策；**不要把实参改成 settings[8]**，否则普通模式下同步字会错。
3. **mask 的代价**：用户失去原厂造型灯功能（C.Fn LIGHT 设为 ON/OFF 不再点灯），物理行为固定为 12sec；需在 README 说明"LIGHT 项已改作密钥开关"。
4. **LIGHT 持久化语义**：settings[8] 保存的是用户值（0/1/2），恢复出厂=0（普通模式）；但按键工厂复位路径 `0x0800CEAA` 会清 0 并重设同步，属预期。
5. **item10/11 语义未定性**：V1S 中除 save/load 外无功能/显示读者（与 V1C 不同）；若 Lead 需第二开关项可评估 item10/11（零 mask 成本），但需先确认 UI/协议语义。
6. **固件版本锁定**：本报告只对 V1S V1.8（sha256 `87a06000…`）有效；换版本必须重跑 `cfn_v1s.py` 并复核全部地址/字节断言。
7. **代码洞缺失**：若后续补丁必须注入超过 4B 的代码（例如同步字函数整段替换），需要 Lead 决定"镜像末尾追加"或"复用未引用函数"方案（本报告只给出候选，未验证容器）。
8. **未写 `keypatch/devices/v1s.py`**：本任务只交付证据，补丁实现由 Lead 完成；`devices/v1s/firmware/*.bin` 未改动（sha256 断言 PASS）。
