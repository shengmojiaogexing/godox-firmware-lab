## 1. 镜像身份与基址（独立推导，非循环论证）

### 1.1 身份

| 项 | 值 |
|---|---|
| 文件 | `devices/v1s/firmware/V1S_V1.8.bin` |
| 长度 | **78,500 字节**（镜像区间 `[0x08003000, 0x080162A4)`） |
| sha256 | `87a0600046e1b7c2198a7ac8fac15959bb3a5d582edf44d8e0df38706dcb917a` |

### 1.2 向量表

| 槽位 | 值 | 说明 |
|---|---|---|
| `vector[0]` | `0x20001540` | 初始 MSP，位于 SRAM 且 8 字节对齐 |
| `vector[1]` | `0x080030D5` | Reset_Handler（Thumb）；处理函数地址 `0x080030D4` |
| `vector[2]` | `0x0800E22D` | NMI |
| `vector[3]` | `0x0800BE65` | HardFault |
| `vector[4..7]` | `0x00000000` | 未使用 |

### 1.3 base 推导链（三处互相独立、非循环）

1. **Reset 桩模式全镜像唯一**：扫描 `ldr rX,[pc,#i]; blx rX; ldr rY,[pc,#j]; bx rY`
   （12 字节模式，字节级与位置无关），唯一命中**文件偏移 0xD4**：

   ```
   0x080030D4: 0448   ldr r0, [pc, #0x10]   ; [0x080030E8]=0x08011851 (SystemInit)
   0x080030D6: 8047   blx r0
   0x080030D8: 0448   ldr r0, [pc, #0x10]   ; [0x080030EC]=0x080030C1 (__main)
   0x080030DA: 0047   bx  r0
   ```

   由已知绝对向量 `vector[1] = 0x080030D5` ⇒ `base = 0x080030D4 − 0xD4 = **0x08003000**`。

2. **`__main` 桩模式全镜像唯一**：扫描 `ldr r0,[pc,#imm]; mov sp,r0; bl…; ldr r0,[pc,#0]; bx r0`
   且**第一条 ldr 的字面量 == vector[0]（MSP=0x20001540）**，唯一命中**文件偏移 0xC0**：

   ```
   文件 0xC0: 0348 8546 00f0 7cf9 0048 0047
   0x080030C0: 0348  ldr r0, [pc, #0xc]   ; [0x080030D0]=0x20001540 == vector[0]
   0x080030C2: 8546  mov sp, r0
   0x080030C4: 00f07cf9  bl 0x080033C0
   0x080030C8: 0048  ldr r0, [pc, #0]
   0x080030CA: 0047  bx  r0
   0x080030CC: 193a0108    .word 0x08013A19   （最终跳转目标）
   0x080030D0: 40150020    .word 0x20001540   （SP 初值 == MSP，自洽）
   ```

   该桩虚拟地址 = `0x080030C0`（由 Reset 桩字面量 `0x080030C1` 得到），
   文件偏移 = 0xC0 ⇒ `base = 0x080030C0 − 0xC0 = **0x08003000**`。

3. **字面量池交叉验证**：全镜像 `ldr` 字面量中 115 个为 Flash 指针（`0x08xxxxxx`），
   **无任何**指向 `0x08003000` 以下；110 个落在本镜像区间内（其余 5 个指向
   `0x0801F000/0x0801F800` 等镜像尾部之外的 Flash 绝对地址，属正常）。
   在该 base 下所有 BL 目标、字面量池、向量处理函数均解码为合理代码。

**结论：base = `0x08003000`，与已知 V1C / AD100 / AD200 的 app 基址一致（前 12 KB 为 bootloader）。**

## 2. 50024 = 0xC368 字面量唯一性

| 项 | 值 |
|---|---|
| 32 位小端字面量 `68 c3 00 00` 全镜像出现次数 | **1 次** |
| 文件偏移 / 虚拟地址 | `0xE310` / **`0x08011310`** |
| 引用它的指令 | **仅** `0x080112DC` 的 `ldr r2, [pc, #0x30]`（即同步字函数入口） |
| 值 | `0x0000C368 = 50024` |

补充：镜像中另有 2 字节子串 `68 c3`/`c3 68` 与 4 字节串 `…c3 68…` 出现在别处，
但均**不是**孤立的 32 位字面量，也不被任何 `ldr` 引用；Thumb-1（Cortex-M0）无 `movw`，
50024 不能以单条立即数指令出现。因此「ID → 50024/(ID+1)」公式只存在于这一个函数。

**原厂 56 字节（`apply()` 应逐字节校验，与本次独立读取完全一致）：**

### 3.2 逐指令反汇编（0x080112DC..0x0801130E，共 20 条）

SCAL; delay(1000);`。

### 3.3 边界证据（为何整段 56 B 可安全改写）

1. **入口前是上一函数尾部**：`0x080112D6` 为上一函数 `0x0801129C`（频率设置函数）的
   `pop {r4, pc}`；`0x080112D8` 的 4 字节字面量 `0x08015E88` 被该函数
   `0x080112A0/0x080112AA/0x080112B6` 三条 `ldr` 引用 ⇒ `0x080112DC` 是干净的函数起点。
2. **入口被 5 个 BL 直接调用**（§7），且**没有**任何函数指针字面量指向
   `0x080112DC/0x080112DD`（搜索 4 字节模式 0 命中）⇒ 只有直接调用路径。
3. **区内无内部入口/跳转目标**：全镜像所有分支/调用目标中，落在
   `[0x080112DC, 0x08011314)` 的**只有入口本身**（5 次 BL）。
4. **下一函数 0x08011314 是真实函数起点**：被 `0x0800CB8C` BL 调用（位于函数
   `0x0800CB88`，一个射频状态机/任务）；该函数体从 `ldr r0,[pc,#0x28]` 开始，正常代码。
5. `+0x34` 的 50024 字面量只被入口 `ldr` 引用 ⇒ 其 4 字节必须保留（补丁也保留）。

## 5. 全镜像运行期写 CC2500 reg4/reg5 的路径

### 5.1 WriteReg 调用点全量统计

全镜像 `bl 0x0801365A` 共 **60** 个调用点；**全部** r0（寄存器号）均可静态解析为常量
（唯一寄存器赋值形式 `mov r0,r1` 的调用点 `0x0800E71C` 也解析为常量 `0x18`）：

| 类别 | 数量 | 说明 |
|---|---|---|
| 初始化表函数 `0x080133FC` 内 | 47 | reg `0x00..0x2E` 连续写（含 reg4/reg5） |
| 同步字函数 `0x080112DC` 内 | 2 | reg4 @0x080112EE、reg5 @0x080112F6 |
| 其它单点 | 11 | reg `0x3E`（PATABLE 单写，0x08005E34）、reg `0x0D/0x0E/0x0F`（频率函数，3 处）、reg `0x06`（4 处）、`0x18`（3 处/含动态点） |

**写 reg4(SYNC1) 的调用点恰 2 个**：`0x080112EE`、`0x0801342A`；
**写 reg5(SYNC0) 的调用点恰 2 个**：`0x080112F6`、`0x08013432`。

### 5.2 初始化表函数 `0x080133FC`（CC2500 配置表）

- 函数范围 `0x080133FC..0x080135A5`（`pop {r3,r4,r5,pc}` @0x080135A4）；
  **全镜像只被 `0x08005DFA` 调用一次**（在 RF 初始化函数内）。
- 47 次 `WriteReg`，寄存器集合**恰为 `0x00..0x2E`**（CC2500 配置寄存器区），其中：
  - `0x08013426 movs r1,#0xC3; 0x08013428 movs r0,#4; 0x0801342A bl WriteReg` → **reg4 = 0xC3**
  - `0x0801342E movs r1,#0x68; 0x08013430 movs r0,#5; 0x08013432 bl WriteReg` → **reg5 = 0x68**
- 表尾 `0x08013588 strobe(0x33=SCAL) + delay(1000)`、`0x0801359A strobe(0x39=SFRX) + delay(1000)`。

> 注意：**原厂 ID=0 时同步字公式 50024//1 = 0xC368 ⇒ SYNC1/SYNC0 = 0xC3/0x68，与初始化表缺省值完全相同**。
> 因此若只看「ID=0」会误以为从未被覆盖；实际每次 RF 初始化都会在 init 表之后调用同步字函数重写一遍。

### 5.3 RF 初始化函数 `0x08005DE4` 与顺序

```
0x08005DE4  push {r4,r5,r6,lr}
0x08005DF6  bl 0x080135E4              ; CC2500 复位：SRES(0x30)+GPIO 时序+等待就绪
0x08005DFA  bl 0x080133FC              ; ① 初始化表：reg0..0x2E，含 reg4=0xC3、reg5=0x68
0x08005DFE  bl 0x080135BA(ReadReg)     ; 读 reg 0x0D（配置值 0x5C）-> RAM
0x08005E06  bl 0x080135BA              ; 读 reg 0x0E -> RAM
0x08005E10  bl 0x080133CC              ; delay(10000)
0x08005E1A  bhi 0x08005E22 / 0x08005E20 bne 0x08005DF6   ; 回环最多 10 次，直到读回 RAM 值==0x5C
0x08005E22  bl 0x0801371C              ; strobe(0x36)=SIDLE
0x08005E2A..0x08005E34                 ; WriteReg(0x3E, PATABLE 表值)
0x08005E38  bl 0x0801371C              ; ② strobe(0x33)=SCAL
0x08005E3E  movs r0,#0x7d; lsls #3; bl 0x080133CC  ; delay(1000)
0x08005E46  ldr r0,=0x20001054; ldrb r0,[r0,#6]    ; ID = settings[6]
0x08005E4A  bl 0x080112DC              ; ③ 同步字函数：用 50024/(ID+1) 覆盖 reg4/reg5
```

- `0x08005DFE..0x08005E4A` 之间**只有 2 条分支**（`bhi` @0x08005E1A、`bne` @0x08005E20），
  目标都不越过 `0x08005E4A` ⇒ **每次 RF 初始化必然先写 0xC3/0x68、再被同步字函数覆盖**。
- RF 初始化函数本身被 `0x08011930`、`0x080120F0` 调用（初始化路径）。
- 结论：**补丁不改初始化表也安全**；上电/重初始化后的最终 SYNC 值由补丁函数决定。

### 5.4 无第三处运行期写入（SPI 扇入拓扑证据）

| 函数 | 地址 | 全镜像调用点 |
|---|---|---|
| 单字节传输 `spi_xfer_byte` | 0x080136A4 | 恰 4 个：`0x080136FE`(读突发地址相)、`0x08013726`(strobe 命令)、`0x08013742`(写突发地址相)、`0x0801374E`(写突发数据相) |
| 写突发 `spi_write_burst` | 0x08013734 | 恰 3 个：`0x08013584`(地址 0x7E)、`0x08013654`(地址 0x7F)、`0x08013660`(WriteReg 内部) |
| 读突发 `spi_read_burst` | 0x080136F0 | 恰 3 个（地址 0xFF / `reg\|0x80` / `reg\|0xC0`，均为读路径） |

即：全镜像所有 CC2500 写操作只有两种形态——**通过 `WriteReg(reg,val)`（60 个调用点，r0 全为常量）
或通过写突发固定地址 0x7E/0x7F**；不存在其它 SPI 写路径，故 reg4/reg5 的运行期写点
**恰为 §5.1 的 4 个**，且都归属「初始化表 + 同步字函数」两类。

## 6. 同步字函数 5 个调用点与 ID 入参来源

| 调用点 | 所在函数（BL 目标判定） | 取 ID 指令 | ID 基址来源（反向切片） |
|---|---|---|---|
| `0x08005A90` | `0x080059FC` | `0x08005A8E ldrb r0,[r0,#6]` | `0x08005A3E ldr r0,[pc,#0x32c]` → 字面量 **0x20001054** |
| `0x08005E4A` | `0x08005DE4`（RF 初始化） | `0x08005E48 ldrb r0,[r0,#6]` | `0x08005E46 ldr r0,[pc,#0x1c]` → **0x20001054** |
| `0x0800C3EE` | `0x0800C354`（C.Fn 递增/设置处理） | `0x0800C3EC ldrb r0,[r0,#6]` | `0x0800C396 ldr r0,[pc,#0x354]` → **0x20001054** |
| `0x0800CEC2` | `0x0800CB88`（射频/协议状态处理） | `0x0800CEC0 ldrb r0,[r4,#6]` | `0x0800CE9C ldr r4,[pc,#0xc4]` → **0x20001054** |
| `0x0800CEEE` | `0x0800CB88`（同上） | `0x0800CEEC ldrb r0,[r0,#6]` | `0x0800CEEA ldr r0,[pc,#0x78]` → **0x20001054** |

- **设置区基址 `SETTINGS_BASE = 0x20001054`，ID 字节地址 `ID_ADDR = 0x2000105A`（= base+6）**；
  5 个调用点全部读同一地址。
- **门条件证据**：两处「只有改动项 == 6（ID 项）才重设同步字」——
  `0x08005A8A cmp r1,#6; bne`、`0x0800C3E8 cmp r1,#6; bne`，随后才是 `ldrb …, #6` + BL。
  这是 settings[+6] 就是 **ID 设置字节**的独立证据（与 V1C 的 C.Fn item 6 = ID 一致）。
- **无间接调用**：全镜像没有指向 `0x080112DC`（含 Thumb 位）或下一函数的 4 字节函数指针字面量；
  5 个直接 BL 即全部路径 ⇒ 整函数改写一处即可覆盖所有 ID 设置/恢复路径。

> 对实现的意义：补丁函数只把入参 r0 当 ID 使用，不需要知道 `0x20001054`；
> 但如果采用「FLAG 开关」方案，FLAG 字面量应指向该设置区内 CFN 分析确定的开关字节
> （`0x20001054 + item_index`），该地址由 **CFN 分析**任务确定，不在本报告预设。

## 7. 关掉 SCAL(0x33)+1ms 延时的理由与风险

### 7.1 理由（证据）

1. **SCAL 属于「改频率」路径**：`0x0801129C` 是频率设置函数——按索引表写
   reg `0x0D/0x0E/0x0F`（FREQ2/FREQ1/FREQ0），随后 `delay(20)` + `strobe(0x33=SCAL)` +
   `delay(1000)`；其调用点 5 个（`0x0800E724/0x0800E7FC/0x0800EAA0/0x0800EAC0/0x0800EB48`，
   信道切换路径）**保留不动**。
2. **上电路径已两次校准**：初始化表函数自身在写完全部配置寄存器后有
   `strobe(0x33=SCAL)+delay(1000)`（0x08013588..0x08013594）；RF 初始化函数在调用同步字函数
   之前又做了一次 `strobe(0x33=SCAL)+delay(1000)`（0x08005E38..0x08005E42）。
3. **SYNC1/SYNC0 是纯数据寄存器**：写它们不改变频率合成器/信道配置，不引入新的校准需求。
4. 同族已支持设备（V1C v5、AD100、AD200）均采用「只写 SYNC1/0，不 SCAL、不延时」的补丁形态。

### 7.2 风险（必须随补丁交付说明）

- 这是相对原厂**唯一**的射频行为差异。若某些批次 CC2500/兼容芯片在写 SYNC 后要求重新校准，
  极端情况下可能出现「上电首包丢失」。真机若出现首包异常，**优先怀疑此处**。
- 回退方案：保留原厂 `delay(20)`（但仍去 SCAL）需要 50 B 代码，放不进「KEY+FLAG+50024」
  三字面量布局的 44 B；若必须保留完整原厂序列，只能把函数搬到空闲 flash 注入区（本报告不涉及）。

## 8. 44 B 新函数体布局（KEY/FLAG/50024 三字面量）

### 8.1 布局（56 B 预算 = 44 B 代码 + 3×4 B 字面量）

| 偏移 | 内容 | 说明 |
|---|---|---|
| `+0x00..+0x2B` | **44 B 代码** | 19 条指令（3 条 BL） |
| `+0x2C` | `.word KEY` | 私有 16 位同步字（示例 0xD798） |
| `+0x30` | `.word FLAG` | C.Fn 密钥开关字节地址（**示例值，真实地址由 CFN 分析确定**） |
| `+0x34` | `.word 50024` | **必须与原厂同址同值**（普通模式公式仍用） |

新函数语义（与 V1C v5 同构，仅 BL 编码不同）：

```
push {r4,lr}
flag = *(uint8_t*)FLAG;
if (flag == 2) sync = KEY;              // 密钥模式
else           sync = 50024/(id+1);     // 原厂普通模式
WriteReg(4, sync>>8);                   // SYNC1
WriteReg(5, sync&0xFF);                 // SYNC0
return;                                 // 无 SCAL、无延时
```

### 8.2 独立构造的字节（本节为“布局可行性”验证样例）

`FLAG=0x20000F00`（示例）、`KEY=0xD798` 时：

```
地址        偏移   字节                                                      含义
0x080112DC  +00    10b50b4b0b4a1b78411c022b01d1074a01211046f1f7fefe0446
                   010a042002f0aef9e1b2052002f0aaf910bd                              44 B 代码
0x08011308  +2C    98d70000                                                          KEY = 0xD798
0x0801130C  +30    000f0020                                                          FLAG = 0x20000F00（示例）
0x08011310  +34    68c30000                                                          50024（原址原值）
```

整段 BLOB（56 B）：

```

```

逐指令：

| 偏移 | 字节 | 汇编 |
|---|---|---|
| +00 | `10b5` | `push {r4, lr}` |
| +02 | `0b4b` | `ldr r3,[pc,#0x2c]` → FLAG |
| +04 | `0b4a` | `ldr r2,[pc,#0x2c]` → 50024 |
| +06 | `1b78` | `ldrb r3,[r3]` |
| +08 | `411c` | `adds r1,r0,#1` |

| +10 | `0121` | `movs r1,#1` |
| +12 | `1046` | `mov r0,r2` |
| +14 | `f1f7fefe` | `bl 0x080030F0`（uidiv） |
| +18 | `0446` | `mov r4,r0` |
| +1A | `010a` | `lsrs r1,r0,#8` |
| +1C | `0420` | `movs r0,#4` |
| +1E | `02f0aef9` | `bl 0x0801365A`（WriteReg） |
| +22 | `e1b2` | `uxtb r1,r4` |
| +24 | `0520` | `movs r0,#5` |

| +2A | `10bd` | `pop {r4, pc}` |
| +2C | KEY | 4 B |
| +30 | FLAG | 4 B |
| +34 | `68c30000` | 50024（原址原值） |

静态性质（脚本断言）：长度 56、结束于 `0x08011314`、BL 目标 = `[uidiv, WriteReg, WriteReg]`、
不含 strobe/delay、`+0x34` 4 字节与原厂完全相同。

### 8.3 Unicorn 行为级自证

harness：ROM `0x08000000..0x08020000`、RAM `0x20000000..0x20004000`；
`WriteReg(0x0801365A)/strobe(0x0801371C)/delay(0x080133CC)` 入口替换为 `bx lr` 记录桩；
`__aeabi_uidiv(0x080030F0)` 真实执行；从 `SYNC_FN|1` 执行，r0=ID；返回哨兵 `b .`。

| 用例 | 结果 |
|---|---|
| 原厂镜像，ID=0..99（100 个） | 全部 `WriteReg(4,50024/(ID+1)>>8) → WriteReg(5,50024/(ID+1)&0xFF) → delay(20) → strobe(0x33) → delay(1000)` |
| 补丁镜像 KEY=0xD798 / 0xA5C3，FLAG==2 | 全部 `WriteReg(4,KEY>>8) → WriteReg(5,KEY&0xFF)`（无 SCAL/无延时） |
| 补丁镜像，FLAG∈{0,1} | 68 个用例全部 `50024/(ID+1)`，与原厂逐位相同（无 SCAL/无延时） |
| 补丁镜像长度/差异范围 | 长度 78,500 不变；与原厂差异 49 字节，全部落在 `0x0E2DC..0x0E313`（56 B 补丁区内） |

> 差异 49 字节而非 56，是因为新函数体有 7 个字节与原厂巧合相同；范围仍严格等于补丁区。

### 8.4 空间核算（重要实现约束）

- 三字面量布局只留 **44 B 代码**；若要保留 `delay(20)`（`movs r0,#0x14; bl delay` = +6 B）
  需要 **50 B > 44 B** ⇒ **「FLAG 开关」与「保留 delay(20)」不可兼得**。
- 备选形态（若不用 FLAG、改用「ID==0 → KEY」开关）：48 B 代码 + `KEY@+0x30` +
  `50024@+0x34` = 56 B 可行（V1C v4 形态），但失去 settings 里的 C.Fn 开关。

## 9. 与 Lead 初扫候选的逐项对照（含补充/差异）

| 初扫候选 | 本次结论 | 差异/补充 |
|---|---|---|
| 50024=0xC368 全镜像只 1 处 @文件 0xE310 / 0x08011310 | **正确** | 补充：唯一引用指令 = 入口 `0x080112DC`；无函数指针/立即数形式 |
| 同步字函数候选 0x080112DC..0x08011313（56 B，代码到 0x0801130E pop，+0x34=0x08011310 字面量），下一函数 0x08011314 | **正确** | 补充：下一函数真实起点的调用者 `0x0800CB8C`；入口为 4 字节对齐；入口前为上一频率函数尾部（0x080112D6 pop + 0x080112D8 字面量）；区内无其它跳转目标 |
| `__aeabi_uidiv=0x080030F0` | **正确** | 补充：自包含移位减法、无 BL；调用点 `0x080112E4` 入参/返回证据 |
| `CC2500_WriteReg=0x0801365A` | **正确** | 补充：`(r0=reg, r1=val)` 由初始化表 `0x08013426..0x08013432` 现场证明；内部调用写突发 0x08013734 |
| `delay_us=0x080133CC` | **正确** | 补充：`subs r0,#1; uxth` + nop 内层循环，`bx lr` @0x080133FA |
| `strobe=0x0801371C` | **正确** | 补充：只发命令字节 + CS 时序；`0x33`=SCAL、`0x36`=SIDLE、`0x39`=SFRX 等调用点 |
| （未给出）设置区基址 / ID 字节 | **补充：`0x20001054` / `0x2000105A`** | 5 个调用点 CFG 反向切片一致；2 处 `cmp r1,#6` 门条件 |
| （未给出）初始化表函数 / RF 初始化函数 | **补充：`0x080133FC` / `0x08005DE4`** | init 表 47 写、缺省 0xC3/0x68；顺序 init(0x08005DFA) → sync(0x08005E4A)，直线无旁路 |
| （未给出）频率设置函数 | **补充：`0x0801129C`** | 写 FREQ2/1/0 + SCAL + 1ms；是「SCAL 属于改频率」的直接证据 |
| （未给出）全量写寄存器调用点 / SPI 扇入 | **补充：60 个 WriteReg 调用点；SPI 扇入 0x080136A4/0x08013734/0x080136F0/0x08013760/0x08013780** | 排除旁路写，确认无第三处运行期 SYNC 写 |
| （未给出）44 B 布局可行性 | **补充：可行（见 §8）** | KEY@+0x2C、FLAG@+0x30、50024@+0x34；delay(20) 放不下 |

**未发现任何地址/边界/语义错误**，无需修正初扫结论；差异仅为「补充了初扫未覆盖的实现必需信息」。

补充：V1S 的同步字函数与 V1C 的同名函数是**同一套 C 源码原型**——56 字节中
除 6 条 BL 的立即数字段（16 字节）外，其余 40 字节**逐字节相同**（`push`/`ldrs`/`uxtb`/
`movs`/`pop`/50024 字面量等完全一致）；差异仅因两侧 `__aeabi_uidiv`/`WriteReg`/`delay`/
`strobe` 的链接地址不同。因此 V1C v5 的 `build_sync_function()` **函数体形态可以整体复用**，
只需按本报告 §3.2 的 BL 编码重新计算（或直接使用本报告 §8.2 的独立构造）。

## 10. 给 `keypatch/devices/v1s.py` 的常量与实现要点（证据已确认）

```python
BASE        = 0x08003000
IMAGE_SIZE  = 78500
SHA256      = "87a0600046e1b7c2198a7ac8fac15959bb3a5d582edf44d8e0df38706dcb917a"

SYNC_FN     = 0x080112DC      # void rf_set_sync(uint8_t id)
SYNC_FN_END = 0x08011314      # 下一函数起点（补丁必须止步于此）
SYNC_FN_SIZE = 56
ORIG_FUNC   = bytes.fromhex(
    "0c4a10b5411c1046f1f704ff0446010a042002f0b4f9e1b20520"
    "02f0b0f9142002f066f8332002f00bfa7d20c00002f05ff810bd68c30000")

ID_NUMERATOR = 50024          # 0xC368（补丁必须保留在 SYNC_FN+0x34）
DIV_FUNC     = 0x080030F0     # __aeabi_uidiv
WRITE_REG    = 0x0801365A     # WriteReg(reg=r0, val=r1)
WRITE_CMD    = 0x0801371C     # strobe(cmd=r0)（补丁版不再调用）
DELAY_US     = 0x080133CC     # delay_us(n=r0)（补丁版不调用）

SETTINGS_BASE = 0x20001054    # C.Fn 设置区基址（5 个调用点一致）
ID_IDX        = 6             # ID 设置项索引 -> ID 字节 = 0x2000105A
```

实现要点：

1. `apply()` 先校验 `len(data)==78500`、`sha256`、`data[0xE2DC:0xE314] == ORIG_FUNC`，
   不符即 `raise ValueError`（版本锁定）。
2. 整段改写 `0x080112DC..0x08011313`（56 B），保持长度不变；
   **`+0x34` 的 `68 c3 00 00` 必须原址原值保留**（普通模式公式）。
3. 采用 44 B 代码 + 三字面量布局：`KEY@+0x2C`、`FLAG@+0x30`、`50024@+0x34`。
   **FLAG 指向的开关字节由 CFN 分析确定**（本报告只证明 settings 基址 0x20001054 与
   三字面量布局可行，不预设开关项）。
4. `verify()` 可用本报告 §8.3 的 Unicorn harness：桩掉 `WRITE_REG/WRITE_CMD/DELAY_US`
   入口为 `bx lr`，保留 `DIV_FUNC` 真实执行，从 `SYNC_FN|1` 跑多个 ID × FLAG 值，
   断言 `WriteReg(4,…)`/`WriteReg(5,…)` 序列；原厂镜像同 harness 自证得到
   `50024/(ID+1)+delay(20)+strobe(0x33)+delay(1000)`。
5. 差异范围断言：补丁后与原厂差异字节必须全部落在 `0x0E2DC..0x0E313`（文件偏移）。

## 11. 风险与未验证事项

1. **无实机 / 无整机模拟（最高风险）**：本报告只有静态复核 + Unicorn 单函数调用级验证，
   没有整机启动、没有真实 CC2500 RF bring-up、没有任何真机刷写。发布前必须真机验证：
   上电首包、ID 菜单 0/1/5/37/99 切换、掉电重启后设置保持、与原厂设备混用的兼容性。
2. **FLAG（C.Fn 密钥开关）地址未在本报告确定**：由 CFN 分析任务给出；若开关项选择变化，
   补丁中的 FLAG 字面量需相应修改（44 B 代码本身不变）。
3. **去掉 SCAL(0x33)+1ms 的影响**：见 §7.2；只改同步字不改频率，且上电路径已有两次 SCAL；
   但这是唯一射频行为差异，真机首包异常优先回退此处。
4. **44 B 布局不含原厂 `delay(20)`**：原厂在写 SYNC 后有 20 计数建立时间；本方案省略。
   若真机对写 SYNC 后时序敏感（首包丢失），备选是 48 B「ID==0 开关」形态（无 FLAG）保留 delay，
   或函数搬移至空闲 flash 注入区。
5. **版本锁定**：本结论只对 `V1S_V1.8.bin`（sha256 `87a06000…`）有效；官方升级后需重新定位
   地址/字节/调用点。`apply()` 必须逐字节校验原厂 56 字节与 sha256。
6. **KEY 取值建议 > 50024**（如 0xD798/0xA5C3），否则可能与某个 `50024//(ID+1)` 普通值冲突，
   导致普通设备误触发或密钥设备被普通帧触发（同 V1C/AD100 的既有建议）。
7. **5 个调用点覆盖所有已定位路径**；静态扫描未发现其它写 SYNC 的路径（含函数指针/SPI 旁路），
   但未来固件若新增路径需重新复核。
8. **settings 基址 0x20001054 是静态数据流结论**（5 个调用点一致），补丁函数自身只接收 r0，
   不依赖该地址；但若实现「读 FLAG」方案，该地址的 RAM 有效性由链接脚本固定，未实机验证。

## 12. 结论

对 `V1S_V1.8.bin` 的独立静态 + Unicorn 复核表明：
