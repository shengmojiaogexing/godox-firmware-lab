# X3 Pro（C 版，V1.22）静态证据与复现

本文记录 **Godox X3 Pro（C 版引闪器，固件 V1.22）** 的「私有密钥」补丁所依赖的静态证据、
定位过程与可复现命令，供复核/换固件版本时重新定位用。结论已汇总进
[`../README.md`](../README.md)，这里只放**过程证据**。

> 前置：仓库根便携 Python（capstone 5.0.7 / unicorn 2.1.4）`tools\python\python.exe`；
> 固件 `devices/x3pro/firmware/X3pro_C_v1.22_app.bin`（1,941,020 B，sha256 `2e2b8a3b…`）。
> 补丁模块：`keypatch/devices/x3pro.py`。
>
> ⚠️ 本文件的数字以 **2026-11-11 本机当前模块（长按开关版）** 实测为准：注入区 **356 B**、
> 与原厂差异 **370 B**、`verify()` **41 项 PASS**、成品 sha256 `11f58c71…4ae6`。
> 换固件版本或改动模块后请重跑 §7 的复现命令重新核对。

---

## 1. 镜像与基址判定

| 项目 | 实测值 |
|---|---|
| 文件 | `devices/x3pro/firmware/X3pro_C_v1.22_app.bin` |
| 大小 | 1,941,020 B（0x1D9E1C） |
| SHA-256 | `2e2b8a3b5ff70e62c4acddc406b055ea2625e4833a213e81863f96c0da5a911b` |
| 文件偏移 0 | 初始 SP=`0x20270000`、Reset=`0x08031345` |
| **App 基址** | **`0x08020000`**（`file_offset = vaddr - 0x08020000`） |
| 镜像范围 | `0x08020000–0x081F9E1C` |
| BSS 区间 | `0x20000440–0x2001AF38`（Reset_Handler 的清 BSS 循环；RAM 容量未实测） |
| 尾部子镜像 | 最后 24,092 B（vaddr `0x081F4000` 起 = **文件偏移 `0x1D4000`**），与 `tools/hotshoe_blob.bin` 逐字节一致 |

**基址判定依据**：

1. 向量表 Reset = `0x08031345`；按 2 字节对齐取 `0x08031344`，减去基址 `0x08020000`
   得文件偏移 **`0x11344`**——该处正是标准 Reset_Handler：
   `设置 SP → 拷贝 .data → 清 .bss → SystemInit → main`。
2. 初始 SP=`0x20270000`（RAM 端），与 `0x0802xxxx`/`0x081xxxxx` 的代码/字面量地址一致地
   落在「`0x08000000` 映射 Flash + `0x20000000` 映射 SRAM」的 Cortex-M 地址空间。
3. 若误用 X3-C/X3-S 的基址 `0x08004800`，Reset 会算出 `0x2CB45`，落点不是函数起点，
   与反汇编不符——因此 X3 Pro 的基址确定是 `0x08020000`（前 128 KB 为厂商 bootloader，
   不在 `.bin` 内）。

> ⚠️ **不要混淆文件偏移与虚拟地址**：热靴子镜像的**文件偏移**是 `0x1D4000`，对应
> **vaddr `0x081F4000`**（不是 `0x081D4000`；`0x081D4000` 仍在全 `0xFF` 的注入安全区内）。

## 2. 同步字函数定位：`0x0802F040`

### 2.1 定位方法

1. 在镜像里搜 4 字节小端字面量 `68 c3 00 00`（= 50024 = `0xC368`）；
2. 找到引用它的函数体，特征序列：`movw r4,#0xC368` → `add r3,r2`（除数 = ID+1）→
   `udiv r4,r4,r3` → 两次写 CC2500 `reg4/reg5` → `delay(20)` → `SCAL(0x33)` →
   `delay(1000)` → `SIDLE(0x36)` → `delay(700)`；
3. 确认函数边界：下一函数起点 `0x0802F09C`，本函数体 **`0x5A`（90）字节**
   （`0x0802F040–0x0802F099`，末尾 `0x0802F09A` 是 2 B 对齐 `NOP`）。

X3 Pro 的结果：函数入口 **`0x0802F040`**，10 字节公式段在 **`0x0802F046–0x0802F04F`**。

### 2.2 原厂反汇编（摘要）

```asm
0x0802F040  01 22            movs  r2, #1
0x0802F042  03 46            mov   r3, r0              ; r3 = ID
0x0802F044  10 b5            push  {r4, lr}
0x0802F046  4c f2 68 34      movw  r4, #0xC368        ; 50024
0x0802F04A  13 44            add   r3, r2            ; r3 = ID + 1
0x0802F04C  b4 fb f3 f4      udiv  r4, r4, r3        ; sync = 50024/(ID+1)
0x0802F050  82 b0            sub   sp, #8
0x0802F052  23 0a            lsrs  r3, r4, #8        ; SYNC1
0x0802F058  04 20            movs  r0, #4
0x0802F05E  ff f7 5d fb      bl    0x0802E71C        ; WriteReg(4, SYNC1)
0x0802F068  05 20            movs  r0, #5
0x0802F06E  ff f7 55 fb      bl    0x0802E71C        ; WriteReg(5, SYNC0)
0x0802F072  14 20            movs  r0, #0x14           ; delay(20)
0x0802F078  33 20            movs  r0, #0x33           ; SCAL
0x0802F07E  4f f4 7a 70      mov.w r0, #0x3E8         ; delay(1000)
0x0802F086  36 20            movs  r0, #0x36           ; SIDLE
0x0802F08C  4f f4 2f 70      mov.w r0, #0x2BC         ; delay(700)
0x0802F096  fc f7 a1 ba      b.w   0x0802B5DC        ; 尾调用 delay_us(700)
0x0802F09A  00 bf            nop                      ; 对齐
0x0802F09C  ...                                       ; 下一函数
```

补丁模块把 `0x0802F046–0x0802F04F`（原厂 `movw/add/udiv` 共 10 B）改成
`B.W <inj_sync>` + 3×`NOP`：

```text
原厂 0x0802F046  4c f2 68 34 13 44 b4 fb f3 f4
补丁 0x0802F046  90 f1 db bf 00 bf 00 bf 00 bf   ; B.W inj_sync + 3×NOP（key=0xD798 时）
```

`inj_sync` 读 `KEY_ON`（RAM `0x20001096`）：**=1 → `r4 = KEY`；=0 → 逐字节重放原厂公式
（`movs r2,#1; mov r3,r0; movw r4,#0xC368; add r3,r2; udiv r4,r4,r3`）**，再跳回 `0x0802F050`
继续原厂的 SYNC1/SYNC0 写入 + SCAL/延时序列。因此所有调用路径（同步直发、中断队列）都按
`KEY_ON` 分流。

### 2.3 函数边界与调用点

- 函数体止于 `0x0802F099`，**不能**写到 `0x0802F09C`（下一函数是另一个函数）。
- 全镜像 `BL → 0x0802F040` 的调用点共 **6 处**：

  | 调用点 | 调用前 ID 来源（静态可见） |
  |---|---|
  | `0x0802F134` | `ldrb r0,[r6,#1]`（r6 = 设置区 `0x20001768`） |
  | `0x0802F144` | `mov r0, r5`（寄存器传入，上游路径未逐一回溯） |
  | `0x0802F234` | `ldrb r0,[r4,#1]`（r4 = 设置区 `0x20001768`） |
  | `0x0802F720` | `mov r0, r6`（寄存器传入，上游路径未逐一回溯） |
  | `0x0802F740` | `mov r0, r6`（同上） |
  | `0x0802F902` | `ldrb r0,[r4,#1]`（r4 = 设置区 `0x20001768`） |

6 个入口共享同一个函数，所以 10 字节改写一处即可覆盖全部「设置同步字」路径。

## 3. 全镜像写 CC2500 reg4/5 的唯一性

**扫描口径**：按 2 字节步长扫全镜像，找 `movs r0,#4` / `movs r0,#5`（`MOVS Rd,#imm8`，
Rd=0）后 8 字节内紧跟 `BL 0x0802E71C`（`write_reg`）的位置。结果全镜像只有 **4 个立即数写点**：

| 立即数点 | 写入 | 场景 |
|---|---|---|
| `0x0802E94C` | reg4（SYNC1）= `0xC3` | CC2500 **初始化表**（`0x0802E942` 处 `movs r2,#0xC3`；`0x0802E954` 处 `movs r2,#0x68` → reg5） |
| `0x0802E95E` | reg5（SYNC0）= `0x68` | 同上 |
| `0x0802F058` | reg4（SYNC1）= sync>>8 | **同步字函数** `0x0802F040`（运行期唯一写入） |
| `0x0802F068` | reg5（SYNC0）= sync&0xFF | 同上 |

初始化表写的是原厂 ID=0 的缺省同步字 `0xC3/0x68`；RF 初始化流程随后会调用同步字函数按当前 ID
覆盖它。补丁只改同步字函数，**不需要**动初始化表。

## 4. 设置结构 `0x20001768`（ID 菜单为原厂含义）

| 项 | 结论 | 证据 |
|---|---|---|
| 设置区基址 | `0x20001768` | 全镜像 **24 处** 4 字节字面量引用（`0x0802F168`/`0x0802F268`/`0x0802F77C`/`0x0802F938` 等） |
| `[+0]` | 频道 | 同步字函数调用点前常见 `ldrb r0,[r4]` → `set_channel(0x0802EFC8)` |
| `[+1]` | **ID**（`0x20001769`） | 调用同步字函数前 `ldrb r0,[r4,#1]`（`0x0802F230` / `0x0802F900`） |
| ID 菜单范围 | **0..99（原厂含义；本补丁不再占用 99）** | 修改处理块 `0x08029996` 起：`0x080299A0` 为 +10 路径、`0x080299AE` 为 +1 路径，两者最后都汇到 `0x080299A4 cmp r3,#0x63` / `0x080299A8 movhi r3,#0x63`（0x63=99） |

> 说明：上一版补丁曾把「ID=99」当密钥开关；**现行长按版已取消该语义**，ID 菜单完全恢复原厂
> （0..99 都只是普通引闪 ID）。这里的钳位证据只用于说明 ID 菜单的真实范围。

`0x08029996` 起这段的关键字节（本机核对）：

```text
0x08029996  07 4b 07 4a 19 78 53 78 31 b1     ; ldr r3,=flag; ldr r2,=settings; 读 flag、ID
0x080299A0  0a 33 db b2 63 2b 88 bf 63 23     ; +10 → uxtb → cmp #99 → it hi / movhi #99
0x080299AA  53 70 10 bd                       ; strb r3,[r2,#1]（写回 ID）
0x080299AE  01 33 db b2 ...                  ; +1 路径（同样汇入上面的钳位）
```

## 5. 长按开关的证据：`0x08027E44` / PA6 / `0x0802830A` & `0x080284F2` / KEY_ON

### 5.1 按键扫描入口与 PA6

| 项 | 结论 | 证据 |
|---|---|---|
| 按键扫描函数 | **`0x08027E44`**（`push.w {r3..r11,lr}`） | 入口 4 B 原厂 `2d e9 f8 4f`，下一指令 `0x08027E48` |
| 调用点 | main 主循环 **`0x0802B282`** 每轮 `bl 0x08027E44`（全镜像唯一调用点） | 扫描 `BL → 0x08027E44` |
| PA6 | `GPIOA = 0x42020000`，mask **`0x40`**，`read_gpio` 返回 0 = 按下 | 扫描函数 `0x08027E5C movs r1,#0x40` → `0x08027E60 bl 0x08032A58` |
| 备选键位 | PB4 mask `0x10` / PB5 mask `0x20` / 热靴 GPIOC15 `0x8000` 也在同一扫描函数里读取 | `0x08027E66` / `0x08027E7A` / `0x08027E88` |

### 5.2 原厂 PA6 长按动作（被补丁禁用/复用）

| 项 | 结论 | 证据 |
|---|---|---|
| 原厂长按阈值 A | `0x0802830A` **`21 2b`** = `cmp r3,#0x21`（33 次扫描≈1.5 s） | 超过阈值后不再 `bls 0x08027FEE`，继续往下执行 |
| 长按动作 A 入口 | `0x08028310` 起置长按标志/状态 → **`0x0802852E bl 0x0802B7D0`**（电源/关机流程） | `0x0802B7D0` 的调用点之一为 `0x0802852E`，正在 PA6 长按路径上 |
| 原厂长按阈值 B | `0x080284F2` **`21 2b`** = `cmp r3,#0x21`（状态机另一分支，同一 33 次阈值） | 超过阈值后不再 `bls 0x0802814A`，继续执行 `0x080284FA–0x08028508` |
| 长按动作 B 入口 | `0x080284FA`：`r0=0xB4` 写 `0x20000087`、`r1=0x16` 写 `0x20001089`（置 countdown 状态 `0x16`） | 某些状态（如 `[0x20000087]==0x14` 且 `[0x20001089]!=0`）下长按仍会走到这里 |
| 补丁改写 | **两处** `cmp r3,#0x21` → **`cmp r3,#0xFF`**（`21 2b` → `ff 2b`，各改 1 字节） | 阈值 `0xFF` 永不成立 → 原厂 PA6 长按的动作 A/B 都不再触发 |
| 电源键 | GPIOB0（另一颗键）长按关机不受影响 | 该路径不经过这两处 compare |

### 5.3 开关状态 RAM（KEY_ON / 计数 / latch）

| 地址 | 宽度 | 含义 |
|---|---|---|
| `0x20001096` | u8 | `KEY_ON`：0=普通模式，1=密钥模式（**RAM 版**，上电复位为 0） |
| `0x20001098` | u16 | 长按扫描计数（按下每轮 +1，松开清零） |
| `0x2000109A` | u8 | latch：本次按住已触发过（防重复翻转） |

- 本机静态扫描：全镜像 4 字节字面量对 `0x20001096/98/9A` 的引用均为 **0 处**（静态空白 RAM 区）；
- 注入代码逻辑：`read_gpio(GPIOA,0x40)` → 未按下则计数/latch 清零；按下且未 latch 则计数 +1，
  到 **34（0x22）** 时 `KEY_ON ^= 1` 并置 latch；随后走 `tramp_btn` 重建原 `push.w` 并跳回
  `0x08027E48`，原厂短按/双击/其它键逻辑不变；
- `verify()` 用 Unicorn 对按键逻辑有 **5 个用例**：松开复位、按下 #1、按下 #34 翻转、第 35 次
  latch 不重复、再次长按 #34 切回。

### 5.4 补丁点（6 个区域 / 7 个改动位置）与本机核对

| 地址 | 长度 | 原厂 | 补丁后（key=0xD798） | 说明 |
|---|---|---|---|---|
| `0x08027E44` | 4 B | `2d e9 f8 4f` | `98 f1 14 b9` | 按键扫描入口 → `B.W inj_btn` |
| `0x0802830A` | 2 B | `21 2b` | `ff 2b` | 禁用原厂长按动作 A（实际差异 1 B） |
| `0x080284F2` | 2 B | `21 2b` | `ff 2b` | 禁用原厂长按动作 B（状态机另一分支，实际差异 1 B） |
| `0x0802EDC4` | 4 B | `10 b5 ff f7` | `91 f1 30 b9` | 4B 帧发送入口 → `B.W inj_tx4` |
| `0x0802EE2C` | 4 B | `10 b5 ff f7` | `91 f1 0e b9` | 2B 短命令入口 → `B.W inj_tx2` |
| `0x0802F046` | 10 B | `4c f2 68 34 13 44 b4 fb f3 f4` | `90 f1 db bf 00 bf 00 bf 00 bf` | 同步字函数分流 |
| `0x081C0000` | 356 B | 全 `0xFF` | 注入代码（长按/双发/同步字辅助 + 蹦床） | 预留 2,048 B，其余 1,692 B 保持 `0xFF` |

与原厂总差异 **370 B** = 4 + 1 + 1 + 4 + 4 + 10 + 346（注入 356 B 中 10 个字节恰为 `0xFF`，不计差异）。
注入区布局见 [`../README.md`](../README.md) §4.4。

## 6. 空闲区扫描与注入区 `0x081C0000`

| 检查项 | 结果 |
|---|---|
| 大段空闲区 | `0x081B0A30–0x081F4000` 连续 `0xFF`，共 **275,920 B** |
| 选定注入窗口 | `0x081C0000–0x081C0800`（2,048 B）**全 `0xFF`**，位于上述空闲区中部 |
| 4 字节绝对地址引用（含 `|1` thumb 变体）指向该 2 KB 窗口 | **0 处** |
| `B.W`/`BL` 分支目标落入该 2 KB 窗口 | **0 处** |
| 注入实际占用 | **356 B**（`0x081C0000–0x081C0163`），其余 1,692 B 保持 `0xFF`（`verify()` 断言） |
| 与热靴子镜像的关系 | 热靴子镜像从 `0x081F4000` 起，离注入区约 0x1F000 字节；补丁**不碰**该区 |

> 说明：本机更大范围扫描还能看到 `0x081EC000`/`0x081EC004`/`0x081EC0E0`、
> `0x081F0000`/`0x081F0004`/`0x081F06B0`/`0x081F3FFC` 等地址被代码字面量引用
> （配置/参数区），因此注入区只放在 `0x081C0000`，**不要**向高地址随意扩展。

## 7. 复现命令

```powershell
# 仓库根
tools\python\python.exe keypatch\keypatch.py list
tools\python\python.exe keypatch\keypatch.py info --device x3pro

# 打补丁 + 离线验证（输出到 %TEMP%，不覆盖 keypatch/out/ 的成品）
tools\python\python.exe keypatch\keypatch.py patch --device x3pro --key 0xD798 --verify --out %TEMP%\x3pro
```

`verify()` 的 41 项断言覆盖：

- 长度 1,941,020 B / 注入区 356 B / 注入区剩余 1,692 B 保持 `0xFF`；
- **7 个改动位置**的**补丁后字节**（含两处 compare `0x0802830A`/`0x080284F2` = `ff 2b`）；
- 与原厂差异 = **370 B** 且全部落在补丁点/注入区；
- Unicorn 调用级：`KEY_ON=1` 时 `set_sync(ID=0/1/37/99) = KEY`、
  `KEY_ON=0` 时 = 原厂公式；`TX4`/`TX2` 双发序列（第二帧 = 当前 ID 原厂同步字）、
  普通模式单发、原厂自证；
- **按键计数 5 用例**（松开复位 / #1 / #34 翻转 / #35 latch / 再次长按切回），并断言每次
  都到达原扫描函数体。

更细的静态复核（基址、函数边界、调用点、reg4/5 唯一性、按键扫描/PA6/阈值、开关 RAM、
空闲区引用扫描）可以直接跑附录 A 的脚本，**只读**、不写任何文件。

```python
# -*- coding: utf-8 -*-
"""X3 Pro（C 版，V1.22）静态事实复核（长按开关版；只读；仓库根目录运行）。"""
import hashlib
import struct

FW = r"devices/x3pro/firmware/X3pro_C_v1.22_app.bin"
BASE = 0x08020000
SYNC_FN = 0x0802F040
WRITE_REG = 0x0802E71C
KEYSCAN = 0x08027E44
LONG_CMP = 0x0802830A
LONG_CMP2 = 0x080284F2
INJ, INJ_END = 0x081C0000, 0x081C0800
HOTSHOE = 0x081F4000

d = open(FW, "rb").read()
ok = True


def check(name, cond, detail=""):
    global ok
    ok = ok and bool(cond)
    print("[%s] %s%s" % ("PASS" if cond else "FAIL", name, (" | " + detail) if detail else ""))


def branch_target(hw1, hw2, addr):
    """解码 Thumb-2 B.W / BL（二者 imm 编码相同，靠第二半字区分）。"""
    link = (hw2 & 0xD000) == 0xD000
    wide = (hw2 & 0x9000) == 0x9000 and (hw2 & 0x4000) == 0
    if (hw1 & 0xF800) != 0xF000 or not (link or wide):
        return None
    s = (hw1 >> 10) & 1
    imm10 = hw1 & 0x3FF
    j1 = (hw2 >> 13) & 1
    j2 = (hw2 >> 11) & 1
    imm11 = hw2 & 0x7FF
    i1 = 1 - (j1 ^ s)
    i2 = 1 - (j2 ^ s)
    imm = (s << 24) | (i1 << 23) | (i2 << 22) | (imm10 << 12) | (imm11 << 1)
    if s:
        imm -= 1 << 25
    return addr + 4 + imm


def bl_callers(target):
    out = []
    for o in range(0, len(d) - 4, 2):
        hw1, hw2 = struct.unpack_from("<HH", d, o)
        if (hw2 & 0xD000) == 0xD000 and branch_target(hw1, hw2, BASE + o) == target:
            out.append(BASE + o)
    return out


# ---- 1) 镜像 / 基址 / 尾部子镜像 -------------------------------------------
sp, reset = struct.unpack_from("<II", d, 0)
check("镜像长度 1,941,020 B", len(d) == 1941020, "%d B" % len(d))
check("sha256", hashlib.sha256(d).hexdigest() ==
      "2e2b8a3b5ff70e62c4acddc406b055ea2625e4833a213e81863f96c0da5a911b")
check("向量表 SP/Reset", (sp, reset) == (0x20270000, 0x08031345),
      "SP=0x%08X Reset=0x%08X" % (sp, reset))
check("镜像末尾 0x%08X" % (BASE + len(d)), BASE + len(d) == 0x081F9E1C)
check("Reset 偏移 0x11344 是函数起点", (reset & ~1) - BASE == 0x11344)
blob = open(r"tools/hotshoe_blob.bin", "rb").read()
check("尾部 24,092 B == tools/hotshoe_blob.bin",
      len(blob) == 24092 and d[-len(blob):] == blob,
      "起点 vaddr 0x%08X / 文件偏移 0x%X" % (BASE + len(d) - len(blob), len(d) - len(blob)))

# ---- 2) 同步字函数 ---------------------------------------------------------
callers = bl_callers(SYNC_FN)
check("BL -> 同步字函数 0x0802F040 共 6 处", len(callers) == 6,
      ", ".join("0x%08X" % a for a in callers))
check("函数起始 6 字节与原厂一致",
      d[SYNC_FN - BASE:SYNC_FN - BASE + 6] == bytes.fromhex("0122034610b5"))
check("下一函数起点 0x0802F09C 前有对齐 NOP",
      d[0x0802F09A - BASE:0x0802F09C - BASE] == bytes.fromhex("00bf"))

# ---- 3) 全镜像写 CC2500 reg4/5 的唯一性 ------------------------------------
hits = []
for o in range(0, len(d) - 6, 2):
    hw = struct.unpack_from("<H", d, o)[0]
    if (hw & 0xFFF8) != 0x2000 or (hw & 0xFF) not in (4, 5):   # movs r0,#4 / #5
        continue
    for oo in range(o + 2, min(len(d) - 4, o + 8) + 1, 2):
        hw1, hw2 = struct.unpack_from("<HH", d, oo)
        if (hw2 & 0xD000) == 0xD000 and branch_target(hw1, hw2, BASE + oo) == WRITE_REG:
            hits.append((BASE + o, hw & 0xFF, BASE + oo))
check("写 reg4/5 只有 4 个立即数点（2 处初始化表 + 2 处同步字函数）",
      [h[0] for h in hits] == [0x0802E94C, 0x0802E95E, 0x0802F058, 0x0802F068],
      ", ".join("0x%08X->reg%d" % (h[0], h[1]) for h in hits))
check("初始化表写 SYNC1=0xC3 / SYNC0=0x68",
      d[0x0802E942 - BASE:0x0802E944 - BASE] == bytes.fromhex("c322") and
      d[0x0802E954 - BASE:0x0802E956 - BASE] == bytes.fromhex("6822"))

# ---- 4) 设置结构 / ID 菜单（原厂含义）-------------------------------------
refs = [BASE + o for o in range(0, len(d) - 4, 2)
        if struct.unpack_from("<I", d, o)[0] == 0x20001768]
check("设置区 0x20001768 被 4 字节字面量引用 24 处", len(refs) == 24, "%d 处" % len(refs))
check("ID 菜单 +1/+10 两条路径都钳位 99",
      d[0x080299A0 - BASE:0x080299AC - BASE] == bytes.fromhex("0a33dbb2632b88bf63235370"))
check("调用同步字函数前取 ID（[r4,#1]）",
      d[0x0802F230 - BASE:0x0802F232 - BASE] == bytes.fromhex("6078") and
      d[0x0802F900 - BASE:0x0802F902 - BASE] == bytes.fromhex("6078"))

# ---- 5) 长按开关：按键扫描入口 / PA6 / 阈值 / 开关 RAM ---------------------
check("按键扫描入口 0x08027E44 = push.w {r3..r11,lr}",
      d[KEYSCAN - BASE:KEYSCAN - BASE + 4] == bytes.fromhex("2de9f84f"))
check("main 主循环唯一 BL -> 0x08027E44", bl_callers(KEYSCAN) == [0x0802B282],
      ", ".join("0x%08X" % a for a in bl_callers(KEYSCAN)))
gpio_ctx = {
    0x08027E5C: bytes.fromhex("4021"),        # movs r1,#0x40   PA6
    0x08027E66: bytes.fromhex("1021"),        # movs r1,#0x10   PB4（备选键）
    0x08027E7A: bytes.fromhex("2021"),        # movs r1,#0x20   PB5（备选键）
    0x08027E88: bytes.fromhex("4ff40041"),    # mov.w r1,#0x8000  GPIOC15（热靴）
}
for addr, want in gpio_ctx.items():
    check("按键扫描读 GPIO mask @0x%08X" % addr,
          d[addr - BASE:addr - BASE + len(want)] == want, want.hex(" "))
check("原厂 PA6 长按阈值 A 0x0802830A = cmp r3,#0x21",
      d[LONG_CMP - BASE:LONG_CMP - BASE + 2] == bytes.fromhex("212b"))
check("原厂 PA6 长按阈值 B 0x080284F2 = cmp r3,#0x21",
      d[LONG_CMP2 - BASE:LONG_CMP2 - BASE + 2] == bytes.fromhex("212b"))
check("长按路径在 0x0802852E 调用电源/关机流程 0x0802B7D0",
      0x0802852E in bl_callers(0x0802B7D0),
      ", ".join("0x%08X" % a for a in bl_callers(0x0802B7D0)))
for ram in (0x20001096, 0x20001098, 0x2000109A):
    used = [BASE + o for o in range(0, len(d) - 4, 2)
            if struct.unpack_from("<I", d, o)[0] == ram]
    check("开关 RAM 0x%08X 无 4 字节字面量引用" % ram, not used, str(used[:5]))

# ---- 6) 空闲区 / 注入区 ----------------------------------------------------
check("0x081B0A30..0x081F4000 全 0xFF",
      all(b == 0xFF for b in d[0x081B0A30 - BASE:HOTSHOE - BASE]))
check("注入窗口 0x081C0000..0x081C0800 全 0xFF",
      all(b == 0xFF for b in d[INJ - BASE:INJ_END - BASE]))
abs_refs = []
for o in range(0, len(d) - 4, 2):
    v = struct.unpack_from("<I", d, o)[0]
    if INJ <= (v & ~1) < INJ_END:
        abs_refs.append((BASE + o, v))
check("注入窗口 4 字节绝对地址引用 = 0", not abs_refs, str(abs_refs[:5]))
branch_refs = []
for o in range(0, len(d) - 4, 2):
    hw1, hw2 = struct.unpack_from("<HH", d, o)
    t = branch_target(hw1, hw2, BASE + o)
    if t is not None and INJ <= t < INJ_END:
        branch_refs.append((BASE + o, t))
check("注入窗口分支目标 = 0", not branch_refs, str(branch_refs[:5]))
check("热靴子镜像起点 0x081F4000 不在注入窗口内", HOTSHOE >= INJ_END)

print()
print("结论:", "ALL PASS" if ok else "存在 FAIL，请按上文复核")
```
