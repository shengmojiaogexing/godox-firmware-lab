## 0. 一句话结论

X3 Pro 的「ID → CC2500 同步字」函数是 **`0x0802F040`**（`0x5A` 字节，下一函数 `0x0802F09C`），
它是全镜像**唯一在运行期写** CC2500 `SYNC1/SYNC0`（寄存器 4/5）的地方（另有一处初始化表会被它覆盖）。

**密钥开关用物理按键长按**：**长按 PA6（GPIOA `0x42020000`，mask `0x40`）≈1.5 秒** 切换密钥模式
（不新增 UI；原厂这颗键的长按关机动作被禁用/复用，电源键长按关机不受影响）。

- **密钥模式（`KEY_ON=1`）**：每一帧先按**私有密钥**同步字发一遍（引闪已打补丁的密钥灯），
  再用 `SYNC = floor(50024/(当前ID+1))` 发一遍（引闪同频道、同 ID 的原厂灯，兼容普通灯）；
  发完把同步字恢复成 KEY，保证中断/异步队列发出的帧也走密钥同步字。
- **普通模式（`KEY_ON=0`，出厂/上电默认）**：与原厂行为一致（每帧单发，同步字 = `50024/(ID+1)`）。
- **ID 菜单恢复原厂含义（0..99）**，不再有 ID=99 的特殊语义。

## 2. 核心数据通路：同步字函数 `0x0802F040`

### 2.1 原厂反汇编（`0x5A` 字节）

`0x0802F040` 起到 `0x0802F099`，共 **`0x5A`（90）字节**；`0x0802F09A` 是对齐用 `NOP`，
下一函数起点 **`0x0802F09C`**：

```asm
0x0802F040  01 22            movs  r2, #1
0x0802F042  03 46            mov   r3, r0              ; r3 = ID（入参）
0x0802F044  10 b5            push  {r4, lr}
0x0802F046  4c f2 68 34      movw  r4, #0xC368        ; 50024
0x0802F04A  13 44            add   r3, r2            ; r3 = ID + 1
0x0802F04C  b4 fb f3 f4      udiv  r4, r4, r3        ; sync = 50024 / (ID+1)
0x0802F050  82 b0            sub   sp, #8
0x0802F052  23 0a            lsrs  r3, r4, #8        ; SYNC1 = sync >> 8
0x0802F054  0d f1 07 01      add.w r1, sp, #7
0x0802F058  04 20            movs  r0, #4
0x0802F05A  8d f8 07 30      strb.w r3, [sp, #7]
0x0802F05E  ff f7 5d fb      bl    0x0802E71C        ; WriteReg(4, SYNC1)
0x0802F062  01 22            movs  r2, #1
0x0802F064  0d f1 07 01      add.w r1, sp, #7
0x0802F068  05 20            movs  r0, #5
0x0802F06A  8d f8 07 40      strb.w r4, [sp, #7]
0x0802F06E  ff f7 55 fb      bl    0x0802E71C        ; WriteReg(5, SYNC0)
0x0802F072  14 20            movs  r0, #0x14           ; 20
0x0802F074  fc f7 b2 fa      bl    0x0802B5DC        ; delay_us(20)
0x0802F078  33 20            movs  r0, #0x33           ; SCAL
0x0802F07A  ff f7 07 fc      bl    0x0802E88C        ; strobe(0x33)
0x0802F07E  4f f4 7a 70      mov.w r0, #0x3E8         ; 1000
0x0802F082  fc f7 ab fa      bl    0x0802B5DC        ; delay_us(1000)
0x0802F086  36 20            movs  r0, #0x36           ; SIDLE
0x0802F088  ff f7 00 fc      bl    0x0802E88C        ; strobe(0x36)
0x0802F08C  4f f4 2f 70      mov.w r0, #0x2BC         ; 700
0x0802F090  02 b0            add   sp, #8
0x0802F092  bd e8 10 40      pop.w {r4, lr}
0x0802F096  fc f7 a1 ba      b.w   0x0802B5DC        ; delay_us(700)（尾调用）
0x0802F09A  00 bf            nop                      ; 对齐
0x0802F09C  ...                                       ; 下一函数
```

**补丁要改的 10 字节** = `0x0802F046–0x0802F04F`（原厂 `4c f2 68 34 13 44 b4 fb f3 f4`
= `movw r4,#0xC368; add r3,r2; udiv r4,r4,r3`）：

```text
原厂 0x0802F046  4c f2 68 34 13 44 b4 fb f3 f4
补丁 0x0802F046  90 f1 db bf 00 bf 00 bf 00 bf   ; B.W inj_sync + 3×NOP（key=0xD798 时）
```

补丁后的 `inj_sync` 读 `KEY_ON`：**`KEY_ON=1` → `r4 = KEY`；`KEY_ON=0` → 逐字节重放原厂公式**
（`movs r2,#1; mov r3,r0; movw r4,#0xC368; add r3,r2; udiv r4,r4,r3`），再跳回 `0x0802F050`
继续原厂的 SYNC1/SYNC0 写入 + SCAL/延时序列。

### 2.2 函数边界与调用点

- 函数体止于 `0x0802F099`，**不能**写到 `0x0802F09C`（下一函数是另一个函数）。
- 全镜像 `BL → 0x0802F040` 的调用点共 **6 处**（静态扫描，见
  [`docs/01_静态证据与复现.md`](docs/01_静态证据与复现.md) §2）：

  | 调用点 | 调用前 ID 来源（静态可见） |
  |---|---|
  | `0x0802F134` | `ldrb r0,[r6,#1]`（r6 = 设置区 `0x20001768`） |
  | `0x0802F144` | `mov r0, r5`（寄存器传入，上游路径未逐一回溯） |
  | `0x0802F234` | `ldrb r0,[r4,#1]`（r4 = 设置区 `0x20001768`） |
  | `0x0802F720` | `mov r0, r6`（寄存器传入，上游路径未逐一回溯） |
  | `0x0802F740` | `mov r0, r6`（同上） |
  | `0x0802F902` | `ldrb r0,[r4,#1]`（r4 = 设置区 `0x20001768`） |

- 6 个入口共享同一个「同步字函数」；**10 字节改写对所有调用点同时生效**，无需逐个调用点打补丁。

## 3. 设置结构与开关 RAM

| 项 | 值 | 证据 |
|---|---|---|
| 设置区基址 | **`0x20001768`** | 全镜像 24 处 4 字节字面量引用（`0x0802F168`/`0x0802F268`/`0x0802F77C`/`0x0802F938` 等） |
| `[+0]` | 频道（channel） | 调用点常见 `ldrb r0,[r4]` → `set_channel(0x0802EFC8)` |
| `[+1]` | **ID**（`0x20001769`） | `ldrb r0,[r4,#1]` → `bl 0x0802F040` |
| ID 菜单范围 | **0..99（原厂含义，未被补丁占用）** | ID 修改处理块 `0x08029996` 起：+1（`0x080299AE`）与 +10（`0x080299A0`）两条路径都钳位 `0x080299A4 cmp r3,#0x63` / `0x080299A8 movhi r3,#0x63` |

**开关 RAM（本补丁注入代码使用）**：

| 地址 | 宽度 | 含义 |
|---|---|---|
| `0x20001096` | u8 | **`KEY_ON`**：0=普通模式，1=密钥模式（**RAM 版**，上电/换电池复位为 0） |
| `0x20001098` | u16 | 长按扫描计数（按下每轮 +1，松开清零） |
| `0x2000109A` | u8 | latch：本次按住已触发过（防连发） |

- 这 3 个字节位于本固件静态空白 RAM 区；**全镜像 4 字节字面量对 `0x20001096/98/9A` 的引用 = 0 处**
  （见 `docs/01_静态证据与复现.md` §5）；
- 补丁**不新增**任何设置字节、不占用 ID 菜单；`KEY_ON` 是纯 RAM 状态，重启/换电池后回到普通模式。

## 4. 补丁方案（6 个区域 / 7 个改动位置 + 356 B 注入，输出长度不变）

### 4.1 按键扫描入口 → `B.W inj_btn`（长按开关）

| 地址 | 原厂 4 B | 补丁后（key=0xD798） | 说明 |
|---|---|---|---|
| `0x08027E44` | `2d e9 f8 4f`（`push.w {r3..r11,lr}`） | `98 f1 14 b9`（`B.W inj_btn`） | 按键扫描函数入口；main 主循环 `0x0802B282` 每轮 `bl 0x08027E44` |

`inj_btn` 的判定/计时逻辑（注入区 `0x081C0070`）：

```text
inj_btn:
  push {r4,lr}
  r0 = read_gpio(GPIOA 0x42020000, mask 0x40)     ; PA6；返回 0 = 按下
  if 未按下:
      BTN_CNT = 0; LATCH = 0                       ; 松开复位
  else if LATCH == 0:
      BTN_CNT += 1
      if BTN_CNT == 34 (0x22):                     ; 阈值，≈1.5 s
          KEY_ON ^= 1; LATCH = 1                   ; 翻密钥模式，本次按住只触发一次
  ; 之后一律走蹦床回原厂按键扫描函数体
  tramp_btn: push.w {r3..r11,lr}; b.w 0x08027E48
```

- 原厂按键扫描的**短按/双击/其它键/热靴触发**逻辑全部保留（只在其前面加了长按判定）；
- `BTN_TICKS=34` 与原厂 PA6 长按阈值 `0x21`（33）同量级，实机约 1.5 秒（**需实测确认**）。

### 4.2 禁用两处原厂 PA6 长按动作（关机/倒计时状态被复用）

| 地址 | 原厂 | 补丁后 | 说明 |
|---|---|---|---|
| `0x0802830A` | `21 2b`（`cmp r3,#0x21`） | `ff 2b`（`cmp r3,#0xFF`） | 动作 A：原厂「PA6 长按（计数 > 0x21）→ 电源/关机流程 `0x0802B7D0`」不再触发；电源键（GPIOB0）长按关机不受影响 |
| `0x080284F2` | `21 2b`（`cmp r3,#0x21`） | `ff 2b`（`cmp r3,#0xFF`） | 动作 B：按键扫描状态机另一个分支（某些状态下长按会置 countdown 状态 `0x16`，写 `0x20000087=0xB4`）；同样禁用 |

> 原厂 PA6 长按的关机路径：`0x0802830A` 比较通过后 → `0x08028310` 起置长按标志/状态 →
> `0x0802852E bl 0x0802B7D0`（电源/关机流程）。状态机的另一分支在 `0x080284F2` 也有同样的
> `cmp r3,#0x21`，比较通过后执行 `0x080284FA–0x08028508`（写 `0x20000087=0xB4`、置 countdown
> 状态 `0x16`）；只禁第一处不彻底，所以两处都改成 `0xFF`。这颗键的长按就被本补丁的密钥开关
> 复用；**长按关机改用电源键/菜单**。

### 4.3 两个发送入口 → `B.W` 跳注入（双发）

| 地址 | 函数 | 原厂 4 B | 补丁后（key=0xD798） | 说明 |
|---|---|---|---|---|
| `0x0802EDC4` | 发 4 字节帧（`0x7F` FIFO burst + STX `0x35` + 600 µs + SFTX/SIDLE） | `10 b5 ff f7`（`push {r4,lr}; bl 0x0802EC64`） | `91 f1 30 b9`（`B.W inj_tx4`） | `KEY_ON=1` 时双发 |
| `0x0802EE2C` | 发 2 字节帧（`0xD5 xx` 短命令，STX + 500 µs + SFTX/SIDLE） | `10 b5 ff f7`（同上） | `91 f1 0e b9`（`B.W inj_tx2`） | 同上 |

注入的包装函数按 `KEY_ON` 分流：

```text
inj_tx4 / inj_tx2:
  push {r4,lr}
  if (RAM[0x20001096] != 0):
      唤醒射频后写 SYNC = KEY            → 发第一帧
      唤醒射频后写 SYNC = floor(50024/(ID+1)) → 发第二帧
      恢复 SYNC = KEY                    ; 让中断/队列路径后续的帧仍走密钥
  else:
      唤醒射频后写 SYNC = floor(50024/(ID+1)) → 单发（等效原厂行为）
  pop {r4,pc}
```

每个「蹦床」都按原厂入口顺序重建被覆盖的 4 字节（`push {r4,lr}` + `bl 0x0802EC64`），
**先唤醒/置忙射频，再写同步字**，最后跳回原函数体（`0x0802EDCA` / `0x0802EE32`）——
原厂组帧/FIFO/发射时序 100% 保留。

| `0x081C0164` | `0x69C` | — | 预留到 `0x081C0800`（2 KB），保持擦除态 `0xFF`（`verify` 断言） |

### 4.5 差异统计与安全约束

- 与原厂总差异 = **370 B**，全部落在上述 6 个区域 / 7 个改动位置：
  按键扫描入口 4 B + 两处长按阈值各 1 B（各改 1 字节）+ 两个发送入口 8 B + 同步字函数 10 B +
  注入区 356 B 中实际改变 346 B（注入代码里有 10 个字节恰为 `0xFF`，与原厂擦除态相同，故不计差异）；
- 输出长度 == 输入长度 == 1,941,020 B（G3 可直接刷）；
- 每个补丁点原始字节逐字节校验，固件长度/sha256 不符直接 `raise ValueError`（防刷错版本）；
- 注入只占 `0x081C0000` 起 356 B，预留 2,048 B；该 2 KB 窗口静态扫描**无分支目标、无 4 字节绝对地址引用**，
  且远离 `0x081F4000` 起的 24,092 B 热靴子镜像（详见 `docs/01_静态证据与复现.md` §6）。

## 5. 用户开关语义：长按 PA6 ≈1.5 秒

| 操作 | 行为 |
|---|---|
| **长按 PA6 ≈1.5 s**（原厂长按会关机的那颗键） | **切换密钥模式**：`KEY_ON` 0→1 或 1→0（每次按住只切一次） |
| 短按/双击 PA6、其它按键 | 原厂逻辑不变 |
| 长按电源键（GPIOB0） | **原厂关机不受影响** |

- **不新增 UI**：完全复用原厂按键；
- **密钥模式需要灯端也打同一把密钥并打开密钥开关**（AD100「KEY」/ AD200「F8」/ V1C·V860III·V1S「LIGHT=ON」等）；
- **开关是 RAM 版**：关机/换电池/复位后回到普通模式，需要重新长按开启；
- **没有视觉/声音反馈**：切换后建议用「同频道、同 ID 的原厂灯 + TEST 引闪」确认：灯闪 = 仍能兼容普通灯；
  若要确认密钥隔离，需用另一台未打补丁的原厂引闪器/灯做对照；
- **键位需实机确认**：静态分析只能确定 PA6 是「原厂长按进关机流程」的键；若实机按下的不是它，
  把模块里的 `BTN_MASK` 改成 `0x10`（PB4）或 `0x20`（PB5）重新生成即可（三者都在按键扫描里被读取，改一个常量）。

| 静态 | 固件长度 1,941,020 B（原位补丁 + 注入） |

| 静态 | 与原厂差异 = 370 B，且**全部**落在补丁点/注入区（集合比对），差异之外 0 变化 |
| Unicorn | 同步字函数：`KEY_ON=1` 时 ID=0/1/37/99 → `SYNC=KEY`；`KEY_ON=0` 时 → 原厂公式；SCAL/SIDLE 序列保持 |

| Unicorn | **按键计数 5 用例**：松开复位 / 按下 #1 / 按下 #34 到阈值翻转 / 第 35 次已 latch 不重复 / 再次长按 #34 切回，并断言每次都回到原扫描函数体 |

[PASS] TX4 ID=5 补丁版(普通模式)：SYNC=0x2091 -> 单发
[PASS] 按键 按下 #34（到阈值）：到达原扫描函数体=True，KEY_ON=1 cnt=34 latch=1

### 6.4 做不到的部分（如实记录）

- **整机模拟器未建立**：X3 Pro 没有像 AD100/AD200/X3-C 那样的整机 Unicorn 模拟机，本轮只做到

## 7. 风险与回滚

### 7.1 已知风险

| 项 | 状态 | 说明 |
|---|---|---|
| 实机验证 | ❌ 未做 | 无整机模拟器；首次刷入按 §7.3 安全阶梯 |
| **键位需实机确认** | ⚠️ 待确认 | 静态只能确定 PA6 = 原厂「长按会进关机流程」的键；若实机不是想用的键，改 `BTN_MASK`（`0x10`=PB4 / `0x20`=PB5）重新生成 |
| **原厂 PA6 长按关机被占用** | ℹ️ 预期取舍 | 原厂这颗键的长按关机被禁用（**两处** compare：`0x0802830A` / `0x080284F2` 均改 `#0xFF`），长按改为切密钥模式；关机用电源键（GPIOB0）长按 / 菜单 |
| **RAM 版开关** | ℹ️ 预期行为 | `KEY_ON` 在 RAM `0x20001096`，关机/换电池/复位回普通模式，需要重新长按 |
| **双发时序变长** | ⚠️ 已知取舍 | 密钥模式下每次发射**多一帧**：4B 帧多一次 FIFO+STX；2B 短命令原厂本来就连发 3 次，补丁后每帧再多一次 500 µs 级发射。若实机出现 HSS/连拍异常，优先怀疑这里 |
| 关中断窗口 | ⚠️ 残余 | 注入代码在两次发射之间改同步字，未做 `cpsid`；射频中断发送路径由原厂忙标志 `0x20001D09` 接管，窗口约几十~几百 µs |
| **无反馈指示** | ℹ️ 说明 | 切换没有灯/声音反馈；用同频道同 ID 的原厂灯 + TEST 引闪、或对照未打补丁的引闪器验证 |
| 普通灯兼容 | ✅ 设计保留 | 双发第二帧 = 当前 ID 的原厂同步字，可引闪同频道、同 ID 的原厂灯；不需要兼容时可把模块里的 `DUAL_SEND` 关掉（只剩 KEY 单发，时序变化最小） |
| 16 位同步字 | ⚠️ 非密码学 | 挡的是正常原厂设备误触发；SDR 抓包理论上可克隆 |
| Flash/RAM/显示 | ⚠️ 待确认 | 本轮未做整机逆向；不影响密钥补丁但限制后续 UI 改造 |
| 版本绑定 | ✅ 有防护 | sha256 + 7 个改动位置原始字节双校验，版本不符直接拒绝打补丁 |

### 7.2 回滚（恢复原厂）

用官方 G3 刷回原厂镜像即可：

```text
devices/x3pro/firmware/X3pro_C_v1.22_app.bin
```

G3 若检测不到设备：先正常开机，**按一下侧面的旋转拨轮**再插 USB 试
（与 X3-C 的救砖方法相同，见 [`keypatch/README.md`](../../keypatch/README.md) §0.4 / §9.6）。

### 7.3 实机安全阶梯（建议顺序，风险自负）

1. **原厂基线**：确认官方 G3 能识别设备、手上有同版本原厂固件可回滚；
2. **普通模式回归**：刷补丁版后先不操作长按，确认 ID 0..99 下引闪、功率、造型灯、连拍与原厂一致；
3. **长按切换**：长按 PA6 ≈1.5 s（**先确认这颗键就是原厂长按关机的键**），再用同频道同 ID 的原厂灯
   + TEST 确认仍能引闪（说明双发第二帧在发）；
4. **密钥模式**：引闪器 `KEY_ON=1` + 已打补丁并打开密钥开关的灯 → 能引闪；
5. **隔离验证**：把灯切回普通模式（或让引闪器回到 `KEY_ON=0`）→ 密钥灯应**不被引闪**（密钥生效）；
6. **关机方式回归**：确认长按 PA6 不再关机（改为切密钥），电源键长按关机仍正常；
7. **重启复位**：断电重启后确认回到普通模式（RAM 版开关的预期行为）；
8. **双发时序**：HSS / 连拍 / 造型灯等高频场景各跑一次，确认无误触发/漏闪；
9. 任意一步异常 → 立刻刷回原厂 `X3pro_C_v1.22_app.bin`。

## 9. 与 X3-C / X3-S 的关系（参考 x3c 的说明）

X3 Pro（C 版）与 X3-C / X3-S 同属 X3 平台思路：**原位改同步字 + 在空闲闪存里放注入代码**；
本仓库里 X3-C 的完整逆向资料见 [`devices/x3c/`](../x3c/)（含整机模拟器与网页调试器）。

差异（本机固件实测，三方固件**不能**直接套用对方的地址/字节）：

| 项 | X3-C（V1.38） | X3-S（V1.25） | **X3 Pro（V1.22，C）** |
|---|---|---|---|
| App 基址 | `0x08004800` | `0x08004800` | **`0x08020000`** |
| 同步字函数 | `0x08014864` | `0x0801474C`（相对 X3-C -0x118） | **`0x0802F040`** |
| 密钥开关 | 长按 M/C 切密钥 + 双发（UI 版）/ ID=99（核心版） | v1 固定 KEY（无开关） | **长按 PA6 ≈1.5s（RAM 版）** |
| 补丁形态 | 入口 B.W 注入 + 空闲区 | 同步字函数两条立即数原位改写 | **3 个函数入口 B.W + 同步字 10 B + 两处长按阈值各 1 B + 356 B 注入** |
| 整机模拟器 | ✅ 有（`devices/x3c/emu/`） | ❌ 无 | ❌ 无 |

> 因此不要拿 X3-C 的 `0x080EE000`/`0x080F0000` 空闲区或 X3-S 的立即数偏移来套 X3 Pro；
> X3 Pro 的注入区、函数地址、开关 RAM 都以本文与 `keypatch/devices/x3pro.py` 为准。
