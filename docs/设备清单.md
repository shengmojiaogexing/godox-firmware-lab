> 补丁入口与支持状态。新增设备请同时更新本表（另见 [`新增设备指南.md`](新增设备指南.md)）。

> 本表只记录**文件名 + sha256**，请从官方渠道获取正版固件后按 sha256 核对。

## 2. 固件路径速查（放对位置很关键）

```text
devices/x3c/firmware/X3_C_v1.38_app.bin
devices/ad100pro/firmware/AD100pro_V1.2.bin
devices/ad200pro/firmware/AD200pro_V1.60.bin
```

- 这些文件**不入库**（`.gitignore` 忽略 `*.bin`），只在你本机；
- studio「上传原厂固件」也会保存到对应 `firmware/` 并按 sha256 校验；
- `keypatch\keypatch.py list` 会逐台显示 `sha256 OK` / `MISMATCH` / 缺失。

sha256 自查：

```powershell
(Get-FileHash devices\x3c\firmware\X3_C_v1.38_app.bin -Algorithm SHA256).Hash.ToLower()
tools\python\python.exe keypatch\keypatch.py list
```

## 3. 各设备「补丁入口」含义

| 概念 | 含义 | 参考 |
|---|---|---|
| 同步字函数 | 固件里把当前 ID 换算成 `SYNC1/SYNC0` 并写 CC2500 寄存器 4/5 的函数；本工具把它改写成「同步字 = 私有 KEY」 | `keypatch/INTERFACE.md` |
| 整函数改写 | 在原函数占用的字节范围内重写机器码（输出长度不变，不越界到下一个函数） | `keypatch/dev/ad100/NOTES.md`、`keypatch/dev/ad200/NOTES.md` |
| 入口跳转 + 注入 | 把组帧函数入口改成 `B.W` 跳到空闲闪存里的注入代码，实现「KEY 帧 + 普通帧」双发 | `keypatch/dev/x3c/NOTES.md`、`DESIGN_TOGGLE.md` |
| 开关字节 | 用户可见的「密钥开关」：灯的 C.Fn 项 / 引闪器 UI 磁贴，对应某个 RAM 字节（掉电保存由固件参数区负责） | `keypatch/DESIGN_TOGGLE.md` |
| 离线验证 | Unicorn 直接执行补丁后的机器码，断言写入的 SYNC1/SYNC0；原厂镜像做同 harness 自证 | `keypatch/selftest.py` |

## 4. 支持状态与产物

| 设备 | 补丁模块 | 正式成品（`keypatch/out/`，本机生成） | 容器备用件 | studio |
|---|---|---|---|---|
| X3-C | `keypatch/devices/x3c.py` | `X3_C_v1.38_app_key<KEY>.bin` | `..._container.bin`（`--container`） | ✅ 自动出现 |
| AD100 Pro | `keypatch/devices/ad100.py` | `AD100pro_V1.2_key<KEY>.bin` | `..._container.bin` | ✅ 自动出现 |
| AD200 Pro | `keypatch/devices/ad200.py` | `AD200pro_V1.60_key<KEY>.bin` | `..._container.bin` | ✅ 自动出现 |
| V1C / V862C | 待实现（从 `devices/_template/device.py` 复制） | — | — | 注册后自动出现 |

生成命令（仓库根）：

```powershell
tools\python\python.exe keypatch\keypatch.py patch-all --key 0xD798 --verify --container
```

刷机/回滚/救砖步骤见 [`../keypatch/README.md`](../keypatch/README.md)；接入新设备见
[`新增设备指南.md`](新增设备指南.md)。
