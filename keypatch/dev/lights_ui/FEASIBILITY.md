## 1. AD100 Pro：菜单 / 存储 / 注入点（已实证）

### 1.1 C.Fn 菜单结构

| 项 | 值 |
|---|---|
| 画面渲染函数 | **0x08003F0C..0x0800447A**（1390B）。布局：标题行 + 左侧 3 行列表 + 中部图标 + 值区域 |
| 当前项数 | 6：BEEP(0)、PHOTOC(1)、STBY(2)、DELAY(3)、WL(4)、ID(5) |
| 选择索引 | **RAM 0x2000017B**（UI 结构 0x20000164 + 0x17），页 = sel/3、行 = sel%3（0x08003F88 处 `bl 0x080030F0` 除 3） |
| 每项值 | **RAM 0x20000480[0..5]**（渲染函数 0x08003F96 载入 `r5=0x20000480`；例：ID 值 = 0x20000485） |
| 标题绘制 | "C.Fn" 4 个 8x16 字形（字库 **0x0800DEC6**，17B/字形：宽度 + 每列 2 字节） |
| 字库映射 | `'0'..'9' = 0x00..0x09`，`'A'..'Z' = 0x0A..0x23`；故 `K=0x14, E=0x0E, Y=0x22, O=0x18, N=0x17, F=0x0F` |
| 高亮代码 | 公共尾段 **0x08004318**（按 `[sp+0x10]` 行号反白选中行并画边框） |
| 导航 | 0x08004880（+ 键）选择项 +1 上限 5；0x08008A5C（- 键）选择项 -1 回绕到 5（`0x20000179/*UI+0x15*/==1` 即 C.Fn 打开时生效） |
| 超时 | 0x0800B790 用 `[UI+0x32]`（0x20000196）倒计时，到 0 清 UI+0x13（编辑项）、UI+0x15（C.Fn 打开） |

### 1.2 设置存储链路（已实证，无需改存储代码）

```
flash 记录 0x0801F000 + slot*100 （32B 有效 + 其余填充，首字节 magic 0x5C）
        │  0x0800AD44  上电扫描 slot 19..0 找 magic
        ├─ 0x08005E8C  记录 32B → RAM 0x20000434
        ├─ 0x0800CE6C  展开 0x20000434 → 各设置全局（含 0x20000480[0..7]）
        └─ 0x0800AD44 校验（表 0x0800DA2E：值 > 上限则清零）
保存：  0x08004690(dst=0x20000454) 用当前设置组 32B 记录
        → 0x0800C92C 与影子 0x20000454 比较
        → 0x0800B588(slot) → 0x08005EF4 写 flash（0x0801F000+slot*100）
触发：  0x0800B578 置 200 tick 倒计时；主循环任务 0x080097F8 到期保存
```

**关键结论：记录字节 24..31 一一对应 RAM 0x20000480..0x20000487，且 8 项上限表 0x0800DA2E 为**
`01 02 03 96 01 63 01 01`（即 **slot 6、7 上限 = 1，正好 ON/OFF**）。
所以第 7 项（索引 6）用 **0x20000486 = 记录偏移 30**，加载/保存/掉电恢复全部自动生效，
**不需要改存储与默认值代码**。加/减值处理（0x08004880 / 0x08008A5C）在入口都会调用
0x0800B578 设置保存倒计时，所以 KEY 改动同样会被防抖保存。

### 1.3 补丁清单（`ui_patch_ad100.py`，全部原位、总差异 112 字节、文件长度不变）

| # | 地址 | 原始字节 | 新字节 | 说明 |
|---|---|---|---|---|
| P1 | 0x08003F10..0x08003F88（120B） | `582102231f22002001f00af8…d4ff` | 见下 | 头部重写：删 "Ver 1.2"（6×12B），保留并压缩 "C.Fn" 标题（36B），腾出区域放注入代码 |
| P2 | 0x08003FA2 | `B9 E1`（`b 0x08004318`） | `B6 E7`（`b 0x08003F12`） | page>=2（选中项 6）→ 注入代码 |
| P3 | 0x0800490C | `05 28`（`cmp r0,#5`） | `06 28`（`cmp r0,#6`） | + 键选择项上限 5→6 |
| P4 | 0x08008A8A | `05 21`（`movs r1,#5`） | `06 21`（`movs r1,#6`） | - 键选择项回绕 5→6 |
| P5 | 0x08004F88 | `05 B0 F0 BD`（`add sp,#0x14; pop {r4-r7,pc}`） | `01 B0 FF BD`（`add sp,#4; pop {r0-r7,pc}`） | 8x16 字形绘制收尾恢复 r0-r3（ABI 允许，对既有调用者透明），让注入代码可复用 page/mode 寄存器 |

P1 注入区（0x08003F10 起 120B）布局：

```
0x08003F10: b 0x08003F5C                 ; 正常页面流程：跳过注入代码，画标题
0x08003F12: [注入代码 74B]               ; page>=2 时：
            画 "KEY"（page=2, x=0x0A/0x11/0x18, 字形 K/E/Y, mode=2）
            画值区域 'O'（page=4, x=0x4A, mode=1）
            ldrb r7,[r5,#6] ; cmp r7,#0
              !=0 → 画 'N'（x=0x51）  即 "ON"
              ==0 → 画 'F'(x=0x51)+'F'(x=0x58) 即 "OFF"
            b 0x08004318                 ; 公共高亮/边框
0x08003F5C: [标题 "C.Fn" 36B]           ; 复用 P5，每字形 8B
0x08003F80: 4×NOP 填充 → 0x08003F88
```

### 1.4 与核心同步字补丁的接口（给 fw-ad100）

- **密钥标志 = RAM 字节 0x20000486**（flash 记录偏移 **30**，记录基址 `0x0801F000 + slot*100`）。
- 语义：**0 = 普通模式（ID 逻辑保持原厂）；1 = 私有密钥模式（SYNC = 私有 KEY）**。
- 原 v2 补丁的 "ID=OFF(0) → KEY" 改为：**读 0x20000486**，不再依赖 ID。
- 该字节与 ID（0x20000485）相邻但完全独立；ID 菜单/`rf_set_id` 逻辑不改。

### 1.6 风险 / 已知回归

1. **"Ver 1.2" 版本号从 C.Fn 画面删除**（仅装饰；Lead 已批准）。版本信息若用户依赖，需另找位置显示。
2. **C.Fn 第 3 页（KEY 页）只有 1 项**，左侧另两行是空白框；功能正常但观感一般，可后续在空行画灰字或改分页逻辑。
3. **0x08004F30（8x16 字形绘制）被改为恢复 r0-r3**：ABI 上允许、对既有调用者透明，已用 sel=0..5 逐字节对照验证无回归；但它是一个被多处 UI 复用的函数，实机仍需回归一遍。
4. **翻转 KEY 后同步字不会立即更新**：C.Fn 值修改路径只对 item==5（ID）调用 `rf_set_id(0x0800B758)`；item 6 不会调用。
   → 目前效果是「下次 RF 初始化/改 ID 后生效」。**未完成项**：需要约 8~12B 的额外 hook（或用核心补丁在 RF 收发路径读标志），本原型未做。
5. **MENU 键进入 C.Fn 的端到端按键流程未在模拟器跑通**：本次验证用「设置 UI+0x15=1」+ 直接调用渲染/导航处理函数完成；
   真实按键入口（MENU 键 → 0x0800451C/0x0800B880 等）逻辑已读，但未做完整按键注入回归。
6. **空白新机默认值**：BSS 清零后 0x20000486=0（普通模式）；默认记录保存时 0x08004690 会写入该字节 0。
   已在模拟器验证组包/保存/加载，但未在「全新空 flash + 首次保存」全流程复测。
7. 未在真机验证：段码/OLED 面板方向、按键丝印与键位对应、写 flash 时序。

### 1.7 与核心补丁合并时的冲突点（明确清单）

KEY 标志 0x20000486 的写者只有 3 类，均不与核心补丁重叠：

| # | 写者 | 说明 |
|---|---|---|
| W1 | 0x0800AD44 → 0x08005E8C → 0x0800CE6C | 上电从 flash 记录加载（记录偏移 30 → 0x20000486） |
| W2 | 0x08004690 → 0x0800B588 → 0x08005EF4 | 保存时从 RAM 组 32B 记录写回（含偏移 30） |
| W3 | 0x08004880 / 0x08008A5C（C.Fn 值 +/-） | 用户切换 KEY 时写入 0/1；入口会调用 0x0800B578 设置保存倒计时 |

核心补丁侧：`0x0800B758`（原 `rf_set_id`）有 4 个调用点
（RF 初始化 0x08004AF0、ID 编辑 0x08004880 / 0x08008A5C、按键分发 0x08008D00 的 ID 组合键）。
与原设计一致：**这 4 处都保持调用 0x0800B758，但函数内部改成读 0x20000486 决定 KEY/普通**。

**未完成（需合并者决定是否补）：** C.Fn 修改 KEY 后不会主动调用 0x0800B758 ——
0x08004880/0x08008A5C 只对 `item==5 (ID)` 调 `rf_set_id`，item==6 不调。
若要求「切换 KEY 立即换同步字」，需要在 W3 路径加一段「item==6 时 `bl 0x0800B758`」的 hook
（约 8~12B，需另找空间或用核心补丁在 RF 收发路径读取标志）；本原型未做，当前行为是**下次 RF 初始化/改 ID 后生效**。

建议方案（待继续）：

1. 按实拍 `F1..Fn` 编号机制，新项显示 **`F8`**（F 段 + 数字段已证实可显示），值 `ON`/`OFF`；
   NOTES 说明「F8 ON/OFF = 私有密钥开关」。
2. 先定位 C.Fn 项表/最大项数（ui_menu_task 的索引比较、以及各页渲染函数中的 F 编号段绘制点），
   把上限 +1；在 16B 段码位图里复用 `F` + 数字段 + `ON`/`OFF` 段绘制。
3. 存储：在 0x20000418 镜像 / 0x20000464 参数块的保留位找空闲位（8×u32 中待逐位确认引用），
   或利用 settings_validate 的上限表扩展一个 0/1 项。
4. 截图：需要先把 16B 段码位图映射为像素（段位到玻璃布局的对照表尚未反推）；
   当前模拟器能拿到 0x20000408 的内容，把该缓冲区按段位解码即可出图，属可完成工作。
5. 注入空间与代码量：待 C.Fn 绘制/导航改法确定后评估；若 93B 洞不可用，需要在既有函数内腾空间（同 AD100 思路）。

## 4. 给合并者的最小改动建议（devices/ad100.py）

1. 在 `devices/ad100.py` 中新增 `apply_ui` 调用：先执行原核心同步字补丁，再叠加本 UI 补丁（两者补丁区互不重叠：
   核心补丁 0x0800B758..0x0800B78F；UI 补丁 0x08003F10/0x08003FA2/0x0800490C/0x08008A8A/0x08004F88）。
2. 同步字函数改为：`sync = (*(u8*)0x20000486) ? KEY : 50024/(id+1)`。
3. 建议同时把「KEY 切换后立即调一次 0x0800B758」作为后续增强（本原型未做，见 §1.6-4）。
