# keypatch/dev/x2tc —— X2T-C 补丁决策记录（2026-11-11）

> 固件：`X2TC_Z02_V1.01.bin`（79,748 B，G3 V2.0 容器，payload 79,704 B，base 0x08005000）
> 模块：[`keypatch/devices/x2tc.py`](../../devices/x2tc.py)
> 设备档案：[`devices/x2tc/README.md`](../../../devices/x2tc/README.md)

## 1. 目标

给 X2T-C 引闪器加「私有 2.4G 同步字」，并**用 C.Fn 菜单项做开关**（用户要求「改用 C.Fn」），
与 V1C / V860III / V1S 的灯端方案保持同一语义：

* C.Fn `LIGHT = ON` → 同步字 = 私有 KEY；
* `LIGHT = 12sec`（出厂默认）/ `OFF` → 原厂 `50024/(ID+1)`。

## 2. 为什么是 LIGHT（index 14）

1. `settings[14]` 的读者只有三处：背光任务 `0x08005824`（决定 12sec/OFF/ON）、
   C.Fn 渲染、参数打包；复用代价仅是「背光时间固定 12sec」。
2. 官方 X2T 说明书的 C.Fn 表：SYNC、BLUE.T.、BEEP、ZOOM、SCAN、CH、ID、PC SYNC、
   DELAY、SHOOT、DIST、STEP、GROUP、STBY、**LIGHT**、LCD（X2T-C 无 AFOPT）；
   开机解压出的最大值表 index14=2 与 LIGHT 的三档完全对应。
3. item 5=CH / 6=ID / 14=LIGHT / 15=LCD 由代码与最大值表双重印证
   （CH max 31、ID max 99、LCD max 6 且 LCD 是唯一钳位不回绕项）。

## 3. 补丁点与理由

| # | 地址 | 改动 | 理由 |
|---|---|---|---|
| 1 | `0x0801184C`..`0x08011883` | 56 B 整函数改写 | 原函数正好 56 B，50024 字面量在 +0x34（与 V1C 布局完全一致）；去掉 SCAL+1ms，只写 SYNC1/0 |
| 2 | `0x08005824` | `80 7b` → `00 20` | 屏蔽 LIGHT 原厂读者（背光固定 12sec），避免 ON 档把背光常亮 |
| 3 | `0x080073B4` | 4 B → `BL 0x08005010` | 参数打包入口；C.Fn 改值约 2 s 后自动保存会走到这里，保存前重设同步字 |
| 4 | `0x08005010` | 28 B 注入 | Cortex-M0 向量表保留槽 vec[4..10]，28 B 全 0 无引用；复现原函数头两条指令并调 sync |
| 5 | 容器 footer | 重算 MD5 | 原厂文件是 G3 V2.0 容器，MD5 必须随 payload 更新（长度/名字/魔数不变） |

## 4. 为什么不用其它开关/位置

- **CH/ID**：主界面语义，不能牺牲；
- **BEEP**：默认为 ON，用作密钥开关会出现「刷完即密钥模式」的隐式状态，不直观；
- **PC SYNC / DIST / STEP / STBY**：会影响同步口方向、射频距离档、功率步进或休眠，代价大；
- **新增 UI 项**：该固件 UI 用外置字模 + 固定页布局，新增项风险远高于复用现有 C.Fn 项。

## 5. 为什么 hook 放「保存前」而不是每次按键

- 代码区没有可用空段（唯一 0x00 段都在字模/资源数据里）；
- 向量表保留槽只有 28 B，放不下「增量+减量」两个入口的即时 hook；
- 保存前置 hook 一次调用成本极低、上下文安全（主循环、非 ISR），
  且 C.Fn 改值后 2 s 内必然触发自动保存 → 体验上是「改完即生效」；
- 开机 RF 初始化也会调用同步字函数，因此重启后状态正确。

## 6. 风险 / 未验证项

- **无实机验证**；首次刷入请先确认 G3 能识别设备并准备原厂回滚包；
- **开机默认参数路径也会经过 pack hook**：`0x0801004C` 在找不到有效参数记录时会走
  `0x08007DD0` 出厂默认 → 在 `0x08007E7C` 调 pack（→ 本 hook）。此时 CC2500 的
  SPI/GPIO 可能尚未初始化：STM32F0 上读未开时钟的 GPIO 返回 0，`0x08015DFC` 的
  等待循环会立即退出，随后的 GPIO 写入被忽略，不会挂起/跑飞；RF 初始化函数
  `0x08007D30` 之后还会重新调用同步字函数写入正确同步字。**该判断为静态分析结论，
  无实机验证**；
- 去掉 SCAL + 1ms 延时是相对原厂唯一射频差异（只改同步字不改频率，理论上不需要重校准；
  若实机出现偶发首包丢失，优先怀疑这里）；
- LIGHT 原厂「背光时间」功能被固定为 12sec 档（菜单项只剩密钥开关语义）；
- 若 C.Fn 里看不到 LIGHT 或无法切到 ON，说明该版本菜单项布局与静态结论不符——
  只需把 `FLAG_IDX` 改成实测 item 索引（`settings` 基址不变）并重跑 verify；
- 容器 MD5 必须重算（模块已处理），否则 G3 解析失败。
