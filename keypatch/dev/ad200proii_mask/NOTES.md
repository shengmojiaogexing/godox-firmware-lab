# ad200proii_mask 开发记录

> 作者：夕梦

## 1. 结论

AD200 Pro II（V1.05）的同步字函数在 `0x0800D224`，`sync = 50024 / (ID + 1)`。
把函数头 4 字节换成 `B.W` 跳进空白区，在那里读设置结构体 `0x200009B4 + 0x13`
决定用私有 KEY 还是原厂公式。**44 字节，长度不变。**

## 2. 关键地址

| 符号 | 地址 | 说明 |
|---|---|---|
| `SYNC_FUNC` | `0x0800D224` | 同步字函数入口（`push {r4,lr}`） |
| `HEAD_ADDR` | `0x0800D226` | 被替换的 `movw r1,#0xC368` |
| `HEAD_END` | `0x0800D230` | 原厂流程恢复点 |
| `CAVE_ADDR` | `0x0805BF1A` | 代码洞（942 B 全 `0xFF`） |
| `SETTINGS_ADDR` | `0x200009B4` | 设置结构体基址 |
| `MODE_OFFSET` | `0x13` | 模式字节 |
| 写寄存器 | `0x08018EB4` | `WriteReg(reg, val)` |
| delay | `0x08011962` | `delay(ms)` |
| strobe | `0x08018F80` | `SCAL/strobe` |

## 3. 推导过程

1. 同步字调用点 `0x08001DC2 ldr r0,[pc,#0x18]` → 字面量 `0x08001DDC` = `0x200009B4`；
   `0x08001DC4 ldrb r0,[r0,#0x12]` 取 ID；`0x08001DC6 bl 0x0800D224` 算同步字。
2. 同一结构体 `+0x13` 字节由参数流程载入，初值在 `0x08001E2C` 写 0。
3. 该字节只在开机初始化时读一次 → 运行中改不重算，必须重启。
4. 实机确认：`+0x13` 值 `>= 2` 时用密钥、`< 2` 时原厂公式。

## 4. 为什么不用别的方案

| 方案 | 结论 |
|---|---|
| C.Fn F8（AD200 Pro 的做法） | 本设备菜单里没有 C.Fn 项 |
| ID=99（同设备另一模块） | 占用 ID，且用户要求不靠改 ID |
| 长按键切换 | 本设备长按多绑定原厂功能（关机/菜单），冲突大 |
| 改 `set_sync` 计算段 | 可行但发送路径相关，实测易破坏发射总线 |

## 5. 踩坑

- `movw` 编码注意 `i` 位：h1 的 bit10 与 h2 的 imm3 要分开算；用 capstone 反向确认了
  `0xD4EC / 0xA1B2 / 0x8000 / 0x0325 / 0xFFFF` 五个值都编码正确。
- 代码洞必须校验全 `0xFF`，否则拒绝写入（防止版本不符时写坏别处代码）。
- `verify()` 里逐字节比较时不要每字节重新读盘，缓存一次原厂镜像即可。
