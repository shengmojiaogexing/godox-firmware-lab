## 1. 页面/窗口架构（全部有地址证据）

### 1.1 UI 库是自研 widget/WM 库（不是 emWin）
一套对象模型：每个控件 = 堆对象（句柄是高地址 RAM 指针，如 0x2004xxxx），
父窗口用 `[obj+4]` 链起来，绘制由控件的 callback `[obj+0x10]` 完成
（`FUN_0802EB88` 是"向上层窗口投递消息"，会沿父链找 callback）。

| 地址 | 作用 | 参数（实测/反编译） |
|---|---|---|
| `0x08010ACC` | 建窗口/对话框 | (parent, type, x, y, w, h)；type 9 = 根对话框 |
| `0x08006220` | 建磁贴/按钮类控件 | (parent, type, x, y, w, h) |
| `0x0802553E` | 建文本控件 | (parent, type, x, y, font, color, fmt_ptr)，文本走 sprintf 格式串 |
| `0x0802D97A` | 设控件文本 | (widget, str_ptr, 0) |
| `0x080312xx/080313xx` | 设字体/颜色/尺寸/边框/圆角 | 见 `FUN_080079E8` 里大量调用 |
| `0x0802DA22` / `0x0802E2D2` | 显示 / 隐藏（带 flag 位） | (widget, flags) |
| `0x0802DB44` | 把控件挂到父窗口 | (widget, type, x, y) |
| `0x08027D90` / `0x08027FB8` / `0x08027FE0` | 取字体/颜色/动画值 | — |

坐标系：**屏幕 368×448（0x170×0x1C0）**，左上原点，y 向下；
窗口按父窗口相对定位；底部页签在 y=0x155(341)。

### 1.2 页面 = 函数分发（不是表驱动）
页面切换器 = **100 ms 软定时器回调 `0x08014B28`**（`FUN_08014b28`，size 2042）：

- 注册点：`FUN_080358FC`（main 里调用）→ `FUN_08033500(cb=0x08014B29, period=100, 0)`，
  定时器链 `FUN_080336CA/0x08033570`，tick 源 = `FUN_080334D8` 读 RAM `0x20000310`。
- RAM 变量：`0x200003E7` = 当前页面/模式（`*DAT_08014f0c`）、
  `0x200004C4` = 请求页面 id（`*DAT_08014f3c`）。
- 分发（`0x08014B28` 内 `0x080154xx` 附近）：页面变了就
  `FUN_08014B28` → 隐藏旧窗 → 调对应页面构建函数：
  - **页 0** → `FUN_080345B4(0)`（0x080345B4，size 1104）
  - **页 1** → `FUN_0800FE78()`（0x0800FE78，size 226）= **首页（快捷面板）**
  - **页 2..13** → `FUN_08006F0C(win, page)`（0x08006F0C，size 9716）= 巨型 switch，
    每个 `case N` 一个页面的控件树。
- 页面构建完后 `FUN_0802E2D2(win, 0x10)`（显示/重绘）、`*0x200004C2 = 6` 等收尾。

### 1.3 首页（快捷面板）= `FUN_0800FE78` → `FUN_080079E8`
`FUN_0800FE78`（页 1）：
```
*0x20000034 |= 0x80;  *0x200003E7 = 1;      // 标记"当前页=1"
FUN_0802B798(*(u32*)0x20000470);            // 销毁旧页面（0x20000470 = 当前页窗口句柄）
root = FUN_08010ACC(0, 9, 0, 0, 0x170, 0x1C0);   // 根对话框
FUN_08010ACC(root, 0, 0, 0, 0x170, 0x28);        // 顶栏
FUN_0800E168();                                  // 状态栏图标
content = FUN_08010ACC(root, 2, 0, 0x28, 0x170, 0x198);
FUN_0800F4BC();                                  // 背景
FUN_080079E8(root);                              // ★ 主菜单/快捷面板
FUN_08032078(root, 6, 200, 0, 1);                // 淡入动画（依赖 tick）
FUN_0802E2D2(root, 0x10);  *0x200004C2 = 6;
```

`FUN_080079E8`（0x080079E8，size 2102）建的控件（**和用户实拍图完全对得上**）：

| 控件 | 调用点 | 位置/尺寸 | 实拍对应 |
|---|---|---|---|
| 根/滑出页 | 0x08007A02 / 0x08007A3E | (0,0,368,448) / (0,-50,368,548) | 整屏 + 上滑面板 |
| 内容面板 | 0x08007AA4 | (0,12,344,320) | 中间区域 |
| 磁贴1（声音） | 0x08007B10 | (0x28,0x28,0x6C,0x6C) = (40,40,108,108) | 左上圆形喇叭 |
| 磁贴2（造型灯） | 0x08007C1A | (-0x28,0x28,0x6C,0x6C) | 右上圆形灯泡 |
| 宽磁贴（锁） | 0x08007D52 | (0x28,0xAC,0x108,0x6C) = (40,172,264,108) | 中间锁条 |
| 底部页签1 | 0x08007E8C | (0x0B,0x155,0xA8,0x5C) | 「频闪/Multi」 |
| 底部页签2 | 0x0800808A | (0xBB,0x155,0xA8,0x5C) | 「设置/Setting」 |
| 底部小条 | 0x08008230 | (0x8A,0x1B2,0x5C,6) | 底部指示条 |

底部页签文本是条件选择（`*0x200003E7` 决定左页签显示"频闪"还是"主界面"），
字符串用 **ADR** 引用：`0x08008268 频闪 / 0x08008270 Multi / 0x0800827C 主界面 /
0x08008288 Home / 0x080082A0 设置 / 0x080082A8 Setting`（ADR 站点 0x08007F78/0x08007F9C 等）。

### 1.4 字符串引用方式：Thumb ADR（±4KB）
- 固件用 `ADR`（`add rX, pc, #imm` / Thumb-2 ADDW）取邻近 rodata，**没有字符串 ID 表**。
- 我写了全镜像扫描器 `x3c_util.adr_scan()`：1496 处 ADR 站点，可做"字符串↔函数"映射
  （`string_users()`）。
- **推论**：新增字符串必须放在引用它的代码 ±4KB 内。注入区 0x080F0000 自成一区，
  代码与字符串（0x080F0400）相距 < 1KB → **ADR 可达，可行**。

### 1.5 新增一个菜单项要改哪些点（结论）
1. **控件创建**：在 `FUN_080079E8`（快捷面板）或 `FUN_08006F0C`（其他页）里加一次
   `FUN_08006220(parent, type, x, y, w, h)` + `FUN_0802553E(...)`；
   需要 4 字节 `bl` 注入点 → 用"接管现有创建块"（把一段 8~18 字节的原指令搬到注入区，
   原地改成 `bl 注入函数`），注入函数补建原控件 + 新控件。**方案已设计，未验证**（§5.3）。
2. **页面分发**：新页面 id 14 → 在 `FUN_08006F0C` 的 switch 前加 8 字节比较/跳转，
   或在 `FUN_08014B28` 的分发链里加分支 → 跳注入区页面构建函数。
3. **字号/文本**：新中文必须自绘点阵（见 §4.2），用 UI 库的位图/图标路径或用
   LCD 绘图原语逐行填（§4.3）。
4. **触摸命中**：见 §5.1（阻塞项）。
5. **状态持久化**：见 §3。

## 2. 绘制 API / 坐标系 / 字形

- 屏幕 368×448 RGB565，8080 总线在 XMC `0x6C000000`（A0=0 命令 / A0=1 数据）：
  - `0x08025E94`：写 A0=0（命令选择），`0x08025E9C`：写一个数据字节（`strb r0,[0x6C000001]`）。
  - 命令：0x2A 列窗口 / 0x2B 行窗口 / 0x2C 写显存 / 0x36 MADCTL / 0x3A COLMOD。
- 绘图原语都在 0x08025xxx~0x0803xxxx：`FUN_0800CE2C`（LCD 驱动）、
  `FUN_080374B0`（刷新）、`FUN_08014418`、`FUN_0801C198`。
- 文本：字体对象在资源区（例：`0x0806B090`、`0x0806D364`、`0x0800EC910`、`0x080DB268`），
  结构前两个 word 是渲染函数指针（`0x0802AF19` / `0x0802AE31`）；
  `FUN_080220E0(font, codepoint)` = 按码点查字形（分组表：每项 20 字节，
  `[0]=起止码点`、`[+8]=字形表基址`、`[+0x12]=bit0-8 数量 / bit14-15 flags`）。
- **图标也是"私用区字符"**：快捷面板磁贴的图标文本 = `0x08007E20` 处的 3 字节
  UTF-8 `EE A4 80`（U+E900 私用区），即"图标字模"。→ 自绘汉字点阵有两条路：
  (a) 找到"按字形指针直接绘制"的 API（未定位到公开入口）；
  (b) 用自己的 LCD 填矩形原语逐行画（最稳，已可注入代码实现）。

## 3. 设置持久化（重要发现）

**X3-C 用 flash 页 0x080F7800 存设置，RAM 里有一份 0x400 字节的扇区副本。**

| 项 | 地址/值 | 证据 |
|---|---|---|
| 设置 flash 页 | **0x080F7800**（镜像里当前全 0xFF = 擦除态） | 字面量 0x080F7800 出现在 0x0801139C、0x08017214、0x08021720、0x080217A8、0x08021A28 的池里 |
| 设置魔数 | **0x4B3C2D1E**（页首 4 字节） | `FUN_080112E8` 池 0x080113A0 |
| 有效标记 'Z' | **RAM 副本 + 0x87** | `if (*(char*)(iVar3+0x87) == 'Z')` |
| RAM 扇区副本 | **0x20000D84** | `FUN_080112E8` 池 0x080113A8 |
| 加载/校验 | `FUN_080112E8`（main 第 40 行调用）、`FUN_080171C0`（重新加载） | 反编译见 `devices/x3c/re/.../0x080112e8_*.c` |
| 扇区扫描 | `FUN_08021778(page)`，page 0..13（`FUN_080112E8` 里 `0xd - uVar4`） | 反编译 |
| 写回/保存 | **`FUN_080219E4`**（加载失败时把默认值写回，即保存函数） | `FUN_080112E8` 失败分支 `FUN_080073F0(); ... FUN_080219E4();` |
| 默认值 | `FUN_080073F0`（16 组 × 6 字节 = group/power/model 等） | 反编译 |
| 另一数据页 | 0x080F7000（被 `FUN_08010C8C` 引用，疑为工厂校准/参数） | 字面量池 0x080110B0 |
| 升级相关 | `FUN_0801FFFC` 用 0x080F7000 作"升级请求"标记页 | 反编译 `0x0801fffc` |

→ **持久化 KEY_ON 的正路**：把 KEY_ON 放到"设置扇区副本里一个未被使用的字节"，
改完调用 `FUN_080219E4()` 写回 flash；上电时 `FUN_080112E8` 会自动把扇区读回 RAM。
**待办**：需要把设置扇区的字段布局逐字节确认（`FUN_080073F0` 默认值写入的 RAM 变量池
可以反推字段范围）。**本原型先用 RAM 版（重启复位），见 §4.1。**

## 4. 原型实现（本目录代码）

### 4.1 KEY_ON 标志（RAM 版）
- 地址：**`0x20001080`**（可用 `opts["key_flag"]` 覆盖）。
- 语义：`1` = 密钥模式（fw-x3c 双发：先私钥 SYNC 帧，再按当前 ID 发普通帧）；
  `0` = 原厂单发。**上电默认 0（关）**。
- 选址证据（按 Lead 要求逐条）：
  1. 全镜像 4 字节对齐字面量扫描：**没有任何字面量落在 0x20001080..0x20001083**
     （最近的是 0x20001048 和 0x20001117）。
  2. 40,000,000 指令的模拟器运行（含启动 + 主循环 + 全部初始化）写内存追踪：
     `0x20001080` 只有 **1 次**写（`__scatterload` 的 .bss 清零），之后从未被写；
     而同区内的 `0x20001148/0x20001158` 有 25 次写（说明扫描能区分"活变量"）。
  3. **不再使用 0x200004D0**：Lead 指出它被 3 处字面量引用，我已复核确认
     （字面量 0x200004CD、0x200004D0 覆盖 D0..D3）。
- 风险：`0x20001080` 距 `0x20001048`（一个结构体基址）+0x38，理论上可能是该结构的
  未用字段；若后续发现冲突，改 `opts["key_flag"]` 一行即可（补丁字节会跟着重算）。

### 4.2 自绘字模 + 标签
- `0x080F0200` 起：5 个 24×24 1bpp 点阵（密/钥/广/播/全），每字 96 字节
  （`GLYPH_ROWS=24` 行 × u32，MSB 在左，bit=1 亮），共 480 字节。
  直接来自 `keypatch/dev/lead/glyphs24`，`load_glyph()` 读入。
- `0x080F0400` 起：UTF-8 标签 `密钥\0广播\0全频道\0全ID\0KEY ON\0KEY OFF\0`（45 字节）。
- 设计稿（用同一批点阵 + 原厂布局常量渲染，**不是固件渲染**）：
  `shots/mock_home.png`（快捷面板：原厂声音/造型灯/锁 + 新增「密钥」「广播」两个磁贴 +
  底部三页签）、`shots/mock_broadcast.png`（广播页：全频道 / 全频道+全ID / 开始 / 取消）。
  生成器：`ui_mock.py`。

### 4.3 注入代码（0x080F0000 区，全部已 Unicorn 验证）
| 偏移 | 符号 | 大小 | 作用 |
|---|---|---|---|
| +0x000 | `ui_key_toggle` | 20 B | 翻转 KEY_ON，返回新值 |
| +0x020 | `ui_broadcast_allch` | 56 B | 32 频道广播：set_channel → SYNC=KEY → send_property(0x50,0xB1,0) → send_short(0x09) |
| +0x100 | `ui_broadcast_allid` | 88 B | 全频道 + 全 ID 扫描（32×10 帧） |
| +0x200 | glyphs24 | 480 B | 5 个汉字点阵 |
| +0x400 | labels | 45 B | UTF-8 标签 |
| +0x800 | 预留 | — | 以后放"页面构建函数"（远端注入） |

调用链（注入代码用的固件函数）：`SET_CHANNEL 0x08014814`、`WRITE_REG 0x08023540`、
`SEND_PROPERTY 0x0801184C`、`SEND_SHORT 0x080118B0`、`SET_SYNC 0x08014864`。
与 fw-x3c 的注入区不冲突（fw-x3c 用 0x080EE000 起 216 B；本补丁只用 0x080F0000..0x080F04FF，
**且不改任何原厂字节**——`verify_ui` 断言"区外差异 = 0"）。

## 5. UI 接线（设计完成、未验证）

### 5.1 触摸命中链：**未定位**（阻塞项，证据如下）
已排除/已检查：
- **没有 I2C 触摸驱动**：全镜像 4 字节字面量里 **0x40005400/0x40005800/0x40005C00
  （I2C1/2/3）一个都没有**。
- **没有 SPI2/3 触摸驱动**：SPI1 是 CC2500 通道（0x08012890/0x08012910 等 RF 函数用它），
  SPI2/3 各只有 1 处引用。
- **LCD 总线是只写的**：全镜像只有 5 处把 0x6C000000 实体化（`FUN_08025E94/9C`、
  `FUN_08035BC4/08035BE8`、`FUN_08015B38`），都是写；没有 `ldr` 从 0x6C000000 读回
  （触摸若挂在同一 8080 总线上就必须有读路径）。
- **没有触摸控制器初始化代码/字符串**（FT6xxx/GT9xx/CSTxxx 均无字符串；
  未知外设 MMIO 在模拟器里也是 "(none)"）。
- 已排除的"像触摸"的任务：`FUN_0800CC30` = **物理按键扫描**（GPIOB 0x200/0x100/0x8000，
  消抖后写入 mask 字节）、`FUN_08005D64` = 电池/ADC 任务、`FUN_08012540/08012890/08012910` = RF。
- Ghidra 漏识别的函数区间（可能是触摸驱动所在）：
  `0x080062E2..0x080067D4`（1266 B，含单拍/群拍文本）、`0x08011B12..0x0801238F`（2174 B，
  含 SCAN/Wireless Sync 文本）——这两块还没逐条反汇编。

**影响**：无法把"点击磁贴"接到触摸上；但**页面构建 + 视觉 + 逻辑**可以独立验证，

### 5.3 底部页签 2→3（已给出字节级补丁点，默认不启用）
`FUN_080079E8` 的两个页签创建调用：
- `0x08007E8C`：h=`movs r0,#0x5c`@0x08007E7A；w=`movs r1,#0xa8`@0x08007E7C；
  y=`movw r3,#0x155`@0x08007E82；x=`movs r2,#0xb`@0x08007E86
- `0x0800808A`：同 h/w/y；x=`movs r2,#0xbb`@0x08008084

三按钮布局（宽 0x6E=110、间距 8）：
```
0x08007E7C  a8 21 -> 6e 21     (w=0x6E)
0x0800807A  a8 21 -> 6e 21     (w=0x6E)
0x08008084  bb 22 -> 81 22     (x2 = 0x81；第三个 x = 0xF7)
```
（`ui_patch.py: MENU_LAYOUT_PATCH`，`enable_menu_patch=True` 时写入并做原始字节校验。）

**第三个按钮的创建**需要 4 字节 `bl`：建议把 `0x08008078..0x08008089` 这 18 字节
（原第二个按钮的参数装载 + `strd` + `bl FUN_08006220`）搬到注入区，原地改成
`bl 0x080F0800`；注入函数里补建"第二个按钮（新 x）"+"第三个按钮（x=0xF7）"
并按原样设置字体/颜色/文本（文本指针用 `0x080F0400` 的 UTF-8 标签）。
这是标准函数劫持，风险中等；**必须先有模拟器页面渲染能力再做，否则等于盲改 → 砖机风险。**

### 5.4 退化方案（若触摸最终不可改）
- **广播**：长按 TEST（`FUN_0800CC30` 的按键 mask，物理按键）+ 计时 → 调
  `ui_broadcast_allch()`，用屏幕 toast 提示。
- **密钥开关**：复用现有 ID 菜单（ID=99 = 密钥模式）或设置页项。
- 这两个退化方案都能**只改注入代码 + 一个按键任务分支**，不碰页面系统，风险低。

## 6. 模拟器验证现状（为什么 UI 没截到固件真图）

已用 `devices/x3c/emu` 的 Unicorn 模拟器跑通：
- 启动 → LCD 初始化 → 开机电池图（`shots/ui_boot_10000000.png`，真固件渲染）；
- 24M 指令内进入 **main 主循环**（PC 落在 `0x080335BC` 定时器轮询 / `0x080334E4` get_tick；
  以"主循环等待标志 0x20000004 被消费"判定），3.3 秒跑完 24M 指令。

**缺口 1：TIM7(IRQ55) 1 ms 节拍未建模。** 主循环 `do{...}while(*(u8*)0x20000004==0)`
等这个节拍；我用"每 chunk 注入 tick + 置标志"绕过（`probe_ui.py`）。
**缺口 2：显示器/页面状态机没被驱动。** 上电后屏幕停在开机 logo，
`*0x200003E7`（当前页）始终 0；手工把 `*0x200004C4=1` 也不会触发页面切换，因为
UI tick 的前置条件没满足（`*0x200003E7` 不为 2，那是"UI 已激活"状态）。
**缺口 3：直调页面构建函数会失败。**
- `FUN_0800FE78()` 入口 `FUN_0802B798(*(u32*)0x20000470)`：0x20000470 = 0 → 空指针解引用。
  手工建一个根窗口塞进 0x20000470 后，改为在 `FUN_0802EB88`（投递消息）沿父链找 callback
  时读到 0 → `blx r0` 跳到 0（CFSR=0x3 / HARD FAULT）。
- 跳过老的销毁+动画调用（把 0x0800FF44 的 `bl 0x08032078` 改成 nop）后仍会在
  约 20.7M 指令处 `pc=0` 空调用 → 说明**控件绘制/字体路径上还有全局状态没初始化**
  （属于显示器状态机，不是页面函数本身）。
→ **结论：当前模拟器无法渲染任何真实页面**；这也是 UI 接线暂不写入补丁的原因。
Lead 已安排 emu-tmr7 补 TIM7，补齐后本探针（`probe_render.py`）可直接复用：
`boot → 建根窗口 → 调页面函数 → 解码 LCD 出 PNG`。

### 10.2 工作方式（为什么这样改最可能一次成功）

* **挂载点选在 `FUN_080079E8` 的尾部**（`bl 0x08027fe0`，0x08008236）。
  该点上下文已知：`r4` = 刚建好的底部指示条控件、`r6` = 滑出面板窗口（磁贴父窗口），
  原指令只负责"取一个颜色"。
* 注入函数 `ui_quickpanel_ext()` 做法：
  1. `push {r4,r5,r6,lr}`（16B，保持 8 字节栈对齐；r4/r6 被调用者后续继续使用，必须保存）；
  2. 先执行原语义 `FUN_08027FE0()`（颜色存 r5）；
  3. 两次调用 **完全相同的原厂 API**：
     `FUN_08006220(parent=r6, type=1, x, y, w, h)` + `FUN_0802D97A(tile, "KEY"/"BCAST", 0)`；
  4. `return r5`（颜色）。
* 新磁贴参数：`(40,288,128,44)`、`(176,288,128,44)` —— 位于"锁"宽磁贴
  `(40,172,264,108)` 下方、底部页签 `y=341` 上方的 **44px 空隙**，与既有控件不重叠
  （内容面板 y=12..332 内）。type=1 与原厂磁贴一致（同一套 WM 分发路径）。
* **动作接线**：磁贴点击事件的派发在 WM 内部（属性 id 9 = type 决定行为），
  而 v1 的"按下→动作"尚未接线（见 §10.5 风险 1）。动作函数本身已注入并验证
  （`ui_key_toggle` / `ui_broadcast_allch`），只差"谁在按下时调用它"。

## 11. v1.1 追加：磁贴点击 → 动作接线（完成）

> 目标：让快捷面板新增的 KEY / BCAST 磁贴"点了有反应"。
> 结果：**注入 + 桩验证全 PASS（17/17）**，仍属"无实机验证"。

### 11.1 按下状态读取（与固件等价）
- 按下判定 = `(*(u16*)(widget + 0x28) & 8) != 0`，与固件 `0x0802FCB6(widget, mask)`
  （`ldrh r0,[r0,#0x28]; ands r0,r1`）等价；`0x0800BA4C` 里用 `mask=8` 判断控件激活。
- 边沿检测：last-state 字节 **0x2000108C（KEY）/ 0x2000108D（BCAST）**，
  按住只触发一次，松开后清零可再次触发。
- 注：上一版试过 `0x080303B8`（Lead 更正：那是"控件树成员检查"，不是按下状态），已弃用。

### 11.2 注入布局（新增 2 段）
| 地址 | 大小 | 内容 |
|---|---:|---|
| 0x080F0900 | ~120B | `ui_tiles_poll()`：句柄非空 → 读 `[h+0x28]&8` → 边沿触发 `ui_key_toggle` / `ui_broadcast_allch` |
| 0x080F0A00 | 16B | 页 1 入口跳板：`push {r0-r3,lr}; bl 0x080F0900; pop {r0-r3,lr}; <原首指令 4B>; b.w 0x0800FE7C` |
| **0x0800FE78** | 4 | `b.w 0x080F0A00`（页 1 处理器入口，UI tick 每 100ms 调 0x0800FE78） |

句柄 RAM：`0x20001084` = KEY 磁贴、`0x20001088` = BCAST 磁贴、`0x2000108C/8D` = 上次状态。

### 11.3 为什么"每 tick 调用"成立
`FUN_08014B28`（100ms 软定时器回调）页 1 分支里有
`0x08014C18..0x08014C22: cmp r1,#1; bne ret; bl 0x0800FE78; b ret`
→ **页 1 每 tick 都会调 0x0800FE78**。因此把 poll 挂在它的入口即可获得 100ms 轮询，
且不改动 UI tick 本身的寄存器上下文（跳板保存 r0-r3/lr）。

### 11.4 关于"原首指令"的一处修正
Lead 给的是 `2de9f04f`（push.w {r4-r11,lr}），但**本镜像 0x0800FE78 的实际首指令是
`2de9fc41`（push.w {r2,r3,r4,r5,r6,r7,r8,lr}）**。为避免猜错，实现里由
`UI_PAGE1_ORIG_INS = "2de9fc41"` 常量 + `apply_ui` 的原始字节校验保证一致；
跳板把这 4 字节**原样搬入**再 `b.w 0x0800FE7C`。

### 11.5 反汇编（补丁后，`out/menu_evidence.txt` §八）

## 14. 实机事故复盘（v1.2.3 修正）：`ui_quickpanel_ext` 用错父窗口寄存器

### 14.1 现象
刷入 v1.2 UI 版后，X3-C **反复重启 / 自动关机**（看门狗复位）。

### 14.2 根因（Lead 实机定位 + 本任务复核）
`ui_quickpanel_ext` 在 `FUN_080079E8` 尾部（挂载点 `0x08008236`）执行，原实现假设
"进入时 r6 = 父窗口"，于是把 **r6 当 parent** 传给 `FUN_08006220`。实际该点寄存器是：

| 寄存器 | 真实内容 | 证据 |
|---|---|---|
| **r5** | 快捷面板**根窗口句柄**（正是磁贴的父窗口） | `0x08007A02 bl 0x08010ACC(...)` → `0x08007A06 mov r5,r0`；到 `0x08008236` 之前 r5 未被改写 |
| **r6** | **`0x200004C7`——一个 RAM 字节指针，不是控件** | `0x08007F38 ldr r6,[pc,#0x324]`，字面量 `0x08008260` 处值 = `0x200004C7` |
| r4 | 底部指示条控件（调用者随后继续使用，必须保持） | `0x08008234 mov r4,r0` → `0x08008240 mov r0,r4` |

→ 把 `0x200004C7` 当控件结构写（`FUN_08006220` 会给"父窗口"挂子控件、改字段），
等于**用随机数据覆盖 RAM**，破坏 UI 状态机 → 看门狗反复复位。属我们的补丁 bug，与固件无关。

### 14.3 修正（3 条指令，字节级）
| 地址 | 原（错误） | 新（正确） | 含义 |
|---|---|---|---|
| `0x080F0806` | `05 46` (mov r5,r0) | **`06 46` (mov r6,r0)** | 颜色暂存改 r6（r5 留给父窗口） |
| `0x080F0812` | `30 46` (mov r0,r6) | **`28 46` (mov r0,r5)** | 磁贴#1 parent = r5 |
| `0x080F083A` | `30 46` (mov r0,r6) | **`28 46` (mov r0,r5)** | 磁贴#2 parent = r5 |
| `0x080F0858` | `28 46` (mov r0,r5) | **`30 46` (mov r0,r6)** | 返回颜色从 r6 取 |

（与 Lead 用 4 字节临时补丁验证过的方案一致。）

### 14.4 验证（新增护栏，19/19 PASS）
桩测试现在**模拟真实寄存器上下文**：`r5 = 假根窗口 0x20042100`、`r6 = 0x200004C7`，
并在 `0x200004C4` 起放 32 字节 canary，断言：
```

       建磁贴 2 个 [(0x20042100,1,40,288,128,44), (0x20042100,1,176,288,128,44)]；

       r6(0x200004C7) RAM 未被写=True      <-- 新增护栏
```
如果以后再把 r6 当 parent，`parent` 断言 + canary 断言会同时 FAIL。

## 16. v1.4：磁贴创建点迁移 + 实机三档诊断（当前进行中）

### 16.1 第三次实机失败的根因假设（结构性，而非参数）
上一版把"建磁贴"挂在 `FUN_080079E8`（页面构建函数）内部的 `0x08008236`
（原 `bl 0x08027FE0`）。复核后确认该点有两个不可靠之处：
1. **函数边界可疑**：Ghidra 的 `FUN_080079E8` 只到 `0x0800821E`，`0x08008236`
   落在它的尾部/共享尾声区，该区 r5/r6 用途不稳定（r6=0x200004C7 RAM 指针即症状）；
2. **时机不对**：此处页面仍在构建中（尾部的底部指示条刚建），此时往窗口树插入新控件，
   会踩到 WM 尚未完成的布局/链表 —— 表现就是 RAM 被破坏、看门狗复位。

### 16.2 改法
把创建点整体迁到 **页 1 处理器 `FUN_0800FE78` 的尾部 `0x0800FF50`**：
- 原 6 字节 `ldr r1,[pc,#0x24]; movs r0,#6; strb r0,[r1]`（写 `*0x200004C2 = 6` 页面就绪标记）
  改 为 `bl 0x080F1200` + `nop`；
- 注入函数先**原样复现**那 3 条原指令，再建磁贴；
- 父窗口用 **r6**（已核实 `0x0800FEBA bl FUN_08010ACC(0,9,...)` → `0x0800FEBE mov r6,r0` = 根窗口）；
- 新增 **NULL 保护**：父窗口==0 跳过；`FUN_08006220` 返回 0 跳过（不会对 NULL 设属性）；
- 图标子控件 `FUN_0802553E`（7 参数/3 栈参数，风险最高）**默认关闭**（`opts["tile_icon"]`）。

## 17. 致命 bug 复盘 #2（v1.5 修正）：页 1 跳板的 `pop {...,pc}` 直接返回

### 17.1 现象与根因（Lead 定位，本任务复核确认）
v1.2.3/v1.3/v1.4 的实机现象（反复重启/自动关机）与**属性序列、挂载点都无关**，
真正原因是页 1 钩子写错：

```
旧跳板（0x080F1100）:
  push {r0,r1,r2,r3,lr}
  bl   ui_tiles_poll
  pop  {r0,r1,r2,r3,pc}   <-- Thumb POP 的 bit8 是 PC（不是 LR！）
                              = 把"进入时的 LR"弹进 PC → 直接返回调用者
  push.w {...}            <-- 死代码，永不执行
  b.w  0x0800FE7C         <-- 死代码
```
效果：`0x0800FE78`（页 1 处理器）**一次都没执行** → 主界面/USB 充电分支的 UI 状态
没有初始化 → 看门狗反复复位。**这解释了 A/B/C 都会"假失败"。**

> 另：Thumb 的 `POP` 只能恢复 `PC`（bit8），**不存在 `pop {... ,lr}`**；
> 想保存/恢复 LR 必须走"调用点 wrapper + 尾调用"或栈上显式 ldr。

### 17.2 正解（已实现）：调用点 wrapper
```
0x0800FE78 保持原厂 2de9fc41（不动它）
0x08014C1E:  bl 0x0800FE78   ->   bl 0x080F1100 (wrapper)

wrapper @0x080F1100（12 字节）:
  push {r4, lr}          ; 保存 r4(callee-saved) + 返回 UI tick 的地址
  bl   ui_tiles_poll     ; 每 100ms 轮询
  bl   0x0800FE78        ; 原厂页 1 处理器完整执行（它内部保存/恢复 LR）
  pop  {r4, pc}          ; 返回 UI tick
```
verify 断言（全部 PASS）：`0x0800FE78 == 2de9fc41`、`0x08014C1E == bl wrapper`、
wrapper 反汇编为 `push {r4,lr}; bl poll; bl 0x0800FE78; pop {r4,pc}`。

## 18. Fallback 设计草案：不新建任何控件（复用现有控件做入口 + 自绘覆盖）

> 触发条件：若 A 正常但 B/C 重启（即"在页 1 新建控件"这一层不可靠），直接切这套。
> 本方案**完全不调用 `FUN_08006220` / `FUN_08010ACC`**，因此不触碰 WM 的窗口树/对象池，
> 从原理上规避前几次实机重启的类别（RAM 破坏 / 布局链表 / 分配失败）。

### 18.1 入口（触发源）：只"观察"现有控件，不创建
`FUN_080079E8` 结束时把快捷面板控件句柄写进 RAM 表 **`0x20042740`**：

| 索引 | 控件 |
|---|---|
| [0] | 根窗口 |
| [1] | 上滑覆盖层 |
| [2] | 滑出面板 |
| [3] | 声音磁贴 |
| [4] | 造型灯磁贴 |
| [5] | **锁磁贴**（宽条） |
| [6] | 底部页签1（频闪/Multi） |
| [7] | 底部页签2（设置/Setting） |

"按下/激活"判定（原厂同款，Lead 已核）：`(*(u16*)(widget + 0x28) & 8) != 0`
（等价 `0x0802FCB6(widget, 8)`）。轮询在页 1 wrapper 里做（已有 `ui_tiles_poll` 框架），
**只是不再建控件**，而是读上表句柄：

```
h_lock  = *(u32*)0x20042740[5]      ; 锁磁贴
h_tab2  = *(u32*)0x20042740[7]      ; "设置"页签
h_lamp  = *(u32*)0x20042740[4]      ; 造型灯磁贴
```

### 18.2 交互语义（长按 / 双击，不抢原厂短按）
| 手势 | 动作 | 为什么不冲突 |
|---|---|---|
| **长按锁磁贴 ≥500ms** | `ui_key_toggle()`（KEY_ON 切换） | 原厂短按=锁屏/解锁；长按原厂无定义 |
| **长按"设置"页签 ≥500ms** | `ui_broadcast_allch()`（全频道） | 原厂短按=切页；长按无定义 |
| **双击"设置"页签**（两次按下间隔 <400ms） | `ui_broadcast_allid()`（全频道+全ID） | 双击原厂无定义 |
| （可选）长按造型灯磁贴 | 切换"广播范围"档位 | 原厂短按=造型灯开/关 |

实现：poll 每 100ms 采样一次按下位，维护
`press_ticks[h]`、`last_release_ms`、`edge_detect`（已有 last-state 机制），
达到阈值触发一次并"锁存到松开"，避免连发。

### 18.3 视觉反馈：直接画到面板（不经过 WM）
已确认的 LCD 8080 原语（XMC `0x6C000000`，A0=0 命令 / A0=1 数据）：
```
写命令 c:   ldr r1,=0x6C000000 ; strb c,[r1]
写数据 d:   ldr r1,=0x6C000001 ; strb d,[r1]
列窗口:     命令 0x2A + 4 字节(x_hi,x_lo,xe_hi,xe_lo)
行窗口:     命令 0x2B + 4 字节
写显存:     命令 0x2C + 连续 RGB565 字节
```
我们已有 5 个 24×24 1bpp 点阵（密/钥/广/播/全，0x080F0200 起）与 ASCII "KEY/BCAST"。
注入一个 `ui_overlay_draw()`：
1. 只重画"小区域"（例如锁磁贴右端 108×44、页签右端 90×44），不做全屏；
2. 用 `0x2A/0x2B/0x2C` 铺底 + 逐行填点阵（1bpp→RGB565 前景/背景两色）；
3. 只在 `dirty` 时画（KEY_ON 变化 / 广播触发后的 1.5s 提示），避免每 tick 闪烁；
4. 画在 **wrapper 调用完 `0x0800FE78` 之后**（即页面刚重建完），保证覆盖在正确画面之上。

### 18.4 接线（改动量很小，且都是"插一段调用"）
```
0x08014C1E: bl 0x0800FE78  ->  bl wrapper
wrapper:  push {r4,lr}
          bl   ui_tiles_poll        ; 只观察句柄/按下位，触发动作（不建控件）
          bl   0x0800FE78           ; 原厂页 1 完整执行
          bl   ui_overlay_draw      ; 仅 dirty 时画覆盖（不经过 WM）
          pop  {r4,pc}
```
注入区：`ui_tiles_poll` 扩到 ~150B、新增 `ui_overlay_draw` ~200B，都放 0x080F1000 之后，空间充足。

### 18.5 优点 / 代价 / 风险
* 优点：**零控件分配** → 不碰窗口树、不碰对象池、不碰布局链表；只剩"读 RAM + 发 RF + 写 LCD"，
  与我们已经验证过的广播/密钥后端同一风险等级。
* 代价：视觉上是"覆盖画上去"的，不是真正的 WM 控件；页面重绘/翻页时需重画（dirty 控制）；
  文字仅限我们自绘的点阵/ASCII（不能复用原厂字体排版）。
* 新风险：LCD 直写与 WM 渲染的撕裂（每 100ms 一次机会，dirty 时才写，概率低）；
  若原厂在别处也会全屏重绘，需要"每次 wrapper 之后补画"（设计已含）。
* 验证方式（无实机渲染时）：capstone 断言 `ui_overlay_draw` 里 `strb` 到 `0x6C000000/1` 的
  序列与 0x2A/0x2B/0x2C 命令常量；Unicorn 桩测把两个 LCD 地址拦下来，断言写出的
  列/行窗口范围与像素数量符合预期（点阵逐行填充的确定性输出）。

### 18.6 备选入口（若"长按锁磁贴"用户不接受）
* 底部页签 2（设置）**双击**触发广播、**长按**切 KEY——双入口都在页签上；
* 或完全走物理按键：`FUN_0800CC30`（按键扫描任务）里长按 TEST 触发广播（改动最小、最安全，
  但用户之前明确不想要"长按 TEST"作为最终入口，仅作最后兜底）。

## 21. v1.7（page-0b）：页面门 + 控件树校验 + 显式 show（修复"频闪页签重启/磁贴不显示"）

### 21.1 实机现象 → 两个修复点
1. **短按/长按"频闪"页签都会重启** → 页面切换瞬间句柄表 `0x20042740` 里的指针可能已被释放/重建，
   poll 直接 `ldrh [h,#0x28]` 踩到野指针。
2. **磁贴不显示** → 磁贴是"页面建完后追加"的子控件，需要显式 `show`（并只在主界面构建时创建）。

### 21.2 A2-p0b：poll 三道防线
```
push {r4-r6,lr}
r4 = 0x20042740                    ; 句柄表
① 页面门：*(u8*)0x200003E7 == 0 ?   ; page0=主界面；否则清零状态后直接返回
                                        （避免页面切换中途动作）
for idx in (5=锁, 7=设置页签):
   h = [r4 + idx*4]
   if h == 0            -> 清零状态, 跳过
   if FUN_080303B8(h)==0-> 清零状态, 跳过       ; ② 控件树校验（句柄是否仍在树中）
   if (*(u16*)(h+0x28) & 8) == 0 -> 清零状态, 跳过
   ... 长按计数/触发（同上版）
```
`0x080303B8` 语义证据：`FUN_08014B28` / `FUN_0800E31C` 里都是
`ldr r0,[literal]; ldr r0,[r0]; bl 0x080303B8; cbz r0, skip`（先取句柄再校验是否存在），
与"控件是否仍在控件树"一致（Lead 已复核）。

### 21.3 C-p0b：tiles 页面门 + 显式 show
```
tiles():
  if *(u8*)0x200003E7 != 0: return           ; ① 只在主界面(0)构建时创建
  parent = *(u32*)0x20042740[0]              ; 根窗口；parent==0 -> 跳过
  for each tile:
      tile = FUN_08006220(parent, 1, x, y, w, h)
      if tile == 0 -> 跳过                    ; NULL 保护
      12 个原厂 setter + FUN_0802D97A(文本)
      FUN_0802DA22(tile, 1)                   ; ② **显式显示**
      句柄存入 0x20001084/88
```
**show API 依据**（`0x0802DA22(widget, 1)` = 显示）：
```
080081f6  movs r1, #1
080081f8  ldr  r0, [r4, #4]      ; 子控件
080081fa  bl   0x0802DA22        ; 显示该子控件（builder 内部用法）
```
且有成对语义：`0x0802E2D2(w,1)` = 隐藏 / `0x0802DA22(w,1)` = 显示，
在 `FUN_08014B28` 的页面更新分支里大量成对出现（如 `FUN_0802e2d2(*puVar6,1)` 与
`FUN_0802da22(puVar6[1],1)`）。

## 22. 触摸链路取证（2 小时窗口结论）

### 22.1 ✅ 已定位：触摸采样中断 + 触摸全局 RAM
**向量表 index 34（IRQ 18）→ `0x0800510C`**（`devices/x3c/re/ghidra_exports/main/vector_table.csv`：
`vector_addr=0x08004888, raw=0x0800510D, target=0x0800510C`）。
`FUN_0800510C`（76B）就是触摸采样 ISR，反汇编如下（逐条为证）：

```
0800510c  push {r4, r5, r6, lr}
0800510e  ldr  r4, [pc, #0x48]        ; r4 = *(0x08005158) = 0x40012000（ADC1）
08005110  movs r1, #0x20
08005112  mov  r0, r4
08005114  bl   0x08018C16             ; FUN_08018C16(reg, mask) = ((*reg & mask) != 0)
08005118  cbz  r0, 0x0800512A
0800511a  movs r1, #0x20
0800511c  mov  r0, r4
0800511e  bl   0x08018C10             ; FUN_08018C10(reg, mask): *reg = ~mask（写 1 清标志）
08005122  ldr  r0, [pc, #0x38]        ; r0 = *(0x0800515C) = 0x20000164
08005124  ldr  r1, [r0]
08005126  adds r1, r1, #1
08005128  str  r1, [r0]               ; ★ 0x20000164++（触摸事件计数）
0800512a  movs r1, #4
0800512c  mov  r0, r4
0800512e  bl   0x08018C16             ; 检查结果就绪标志 bit2
08005132  cmp  r0, #0
08005134  beq  0x08005156
08005136  mov  r5, r4
08005138  movs r1, #4
0800513a  mov  r0, r5
0800513c  bl   0x08018C10             ; 清标志
08005140  movs r1, #0
08005142  mov  r0, r5
08005144  bl   0x08018DDA             ; FUN_08018DDA(dev, ch=0) -> 通道 0 结果
08005148  ldr  r4, [pc, #0x14]        ; r4 = *(0x08005160) = 0x20000168
0800514a  strh r0, [r4]               ; ★ 0x20000168 = ADC ch0 = X（u16）
0800514c  movs r1, #1
0800514e  mov  r0, r5
08005150  bl   0x08018DDA             ; FUN_08018DDA(dev, ch=1)
08005154  strh r0, [r4, #2]           ; ★ 0x2000016A = ADC ch1 = Y（u16）
08005156  pop  {r4, r5, r6, pc}
```

结论（触摸状态全局）：
| 地址 | 类型 | 语义 |
|---|---|---|
| `0x20000164` | u32 | **触摸事件计数**（ISR 在状态位 0x20 置位时自增） |
| `0x20000168` | u16 | **触摸 X**（ADC 通道 0 原始值，0..4095） |
| `0x2000016A` | u16 | **触摸 Y**（ADC 通道 1 原始值） |

辅助证据：
* `0x08018C16(reg, mask)` = `((*(u32*)reg & mask) != 0)`；
  `0x08018C10(reg, mask)` = `*(u32*)reg = ~mask`（写 1 清零），见 `0x08018C10/0x08018C16` 反汇编；
* `0x08018DDA(dev, ch)` 仅被 `FUN_0800510C` 调用（`bl_callers` 扫描：2 处，均在本 ISR）；
* 触摸坐标换算 `FUN_08005FB4`（8 次采样取比、×1000/…) 由启动流程 `FUN_08033E20`(0x08034072)
  与 ADC 初始化 `FUN_08010C8C`(0x08010FA0/0x0801106E) 调用 —— 即"电阻触摸 X/Y 比例测量"。
* ADC 设备结构体基址即 `0x20000168`（`FUN_08010C8C` 的池 `0x080110A8 = 0x20000168`），
  电池采样 `FUN_08005FB4` 也从同一结构体取两个通道结果 → 触摸与电池**共用 ADC**（分时）。

### 22.2 尚未定位：坐标 → 控件（hit-test）的消费方
* 全镜像扫描 `0x20000164/0x20000168/0x2000016A` 的字面量引用：除 ISR 自身外，
  只有 `0x08005FB4`（触摸/电池换算）与数据区（hot-shoe 区 0x080F8xxx 等）出现同值，
  没有找到"读 x/y → 比较控件 `[w+0x14]/[w+0x1c]/[w+0x18]/[w+0x20]`"的 hit-test 函数；
* 控件几何已知：`FUN_0802FC5E(w) = [w+0x1c]-[w+0x14]+1`（宽），`[w+0x18]` 为 y 起点，
  `[w+0x20]` 为高度相关（Lead 提供）；按下位判定 `0x0802FCB6(w,mask) = ([w+0x28]&mask)!=0`；
* 已排除：I2C/SPI 外设驱动（I2C 0 引用；SPI2/3 各 1 处非触摸）、bit-bang I2C
  （GPIO 读写热点集中在 LCD 8080 总线 `0x08035BC4/0x08035BE8` 与按键扫描 `0x0800CC30`）、
  未知 MMIO（`m.access.unknown` 为空）、LCD 总线读（XMC 写入序列无读回路径）。
