# Godox V860III-C（V860IIIC_V1.3.bin）C.Fn 子系统分析 —— 开关项选择、读者/持久化证据

本文分析 **Godox V860III-C V1.3** 的 C.Fn / `settings` 子系统，说明为什么复用
**item 8 `LIGHT`** 做私有密钥开关、它的全部读者/写者、默认值与持久化链路，
以及补丁为保护开关所做的 3 处屏蔽。补丁实现见
[`../../../keypatch/devices/v860iiic.py`](../../../keypatch/devices/v860iiic.py)，
总览见 [`../../../devices/v860iiic/README.md`](../../../devices/v860iiic/README.md)。

> 证据来源：`devices/v860iiic/re/cfn.py`（7 项断言，退出码 0）与其输出
> [`re/log_cfn.txt`](../../../devices/v860iiic/re/log_cfn.txt)（UTF-8）；
> 关键代码段对照见 `devices/v860iiic/re/compare.py` 与
> [`re/log_compare.txt`](../../../devices/v860iiic/re/log_compare.txt)。
> 日期：2026-11-11。

---

## 0. 一句话结论

- 设置区基址 **`0x2000108A`**：C.Fn item n = `settings[n]`，共 **12 项（item 0..0xB，3 页 × 4 行）**；
  最大值/回绕表在 **`0x080181AA`**，12 字节 `01 01 01 01 01 1f 63 01 02 06 01 01`
  → max = `1,1,1,1,1,31,99,1,2,6,1,1`；
- **item 8 = `LIGHT`**（原厂造型灯模式：0=12sec / 1=OFF / 2=ON），开关值 =
  **`settings[8]` = RAM `0x20001092`**，出厂默认 **0（12sec，普通模式）**；
- 原厂只有 **2 个功能读者**（造型灯任务 `0x080036AE` / `0x080036D6`）+ 1 处设置同步解包写点
  （`0x0800A7EA`）会影响它；补丁把 2 个读者固定 0、把解包写点 NOP 掉（见 §6）；
- 密钥语义：**`LIGHT = ON(2)` → 同步字 = 私有 KEY；`12sec(0)` / `OFF(1)` → 原厂
  `50024/(ID+1)`**；C.Fn 改值通过 10 B 注入 hook 立即重设同步字（§7）；
- 代价：原厂 LIGHT「造型灯模式」功能被复用 —— **造型灯输出固定原厂 12sec 档**，
  菜单里 LIGHT 仍显示三档，但只剩「ON = 密钥开关」语义。

## 1. 方法与可复现

```powershell
# 仓库根
tools\python\python.exe devices\v860iiic\re\cfn.py
```

`cfn.py` 做的检查（输出末行 `检查项: 7  PASS: 7  FAIL: 0`，退出码 0）：

| # | 检查 | 结果 |
|---|---|---|
| 1 | 同步字函数 `0x080122E8` 原厂 56 B 与期望一致 | PASS |
| 2 | C.Fn 最大值表 `0x080181AA` = 12 字节且与 V1C 同值 | PASS |
| 3 | `BL -> 0x080122E8` 调用点 5 处 | PASS |
| 4 | `settings[8]`（LIGHT）有静态读者 | PASS |
| 5 | `settings[6]`（ID）有静态读者 | PASS |
| 6 | `settings[8]` 有静态写者（默认值/解包/保存） | PASS |
| 7 | 存在无引用全 0 死区（≥10 B 可放 hook）：`0x080179C2`(234 B) 等 | PASS |

方法要点：先按 `ldr rX,=0x2000108A`（settings 基址）找出全部 51 处字面量引用，
再对每个种子做**函数内前向污点扫描**（跟踪基址寄存器 + 常量偏移），得到
`settings[off]` 的全部读写点；偏移未知的记为「动态索引」访问（16 处）。
C.Fn 渲染/最大值表则用「最大值表字面量引用 + 渲染函数逐项 `cmp`」交叉确认。

| `settings[2]` | `0x2000108C` | **`settings[8]`（LIGHT）** | **`0x20001092`** |

- `settings[0]..settings[0xB]` 是 12 个 C.Fn 项；

| 读 | **`0x080036D6`** | `01 7a ldrb r1,[r0,#8]` | 同上 | 功能读者 2（==2 → ON 分支） |

| 读 | `0x0800A7BC` | `09 7a ldrb r1,[r1,#8]` | 无线设置**打包** `0x0800A79C..0x0800A7CB` | 写进紧凑结构 `c[0x16]` |

| 写 | **`0x0800A7EA`** | `08 72 strb r2,[r1,#8]` | 无线设置**解包** `0x0800A7CC..0x0800A7F7` | 用收到的 `c[0x16]` 覆盖 settings[8] |
| 写 | `0x0800E18A` | `25 72 strb r5,[r4,#8]` | 设置区整体写入 `0x0800DDB4..0x0800E2A7`（函数内含 `BL 0x08006780` 默认值调用） | 整体写 settings（含恢复默认） |

## 4. item 8 = LIGHT 的三条直接证据

### 4.1 C.Fn 渲染块 `cmp #8`

`re/log_compare.txt` 中渲染函数 `0x080048B0..0x0800538F` 逐项比较：

| 地址 | 指令 | 结论 |
|---|---|---|
| `0x08004E46` | `06 28 cmp r0,#6` | item6 = ID（`0x08004E50` 起 ID==0 单独分支 = 菜单 OFF 显示） |
| `0x08004EC2` | `07 28 cmp r0,#7` | item7 渲染块 |
| **`0x08004F92`** | **`08 28 cmp r0,#8`** | **item8 = LIGHT 渲染块** |
| `0x08005054` | `09 28 cmp r0,#9` | item9 = LCD 渲染块 |

### 4.2 三档字形选择（12sec / OFF / ON = 0 / 1 / 2）

LIGHT 渲染块尾部：

```asm
0x0800500E  35 4f        ldr  r7, [pc, #0xd4]      ; r7 = =settings 基址 0x2000108A
0x08005010  50 21        movs r1, #0x50            ; 右栏绘制参数
0x08005012  38 7a        ldrb r0, [r7, #8]         ; r0 = settings[8]（LIGHT 值 0/1/2）
0x08005014  00 23        movs r3, #0
0x08005016  40 00        lsls r0, r0, #1           ; r0 = 2 * 值
0x08005018  00 1d        adds r0, r0, #4           ; r0 = 2 * 值 + 4
0x0800501A  c0 b2        uxtb r0, r0
0x0800501C  41 22        movs r2, #0x41
0x0800501E  02 f0 8f f9  bl   #0x08007340         ; 按字形索引绘制右栏
0x08005022  38 7a        ldrb r0, [r7, #8]         ; 再读一次交给显示辅助
0x08005024  00 f0 da f9  bl   #0x080053DC
```

即**值 0/1/2 → 字形 4/6/8**（`2*值+4`），是典型的三档枚举显示。
V1C 的同一段渲染由 UI 报告（真实渲染）确认右栏为 `12sec / OFF / ON`；
V860III-C 本固件没有单独做 UI 报告，**字形文本按同构推断，最终以实机菜单为准**
（见 [`../../../devices/v860iiic/docs/02_验证与实机清单.md`](../../../devices/v860iiic/docs/02_验证与实机清单.md) §3）。

### 4.3 功能读者在「造型灯任务」里

两个功能读者同在函数 `0x080036A8..0x0800379F`：

```asm
0x080036A8  f8 b5        push {r3,r4,r5,r6,r7,lr}
0x080036AA  37 48        ldr  r0, [pc, #0xdc]      ; =settings 基址
0x080036AE  00 7a        ldrb r0, [r0, #8]         ; LIGHT 读者 1
0x080036B6  01 28        cmp  r0, #1
0x080036B8  0c d1        bne  0x080036D4           ; != OFF → 继续
   ...                                                ; ==1：GPIO 关闭造型灯
0x080036D4  2c 48        ldr  r0, [pc, #0xb0]
0x080036D6  01 7a        ldrb r1, [r0, #8]         ; LIGHT 读者 2
0x080036DA  02 29        cmp  r1, #2
0x080036DC  15 d0        beq  0x0800370A           ; ==ON 分支
   ...                                                ; 12sec 分支：计时器 + GPIO
```

该函数直接操作造型灯 GPIO（经 `0x0800B952`，位 `1<<13` / `1<<14`）并按
`settings[8]` 选择模式，所以**屏蔽这两个读者 = 造型灯固定回原厂 12sec 档**。

> `re/compare.py` 同时打印了 V1C 的对应函数 `0x080036D4..0x080037CB`：
> 与 V860III-C 的 `0x080036A8..0x0800379F` 逐条指令同构（仅 BL 目标地址不同），
> 可作为「这是同一套造型灯任务」的交叉证据。

## 5. 默认值与持久化

### 5.1 出厂默认 `0x08006780..0x0800687B`

- `0x080067D0 ldr r0,=0x2000108A`（settings 基址）；
- 随后连续 `strb` 写 `settings[0..0xB]`：`0x080067D2`(+0)、`0x080067D4`(+1) … `0x080067EA`(+0xB)；
- **`0x080067DC strb r1,[r0,#8]` → `settings[8]` 默认 = 0（12sec，普通模式）**；
- 这个函数没有 BL（纯立即数写默认值），是「恢复出厂/首次上电」的默认值来源。

### 5.2 save → load

| 阶段 | 函数 | `settings[8]` 相关点 | 记录位置 |
|---|---|---|---|
| save | `0x08005FA0..0x0800618B` | 读 `settings[8]` @`0x080060DE`；`str r4,[r0,#0x34]` @`0x080060E8` | flash 参数记录 `+0x34`（记录 `+0x2C` 起依次放 settings[0..0xD]） |
| load | `0x080159D0..0x08015CDF` | `ldr r3,[r1,#0x34]` @`0x08015B02`；写回 `settings[8]` @`0x08015B10` | 同上 |

- 记录布局：`+0x2C + n` 对应 `settings[n]`，因此 settings[8] 在 `+0x34`；
- 原厂改 C.Fn 值后由原厂倒计时逻辑自动写 flash，所以 **LIGHT 的值随原厂设置持久化**，
  补丁不需要额外存储；
- 恢复出厂 = 默认值函数把 `settings[8]` 清 0 → 回到普通模式（预期行为，未 patch）。

## 6. 读者屏蔽与开关保护（3 处，为什么必要）

`settings[8]` 在原厂会被「功能读者」和「无线设置同步」读写。补丁做**最小必要**处理，
每处都先逐字节校验原厂内容（`READER_MASK_PATCHES`）：

| 位置 | 原厂字节 | 补丁后 | 作用 |
|---|---|---|---|
| `0x080036AE`（造型灯任务读者 1） | `00 7a`（`ldrb r0,[r0,#8]`） | `00 20`（`movs r0,#0`） | 造型灯任务看到 LIGHT=0（12sec），**密钥开关不影响造型灯输出** |
| `0x080036D6`（造型灯任务读者 2） | `01 7a`（`ldrb r1,[r0,#8]`） | `00 21`（`movs r1,#0`） | 同上（第二个读者） |
| `0x0800A7EA`（无线设置同步解包） | `08 72`（`strb r2,[r1,#8]`） | `00 bf`（`nop`） | **不再用收到的紧凑结构覆盖 `settings[8]`**，防止密钥开关被设置同步静默清 0 |

语义细节：

- 读者 1 被换成 `movs r0,#0` 后，紧随的 `cmp r0,#1` 不成立，直接进入 12sec 逻辑；
- 读者 2 被换成 `movs r1,#0` 后，`cmp r1,#2` 不成立，走 12sec/非 ON 分支；
- 解包函数 `0x0800A7CC` 的上游「打包」函数 `0x0800A79C` 仍会读 `settings[8]` 写进 `c[0x16]`
  （`0x0800A7BE strb r1,[r0,#0x16]`），但回写点已 NOP，**读没有副作用**；
- **有意保留**的读者/写者：菜单渲染（用户要能操作）、save/load（持久化）、
  出厂默认（恢复默认语义）。

## 7. 改值即时生效 hook（gate + 注入 + 代码洞）

### 7.1 为什么需要

原厂只有「改 ID（`cmp r1,#6`）」才立即调用同步字函数。密钥开关换成 item8 后，
**改 LIGHT 也必须立即生效**，否则要等下次 RF 初始化才切换。

### 7.2 做法

1. 代码洞 **`0x080179C2`**（234 B 连续 0x00，无任何 BL/分支/字面量引用）写 10 B 注入代码：

   ```text
   0x080179C2  1f b5        push {r0, r1, r2, r3, r4, lr}
   0x080179C4  80 79        ldrb r0, [r0, #6]          ; r0 = ID（入口 r0 = settings 基址）
   0x080179C6  fa f7 8f fc  bl   0x080122E8            ; 同步字函数（内部读 settings[8]）
   0x080179CA  1f bd        pop  {r0, r1, r2, r3, r4, pc}  ; 返回原 handler 继续
   ```

2. 两个 C.Fn 改值 gate（每处 4 B）替换成 `BL 0x080179C2`：

   | 位置 | 所在函数 | 原厂 4 B | 补丁后 4 B |
   |---|---|---|---|
   | `0x0800630C` | C.Fn 递减处理 `0x0800627C` | `06 29 08 d0`（`cmp r1,#6; beq sync`） | `11 f0 59 fb`（`bl 0x080179C2`） |
   | `0x0800D53E` | C.Fn 递增处理 `0x0800D4A8` | `06 29 07 d0` | `0a f0 40 fa` |

效果：**C.Fn 项改值**（LIGHT 密钥开关、ID、其它可编辑项）都会立即重设同步字并返回原处理函数继续；
hook 入口 `r0` = settings 基址（gate 前数据流解析值 `0x2000108A`），返回时原样恢复 `r0..r4`。

> 为什么不简单把 `cmp #6` 改成 `cmp #8`：那会让**改 ID 不再立即写同步字**（要等 RF 初始化），
> 是行为回归。加 10 B 注入 hook 是最小且不破坏原厂 ID 行为的方案。

### 7.3 代码洞安全性

- `0x080179C2..0x08017AAB` 共 **234 B** 连续 0x00；
- 检查口径：全镜像 BL/BLX 目标、B/条件分支目标、LDR(literal) 目标、按 2 字节步长扫描的
  4 字节绝对地址（含 `|1` thumb 变体）——**0 处引用**；
- 本补丁只用前 10 B，余量充足；备用洞 `0x08017C3A`（222 B，到 `0x08017D17`）在「无引用」列表内。

## 8. 为什么选 item 8（候选对比）

| 候选 | 证据 | 结论 |
|---|---|---|
| item 7（BEEP，同表参照名） | 16 个读者、7 个写者，遍布 UI/按键/显示 | 读者太多，屏蔽成本高，**不选** |
| item 9（LCD） | max=6（非 0/1），另有专用处理函数 `0x08015018` | 非布尔且专用处理，**不选** |
| item 5（CH） | max=31，射频信道 | 改它会影响信道，**不选** |
| item 6（ID） | 原厂既有语义，5 个同步字调用点都用它 | **保留原厂含义**（普通模式的 ID） |
| item 4（SCAN） | 写者 5（扫描流程会回写） | 开关可能被自清，**不选** |
| item 0–3、10、11 | 单 bit 功能，但语义不直观 / 影响发送路径 | 不选 |
| **item 8（LIGHT）** | **max=2 三档；只有 2 个功能读者 + 1 处解包写点；默认 0；`ON(2)` 语义直观** | **★ 选为密钥开关** |

> 关键取舍：`LIGHT = ON(2)` 天然就是「开」，用户看到 ON 即密钥模式；出厂默认 0（12sec）
> 是普通模式，新刷/恢复出厂不会误开密钥。代价是原厂造型灯模式功能被复用。

## 9. 风险与未确认项

| 项 | 状态 | 说明 |
|---|---|---|
| 实机验证 | ❌ 未做 | 无整机模拟器；空口同步过滤只能真机验证 |
| LIGHT 菜单文本/三档显示 | ⚠️ 静态证据 | 渲染块 `cmp #8` + 三档字形选择已在，但文本/实机操作未确认 |
| **造型灯原厂功能代价** | ⚠️ 已知取舍 | 两个读者固定 0 → 造型灯输出固定 12sec 档；C.Fn 的 LIGHT 只剩密钥开关语义 |
| 设置同步覆盖 | ⚠️ 部分保护 | 已 NOP 解包写点 `0x0800A7EA`；但另有一处整体写 `settings[8]` 的路径（`0x0800E18A`，位于 `0x0800DDB4` 函数内）未屏蔽，需实测 |
| 恢复默认会关密钥 | ℹ️ 预期行为 | 默认值函数把 settings[8] 置 0 → 回普通模式，与「恢复默认」语义一致 |

| `settings[12]/[13]` | ℹ️ 说明 | 会持久化但不是 C.Fn 项，不在 12 项范围内 |
