## 0. 结论摘要（TL;DR）

1. **settings[7] 确实是 F8（稳定色温模式）的唯一存储位置**：`0x2000041F`，没有 UI 影子副本
   （全镜像**没有**任何指令直接引用字面量 `0x2000041F`；所有访问都是 `settings 基址 0x20000418 + 7`，
   UI 结构 `0x20000150` 只存“C.Fn 打开/编辑态/当前项索引”，不存 F8 值 → BRIEF 提醒的“别混淆”成立）。
2. **settings[7] 有 8 个真实读者**（静态数据流 + 动态 read hook 双重确认，见 §2）：
   - 期望的：**C.Fn 渲染**（显示 ON/OFF，`0x08004230`）、**记录 builder**（持久化，`0x08004496`）；
   - **原厂「稳定色温模式」功能读者 6 个**（`0x08004AFC / 0x08004FF4 / 0x08005C54 / 0x08006290 /
     0x0800B144 / 0x0800B228`）：F8=1 时走**备用闪光时长/功率表**、改变功率缩放与显示、改变 RF 远程设置处理。
     实测同一档位下 `level_table_lookup_b(0x0800626C)` 返回值 **原厂 F8=1 → 360 vs F8=0 → 210**（约 1.7×）。
   - **结论：复用 F8 当密钥开关，若不屏蔽，ON 状态会真实改变闪光输出/显示/RF 上报行为**（不是纯 UI 副作用）。
     建议**屏蔽这 6 个读者**（A 组补丁，2 字节/处，见 §5），保留渲染与 builder。
3. **持久化链路复核通过（Unicorn 实测）**：builder `0x080043E4` 把 settings[4..7] 写进记录 word7
   → **记录字节 31 = settings[7]**；`0x0800B820(slot)` → `0x08005974` 把 8 个 word 写进
   `0x0801F000 + slot*100`；上电 `0x0800AC58`（扫描 slot 19→0 找 magic 0x5C）→ `0x0800590C`（拷 8 word 到
   0x20000464）→ `0x0800CCC8`（展开到 `0x20000418..1F`）。**实测 settings[7]=1 掉电重启后仍为 1**。
4. **保存触发点**：任何按键 → `ui_key_scan_task` 在 `0x080089CC` 调 `0x0800B810` 把
   `0x20000218`（countdown）置 **0xC8=200**；主循环每次调保存任务 `0x08009B38`，
   递减到 0 且“记录确有变化”才写 flash。**实测：改 F8 后第 200 次主循环落盘**；记录无变化不写 flash。
5. **上电默认值**：`0x080048E4` 实测写入 `settings[0..7] = 00 00 01 00 00 00 00 00`
   ——**F8=0 成立**，但 **BRIEF 说的“settings[0..7] 全写 0”不准确：settings[2]=1（F3 默认档）**。
6. **F8=1 会在这些地方被清 0**（除用户主动改值外）：
   - 改值函数 `-`（0x080045AC）从 1→0；`+`（0x08008504）从 1→2 超上限回绕到 0（上限表 `0x0800E314[7]=1`）；
   - **`ui_key_80`（0x0800BC34）在 `g_mode` bits4-5 由 0→1 时静默 `strb 0 → settings[7]`**（0x0800BC7E，实测可复现）
     → 复用 F8 后这是“密钥开关被悄悄关掉”的风险点，建议 B 组 NOP 阻断；
   - 长按双键恢复出厂（`ui_key_scan_task` 里 `r4==0x14` → `0x08008AAA` → `0x080048E4` 默认值）；
   - 上电加载时若记录字节 31 > 上限 1 → 被 clamp 成 0（`0x0800ADCA`，同一张表）。
   - RF 远程设置处理 **不能**改 settings[7]（它只写 settings[0]/[1]）。
7. **“切换后立即生效”缺口**：原厂改 F7(ID) 会立即重调同步字函数 `0x0800B9AC`，但改 F8 不会
   （两个改值入口都只在 `item==6` 时调 sync）。需要 C 组补丁（把两个入口的 `bne` 改成 NOP，
   使任何 C.Fn 改值后都调一次 `sync(settings[6])`），实测原厂改 F8 的 sync 调用次数=0，打 C 组后=1。

## 2. settings[7] 的全部真实读者（含“F8=1 时会发生什么”）

> 静态：`scan_refs.py` 对 26 个加载 settings 基址的函数做「基址寄存器+偏移」数据流跟踪；
> 动态：`emu_roundtrip.py` T6/T7 在 Unicorn 里装 read hook 实抓读取 PC。
> 所有读取都是 2 字节 `ldrb rX, [base, #7]`（可原位改成 `movs rX, #0` 屏蔽）。

| # | 读取指令 | 所在函数 | 角色 / 用途 | F8=1 时的行为变化 | 风险 |
|---|---|---|---|---|---|

### 2.1 “UI 结构 0x20000150 偏移访问”会不会混淆？
不会。全镜像 26 个函数加载 settings 基址后，除读者 1~8 外，其余函数只读 settings[0..6]（F1..F7）
或只写默认值/加载。UI 结构 `0x20000150` 只提供 C.Fn 菜单状态（+0x12/+0x13/+0x14），
**没有任何 UI 字段保存 F8 值**；渲染器显示 F8 时直接读 `settings[7]`。

## 3. 复用 F8 当密钥开关的副作用结论

**有副作用，且是真实功能副作用，不只是 UI：**
- 若 F8=1（=密钥开关 ON）且不屏蔽读者：闪光**持续时间**切换到原厂“稳定色温”备用表
  （`level_table_lookup_b` 实测 210→360，约 1.7 倍），功率缩放、测量换算、显示数值、RF 远程设置处理
  都会走 F8=1 分支。对“只想要私有密钥、其他行为保持原厂”的目标来说不可接受。
- **建议**：屏蔽 6 个功能读者（A 组，见 §5），保留：
  - C.Fn 渲染（0x08004230，继续显示 ON/OFF → 正好显示密钥开关状态）；
  - builder（0x08004496，持久化必需）。
- 屏蔽后实测：候选镜像启动/主循环无 fault；`level_table_lookup_b` 在 F8=1 时返回 210（=原厂 F8=0 行为）；
  builder 记录字节 31 仍=1；F8 渲染仍读 settings[7]（ON/OFF 显示保留）。见 `log_verify_candidates.txt`。

## 4. 持久化链路复核（静态 + Unicorn 实测）

### 4.1 写（保存）链

```
[任何按键]
  ui_key_scan_task 0x080089CC: bl 0x0800B810
        └─ 0x0800B810: [0x20000218] = 0xC8 (200)          ; 保存“防抖倒计时”
[C.Fn +/− 改值入口] 0x080045BE / 0x08008516 也各调一次 0x0800B810（记录见 callers.py）

主循环 main 0x0800CE9A: bl 0x08009B38                     ; 保存任务，每轮主循环调用
  0x08009B38:
    bl 0x0800B7F4        ; [0x20000218]-- ；减到 0 时 [0x20000216]=1 (save request)
    if [0x20000216]==1:
       [0x20000216]=0
       bl 0x080043E4(dest=0x20000484)     ; builder：生成 32 字节记录
       bl 0x0800C740                      ; 与镜像 0x20000464 比较；不同则复制并返回 1
       if changed:
          slot = [0x20000214]++ ; slot>=20 → 擦参数页 0x0800587C、slot=0
          bl 0x0800B820(slot)
             0x0800B820: bl 0x080043E4(0x20000484)         ; 重新 build 一遍
                         copy 8 个 word: 0x20000484 → 0x20000464 (0x20000484-0x20)
                         bl 0x08005974(0x0801F000 + slot*100)
                            0x08005974: flash_unlock(0x08006CFC)
                                        循环 8 次: flash_program_record(0x2, addr, word[i], 0)
                                                  addr += 4（失败不增）
                                        flash_lock(0x08006C6C)
```

- builder `0x080043E4` 关键指令（反汇编证据 `log_dump_persist.txt`）：
  - `0x08004474 ldr r2,=0x20000418`；
  - 读 settings[0..3] 拼 word6 → `0x08004488 str r3,[r0,#0x18]`；
  - 读 settings[4..7] 拼 word7 → `0x08004496 ldrb r2,[r2,#7]`、`0x0800449C str r1,[r0,#0x1c]`；
  - 所以**记录字节 24..31 = settings[0..7]，记录字节 31 = settings[7]**（记录 word6/word7）。
  - 记录字节 0 = `0x5C`（magic，0x080043EA/0x080043EE 写 0x5C）。
- `flash_store_params` 0x0800B820 的目标地址 = `0x0801F000 + slot*100`（0x0800B840–0x0800B848）。
- **Unicorn 实测**（`log_emu_roundtrip.txt`）：
  - T1：builder(settings[7]=1) → 记录 `5c … 11 22 33 44 55 66 07 01`，word6/7 与 settings 完全一致，字节 31=1；
  - T2：`flash_store_params(slot=3)` → 经 flash 控制器模型真的把记录写进 `0x0801F000+300`，字节 31=1，
    且镜像 0x20000464 同步更新；
  - T3：改 F8 后 `0x0800B810` 置 200，**第 200 次调用保存任务时落盘**（记录字节 31=1）；
    记录无变化时再跑 200 次**不写 flash**（slot 不递增）。

### 4.2 读（上电加载）链

```
main 0x0800CE28: bl 0x0800AC58 (settings_load_task)
  0x0800AC58:
    slot = 20 ; while slot-- > 0:
        bl 0x0800590C(0x0801F000 + slot*100)   ; flash_read_params：拷 8 个 word → 0x20000464
        if [0x20000464] == 0x5C (magic):
            bl 0x0800CCC8 (settings_validate)   ; 展开 8 个 word → 0x20000418..0x2000041F
              ; word6 → settings[0..3] (0x0800CD50–0x0800CD64)
              ; word7 → settings[4..7] (0x0800CD66–0x0800CD78)，其中 0x0800CD78 strb → 0x2000041F
            ; 然后对 UI 字段做范围修正
            ; 关键：inline clamp（0x0800ADC2–0x0800ADDA）
            ;       r2=0x0800E314; for i in 0..7: if settings[i] > table[i]: settings[i]=0
            bl 0x0800587C  ; 擦参数页（0x0801F000）
            bl 0x0800B820(0)  ; 把（夹紧后的）当前设置重新写回 slot 0
        ; 若扫完 0 个合法记录：
        bl 0x080048E4  ; 默认值：settings = 00 00 01 00 00 00 00 00（F8=0）
        bl 0x0800587C ; 擦页
        bl 0x0800B820(0) ; 写默认记录到 slot 0
```

- **Unicorn 实测**（T5/T5b）：
  - 在 slot5 放合法记录（settings `[1,2,3,0x44,2,1,7,1]`）→ 调用 `0x0800AC58` →
    RAM `settings[0..7] = 01 02 03 44 02 01 07 01`（**F8=1 恢复**），且任务末尾把记录归一化重写到 slot0（字节 31 仍=1）；
  - 把记录字节 31 改成 5（>上限 1）→ 加载后 `settings[7]=0`（**加载 clamp 生效**）。
- BRIEF 的“记录读取 0x0800AC58 → 0x0800590C → 0x0800CCC8 把记录 8 个 u32 展开”**复核正确**。

### 4.3 “F8 开关值持久化”的直接证据（一句话）
`builder 0x08004496` 读 settings[7] → 记录字节 31；`flash_store_params` 写 `0x0801F000+slot*100+31`；
上电 `settings_validate 0x0800CD78` 把记录字节 31 写回 `0x2000041F`；Unicorn 实测 1→flash→重启加载→1。✔

| # | 地址 | 文件 off | 原始字节 | 改后字节 | 含义 |
|---|---|---|---|---|---|
| B1 | `0x0800BC7E` | `0x8C7E` | `ca 71` (`strb r2,[r1,#7]`) | `00 bf` (`nop`) | `ui_key_80(0x0800BC34)` 在 `g_mode` bits4-5 0→1 时写 settings[7]=0 |

说明：key code 0x80（按键矩阵 bit7）的处理器；C.Fn 打开时它只是关闭菜单，不受影响。
实测：原厂/仅 A 组会清 0，A+B 后不再清（`log_verify_candidates.txt` V5）。
物理按键标签未确认（矩阵 3×3，键码=3*row+col 的位掩码；0x80=row2,col1）→ **推测/待 cfn-re 确认**。

### C 组：改 F8 后“立即生效”（**与 cfn-re 任务重叠，仅供 Lead 整合参考**）

| # | 地址 | 文件 off | 原始字节 | 改后字节 | 含义 |
|---|---|---|---|---|---|
| C1 | `0x0800854E` | `0x554E` | `02 d1` (`bne 0x08008556`) | `00 bf` (`nop`) | 编辑“+”`0x08008504`：任何 item 改值后都 `sync(settings[6])` |
| C2 | `0x080045EE` | `0x15EE` | `02 d1` (`bne 0x080045F6`) | `00 bf` (`nop`) | 编辑“−”`0x080045AC`：同上 |

- 机制：原厂只在 `item==6`（F7 ID）改值后 `bl 0x0800B9AC(id=settings[6])`；NOP 掉 `bne` 后，
  **任何 C.Fn 改值（含 F8）都会重设一次同步字**，代价是多一次 20µs+1ms 的 sync（无副作用）。
- 实测（V6）：原厂改 F8：sync 调用 0 次；打 C 组：sync 调用 1 次；改 F7 时原厂/候选都 1 次（行为不变）。
- 注意：本组不是“密钥逻辑”本身——`0x0800B9AC` 内部的 `SYNC = settings[7] ? KEY : 50024/(id+1)`
  由 Lead 的 `devices/ad200.py` 负责；C 组只保证“切换后立即调用它”。

## 6. 风险清单与建议

| 风险 | 说明 | 建议/候选点 |
|---|---|---|
| 稳定色温功能被替换 | F8=ON 后原厂“按下不改变输出”不再成立 | A 组屏蔽；文档写明“刷回原厂恢复” |
| 未屏蔽时闪光行为改变 | 时长/功率换算/RF 上报/显示都会变（实测时长表 210→360） | **必须 A 组**，否则不能宣称“其他行为原厂” |
| 密钥开关被静默关掉 | `ui_key_80` 的 0x0800BC7E 会在模式切换时清 settings[7] | B 组 NOP；否则用户按到该键会掉回原厂同步字 |
| 切换后不立即生效 | 改 F8 不触发 sync，要等重启/再改 F7 | C 组（或 Lead 在自己的 patch 里等价处理） |
| 保存防抖 200 次主循环 | 改完 F8 后 ~数百 ms 内断电会丢失 | 可接受；若要更强可另加“改值即保存”，非必需 |
| 恢复出厂会关掉密钥开关 | 长按双键（ui_key_scan_task 中 `r4==0x14`）→ 0x080048E4 → F8=0 | 文档说明；这是原厂行为，可接受 |
| 加载 clamp | 若 flash 字节 31 被写成 >1，加载会清 0（防坏值） | 保持不动（F8 合法值只有 0/1） |
| 每次上电擦写参数页一次 | 原厂 `0x0800AC58` 末尾擦页+重写 slot0（已有磨损行为） | 非本次引入，记录即可 |
| UI 显示 | F8 页显示 ON/OFF；A 组不动渲染，所以密钥开关状态可见 | 无需额外改动 |

**未验证/推测**：
- `0x08005C30` 的 `0x20000134+0x12/0x14` 下游消费者未继续追（推测为测量/显示功率，标记推测）；
- key 0x80 的物理按键标签（推测 row2,col1）；
- 保存倒计时 tick 的绝对墙钟时间（我们按“主循环次数”实测=200，未换算 ms）。
- 未在任何真实硬件上验证（仅 Unicorn 行为级仿真）。
