# Godox V1C（V1C_V2.0.bin）C.Fn 子系统分析 —— 开关项选择与读者/持久化证据

> task-4 / 独立固件审计员 **fw-auditor**；写范围 `devices/v1c/re/`、`keypatch/dev/v1c/`。
> 结论先行：**建议复用 item2（F3 STBY）作为私有密钥开关**；V1C 的 **item7 不是 AD200 的
> 稳定色温设置，而是 BEEP（提示音）**——Lead 初扫里「item7≈稳定色温」的假设不成立。
> 所有证据均来自 `devices/v1c/firmware/V1C_V2.0.bin`（88032 B，sha256
> `4435dda84903cb97cfaf34f7eeb15ecb6168771d60b57da1c346e6a9ca36edfb`，未改动）+
> Capstone 静态数据流 + 调用图，未做实机验证。

## 0. 一句话结论

| 问题 | 结论 |
|---|---|
| C.Fn 项数与索引 | settings 数组基址 **0x20001086**，项 0..0xB（12 项），item n = settings[0x20001086+n]；最大值/回绕表 **0x08018362** = `[1,1,1,1,1,0x1F,0x63,1,2,0x06,1,1]`（与 Lead 初扫一致） |
| 项名 | 固件内无 ASCII 项名；按 V1 说明书 C.Fn 顺序 + 固件最大值表逐项对齐，得：F1 m/ft、F2 AF、F3 STBY、F4 RX STBY、F5 SCAN、F6 CH、F7 ID、F8 BEEP、F9 LIGHT、F10 LCD、F11 FEB ACL、F12 TX（item0..11） |
| 首选开关项 | **item2 = F3 STBY**：max=1、出厂默认 0、菜单显示 OFF/ON；唯一功能读者 0x080124DC（待机任务），mask 成 `movs r0,#0` 即恢复出厂行为；不涉及 RF/闪光/GPIO 输出。见 §8 |
| item7 是什么 | **BEEP（提示音开关）**，max=1、默认 1；读者 16 处（应用函数 0x08003AE8 + 多路 UI/按键/显示）。**不是稳定色温**（V1C 的 C.Fn 里没有 AD200 F8 那项）。见 §7 |
| 持久化 | settings[0..0xD] 全部写入 flash 参数记录（record +0x2C..+0x3B，slot 0x0801F000+slot*100，头字节 0x5C）；上电 load → 0x080158B0 展开；无有效记录 → 0x080066D0 写出厂默认。见 §5 |
| 代码洞 | **0x08017944（234B）与 0x08017D28（222B）确认为死区**：全 0，无 BL/分支/ldr 字面量/u32 绝对地址引用；其它小全 0 段（0x0801749E/0x08016F0A 等）有引用，不安全。见 §9 |
| 立即生效 hook | 两个改值处理函数 0x0800625C / 0x0800D46E 的 `cmp/beq` 门（4B）改 `bl hook`；hook 放 0x08017944（10B）：`push {r0-r4,lr}; ldrb r0,[r0,#6]; bl 0x080121BC; pop {r0-r4,pc}`。调用级语义见 §8.3 |

**对 Lead 初扫骨架的两处修正**（不影响 settings 基址/项数/最大表结论）：

1. **item7 不是「稳定色温」**：V1C 的 item7 = **BEEP**（提示音），max=1、默认 1；AD200 的
   F8=稳定色温是 AD200 自己的 C.Fn 表，不能套到 V1C。见 §7。
2. **item0xB 不是 CH**：item0xB = **TX**（无线发送模式/标志，max=1、默认 1）；
   改值后复制到 RAM **0x200004F5** 的是 TX 标志镜像，不是频道。**CH 是 item5**
   （max=31、默认 0x14；显示为 settings[5]+1 → 1..32；0x080060FC 把它抄到 0x2000054A）。
   见 §3/§4。

## 2. C.Fn 项布局与项名（独立确认 Lead 骨架）

- settings 基址 **0x20001086**（51 处 ldr 字面量引用）；ID = settings[6] = **0x2000108C**
  （与 `re/audit_static.py` 独立审计一致；旧 `log_scan4.txt` 的 0x200004F5 候选是回溯 bug，已废弃）。
- 最大值/回绕表 **0x08018362**，12 字节：
  `01 01 01 01 01 1F 63 01 02 06 01 01`
  = item0..11 的 max：1,1,1,1,1,31,99,1,2,6,1,1。
  引用点：0x08006254（dec 处理）、0x0800D438（inc 处理）、0x08010136（设置应用）。
- 项索引边界：`cmp #0xB` 遍布 C.Fn 处理/显示/持久化路径（0x08006260、0x0800D472、
  0x08005232、0x08006408 等），支持「12 项、0..0xB」。
- **项名来源说明**：固件内没有可直接读取的 C.Fn 项名字符串（UI 用字模/段码）。
  本报告用两个独立线索对齐项名：
  1. Godox V1 公开说明书的 C.Fn 页顺序（外部佐证，非固件内容）：
     P1 m/ft、AF、STBY、RX STBY；P2 SCAN、CH、ID、BEEP；P3 LIGHT、LCD、FEB ACL、TX
     （<https://sugarcamera.work/godox-v1-manual07/>）；
  2. 固件最大值表与上述顺序逐项吻合：item5=CH(max 31)、item6=ID(max 99)、
     item9=LCD(max 6)、item8=LIGHT(max 2)；且固件行为可交叉验证：
     item5 显示为 settings[5]+1（1..32，频道）、item6 调同步字函数（ID）、
     item9 由专用函数 0x08014EF8 处理（LCD 亮度/对比度）、item8 控制造型灯 GPIO。
  该项名表在报告中用于可读性；**真正的开关项选择只依赖固件地址/读者/max/默认值**。

## 5. 持久化、记录布局、出厂默认

### 5.1 save / load

- **save 记录 builder**：0x08005EF0..0x080060DB；settings 拷贝段 0x08006004..0x08006066。
  它把 settings[0..3] → record+0x2C..0x2F（实际字节序 record[0x2C..0x2F] =
  [settings2, settings3, settings0, settings1]，需按 4 字节 word 拼装理解）、
  settings[4..7] → record+0x30..0x33、settings[8..0xB] → record+0x34..0x37、
  settings[0xC..0xD] → record+0x38..0x3B。
  调用者：0x0800E9BC、0x0801189E（保存链路）。
- **load/expand**：0x080158B0（无 BL 的叶函数，从 RAM buffer 0x20000FA4 展开）：
  record[0x2E..0x2F] → settings[0..1]；record[0x30..0x33] → settings[2..5]；
  record[0x34..0x37] → settings[6..9]；record[0x38..0x3B] → settings[10..13]。
- **加载/默认任务**：0x0800FEF8（settings load task）
  - 从 **0x0801F000 + slot*100** 读取记录到 0x20000FA4（0x0800FF12/0x0800FF16，
    最多 20 个 slot：0x0800FF00 置 0x14 后递减）；
  - 记录头字节 **0x5C** 为有效标记（0x0800FF1E/0x0800FF32）：
    有效 → `bl 0x080158B0`（0x0800FF34）展开；
    无有效记录 → `bl 0x080066D0`（0x0800FF76）写工厂默认；
  - flash 参数页地址：0x0801F000（记录槽）、0x0801F800（校验/备份）字面量出现在
    0x08009D48、0x0800FED8、0x0800FF12、0x080118BC。

### 5.3 0x20001070 紧凑结构重叠 quirk（影响无线设置同步）

- 0x0800A6AC：settings[0,1,2,3,7,8,10] → 紧凑结构 0x20001070 的
  c[0]=s0、c[1]=s2、c[3]=s10、c[8]=s1、c[0xA]=s3、c[0x14]=s7、c[0x16]=s8；
  被 0x08003B7C（由 RF 设置打包路径 0x08012EF2 调用）调用。
- 0x0800A6DC：反向 c[0/1/3/8/0xA/0x14/0x16] → settings[0,2,10,1,3,7,8]；
  被 0x080125A8..0x08012790 的 RF 设置应用路径调用。
- **注意**：0x20001070 + 0x16 = **0x20001086 = settings[0]**。因此 0x0800A6AC 最后一条
  `strb r1,[r0,#0x16]` 实际写到了 settings[0]（原厂内存布局重叠；疑似 quirk）。
  该函数路径与「无线设置同步」相关；说明 item0/1/2/3/7/8/10 **可能被 RF 设置同步覆盖**。
  选 item2 时必须把这一点列入真机/模拟器验证项；必要时把 RF 设置应用写点也 mask。
- item4/5/6/9/11 不在这对紧凑结构里，但 0x0800DCDC（设置应用路径）仍会写 settings[0..11]。

## 7. item7 专项：是 BEEP，不是稳定色温（修正 Lead 初扫假设）

Lead 初扫写「item7 可能等同 AD200 F8=稳定色温」。**不成立**：

- V1 说明书的 C.Fn 顺序中 P2 是 `SCAN, CH, ID, BEEP` → item7 = **BEEP**；最大值表
  item7=1、默认 settings[7]=1，与「提示音开关」一致。
- 固件内 item7 的应用函数 **0x08003AE8**（由 C.Fn 设置应用 dispatcher 0x08015B7E 调用）
  读取 settings[7] 后配置 UI/提示音状态；另有 15 个读者分布在
  0x080067CC、0x08008284、0x08008870、0x08008B2C、0x08008F00（5 处）、
  0x08010984、0x08010A98 等 UI/按键/显示/应用路径。
- 对照 AD200：AD200 的 F8（item7）= settings[7]=稳定色温，是 **AD200 自己的 C.Fn 表**；
  V1C 的 C.Fn 表不同（12 项、含 LIGHT/LCD/TX 等），不能把 AD200 的项语义直接套到 V1C。

**item7 全部读者与屏蔽方法**（若坚持复用；默认 1 要求反相语义 0=KEY）：

## 7.1 item8 / item10 / item11 的屏蔽成本对比（含 mask 字节）

## 8. 推荐方案：item2（F3 STBY）作密钥开关

### 8.1 语义与屏蔽

- 新语义：`settings[2] == 0` → 普通模式（sync = 50024/(ID+1)）；
  `settings[2] == 1` → 密钥模式（sync = KEY）。
  出厂默认 settings[2]=0，因此新刷/恢复默认 = 普通模式。
- **需 mask 的功能读者（唯一）**：

```
0x080124DC  原厂 90 78 (ldrb r0,[r2,#2])  ->  00 20 (movs r0,#0)
```
  效果：0x080124D8 待机任务看到 settings[2]=0，始终按出厂默认运行待机计时，
  用户把 F3 设为 ON 不会关闭自动待机。
- **保留不 mask 的读者**：
  - 菜单渲染 0x08004B4E/0x08004B5E：继续显示 F3 的 ON/OFF，用户能看到密钥开关状态；
  - save 0x08006012 / load 0x080159D4：持久化（必须保留）；
  - 0x0800DCDC / A6AC/A6DC：无线设置同步路径（见风险，不建议盲目 mask，需实机确认）。

### 8.2 立即生效 hook（代码洞 0x08017944）

原厂只有 item==6(ID) 改值才调用同步字函数；改成 item2 后必须在 F3 改值时立即调用。
方案：把两个改值处理函数里的 `cmp/beq` 门（4B）改成 `bl hook`，hook 无条件调用同步字函数：

```
hook @0x08017944 (10B):
  1f b5        push {r0, r1, r2, r3, r4, lr}
  80 79        ldrb r0, [r0, #6]          ; r0 已是 settings 基址 -> r0 = ID
  fa f7 38 fc  bl   0x080121BC            ; 同步字函数（Lead 将改为读 settings[2] 标志）
  1f bd        pop  {r0, r1, r2, r3, r4, pc}  ; 返回原处理函数继续
```

| 位置 | 原厂 4B | 改为 | 说明 |
|---|---|---|---|
| 0x0800625C（dec 处理） | `06 29 08 d0` = `cmp r1,#6; beq 0x08006272` | `11 f0 72 fb` = `bl 0x08017944` | 改值路径（含 ID、chosen item）都调用 sync；item11 特殊处理路径保留（hook 返回后继续执行 0x08006260 的 item11 分支） |
| 0x0800D46E（inc 处理） | `06 29 07 d0` = `cmp r1,#6; beq 0x0800D482` | `0a f0 69 fa` = `bl 0x08017944` | 同上 |

已核实：
- hook 入口处 r0 = settings 基址 0x20001086（两个门点都用 CFG 前驱 + 反向数据流确认）；
- hook 10B 可反汇编，BL 目标 = 0x080121BC；
- 两个 patch 点原厂字节、无分支/字面量指向中间（见 log PASS）；
- item9(LCD) 路径在原厂就绕过 gate（0x08006238/50 / 0x0800D45A 等），不会误触发；
- 每次 C.Fn 改值多一次同步字调用（2 次 SPI 写 + 20µs delay；Lead 版同步函数无线程依赖），
  可接受；原厂 ID 改值立即同步的行为保留。

> 注意：hook 无条件调用同步字函数；若 Lead 希望只在 item==2 或 item==6 时调用，可在 hook
> 里加 `cmp r1,#6 / cmp r1,#2` 判断（hook 仍有足够空间，0x08017944 可用 234B），
> 但当前 10B 版本最简单且行为安全。

### 8.3 为啥不改 `cmp #6` 为 `cmp #2`（不用代码洞的替代）

只把 gate 的 `cmp #6` 改成 `cmp #2` 会让 **ID 改值不再立即重写同步字**（正常模式下
用户改 ID 后要等下次 RF 初始化才生效），是回归。若想不加代码洞，可考虑把 inc/dec 的
gate 换成 `bl` 到空余 flash 的 10B hook——这本身就需要代码洞。结论：带洞的 hook 方案最小且不破坏 ID 行为。

## 9. 代码洞验证

| 地址 | 文件偏移 | 连续 0 长度 | 引用检查 | 结论 |
|---|---|---|---|---|
| 0x08017944 | 0x14944 | **234 B**（到 0x08017A2D） | 无 BL/分支/ldr 字面量；全镜像 u32 绝对地址（含 thumb 变体）0 处 | **可用**；hook 只用前 10B |
| 0x08017D28 | 0x14D28 | **222 B**（到 0x08017E05） | 同上，0 引用 | **可用**（备用） |
| 0x0801749E | 0x1449E | 57 B | 有 **1 处 ldr 字面量 / 1 处 u32 绝对地址** 指向 | 不安全，不使用 |
| 0x08016F0A | 0x13F0A | 36 B | 有 **1 处分支目标** 落入 | 不安全，不使用 |
| 0x08016F42 | 0x13F42 | 29 B | 有 **1 处分支目标** 落入 | 不安全，不使用 |

> 说明：这些全 0 段在线性反汇编里会被 capstone 解成 `movs r0,r0`（0x0000 是合法 Thumb 指令），
> 但**没有任何代码/分支/字面量指向 0x08017944 / 0x08017D28**，它们不在函数入口链上，
> 因此是可安全覆盖的死区。检查口径：所有 BL/BLX 目标、所有 B/条件分支目标、
> 所有 LDR(literal) 目标、全镜像按 2 字节步长扫描的 4 字节绝对地址（含 |1 thumb 变体）。
> 较小的全 0 段（0x0801749E/0x08016F0A/0x08016F42 等）仍有字面量/分支引用，不要使用。

## 10. 风险与未验证项

1. **无实机验证（最高风险）**：本报告是静态分析；未在 V1C 真机/整机模拟器上验证：
   - F3 在菜单里确实显示为 STBY ON/OFF、可编辑并持久化；
   - mask 0x080124DC 后待机行为与原厂一致（不出现意外待机/不休眠）；
   - hook 后改 F3 立即改变同步字（需配合 Lead 改写的同步字函数读 settings[2]）；
   - 与未打补丁的引闪器/灯混用时的兼容性。
2. **无线设置同步可能覆盖密钥标志**：item2 被 0x0800DCDC（settings[1..11]）和
   A6AC/A6DC 紧凑结构（settings[2] ↔ 0x20001071）触及；如果 Godox 引闪器/上位机有
   「设置同步」功能，可能把 F3 覆盖回 0（关闭密钥）。需要验证；必要时把对应写点
   mask 成「保留 bit」或改从其它存储位读密钥标志。
3. **mask 掉 STBY 的代价**：原厂 F3=ON（settings[2]=1）会关闭自动待机；复用后该功能
   被强制恢复为默认（待机计时始终启用）。用户失去原厂 F3 功能，菜单仍显示 STBY，
   需要文档说明「F3 已改为密钥开关」。
4. **菜单项命名/文档**：用户看到的是 F3 + OFF/ON（或 STBY OFF/ON），不是「KEY」；
   需在 README/使用说明中写清 F3=ON 即密钥模式。
5. **hook 的额外同步调用**：每次 C.Fn 改值（任意项，item9 除外）都会写 SYNC1/SYNC0 +
   20µs delay；只在用户改 C.Fn 时发生，频率极低；如果 Lead 的同步字函数保留 SCAL/1ms
   会放大开销，建议保持「去 SCAL、保留 20µs」的设计。
6. **item10 FEB ACL 语义未完成**：0x08005548 同时操作 GPIO/RF/定时器，未能完全定性；
   本报告只把它列为「待定」，未推荐。
7. **固件版本锁定**：本报告只对 V1C V2.0（sha256 4435dd…edfb）有效；换版本必须重跑
   `cfn_settings.py` 并重新确认地址/读者/默认值/代码洞。
8. **未修改任何补丁模块**：`keypatch/devices/v1c.py` 由 Lead 负责；本报告只给设计建议
   （chosen item / mask / hook / cave），未写入该文件。
