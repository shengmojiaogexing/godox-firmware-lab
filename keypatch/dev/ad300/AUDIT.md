## 2. 关键证据（全部来自 `audit_cfn.py` 的可复跑输出）

### 2.1 同步字函数 0x0800B548（56 B，逐字节一致）

```
原厂字节: 0c4a10b5411c1046f7f7cefd0446010a042000f08effe1b2052000f08aff14
          2000f04afe332000f0e5ff7d20c00000f043fe10bd68c30000
```
反汇编（含字面量解析）：
```
0800B548: 0c4a       ldr    r2, [0x0800B57C]  ; = 0x0000C368 = 50024
0800B54A: 10b5       push   {r4, lr}
0800B54C: 411c       adds   r1, r0, #1        ; r1 = ID + 1
0800B54E: 1046       mov    r0, r2            ; r0 = 50024
0800B550: f7f7cefd   bl     0x080030F0        ; uidiv(50024, ID+1) -> 商/余数
0800B554: 0446       mov    r4, r0
0800B556: 010a       lsrs   r1, r0, #8       ; SYNC1 = 商 >> 8
0800B558: 0420       movs   r0, #4
0800B55A: 00f08eff   bl     0x0800C47A        ; WriteReg(4, 商>>8)
0800B55E: e1b2       uxtb   r1, r4
0800B560: 0520       movs   r0, #5
0800B562: 00f08aff   bl     0x0800C47A        ; WriteReg(5, 商&0xFF)
0800B566: 1420       movs   r0, #0x14          ; 20
0800B568: 00f04afe   bl     0x0800C200        ; delay(20)
0800B56C: 3320       movs   r0, #0x33          ; SIDLE strobe
0800B56E: 00f0e5ff   bl     0x0800C53C        ; strobe(0x33)
0800B572: 7d20       movs   r0, #0x7d
0800B574: c000       lsls   r0, r0, #3        ; 0x3E8 = 1000
0800B576: 00f043fe   bl     0x0800C200        ; delay(1000)

```
- 同步字 = `50024 / (ID+1)`，ID=0 时为默认 `0xC368`；商最大 50024、最小 500（ID=99），始终 16 位，无除零（分母 ID+1）风险。
- 函数边界：前一函数 `0x0800B508` 以 `pop {r4,pc}`(0x0800B542) 结束，`0x0800B544` 为其字面量；下一函数 `0x0800B580` 有独立调用者 `0x0800865A`；全镜像**无** BL/代码指针跳入 `0x0800B548..0x0800B580` 内部 → **56 B 是完整、安全的补丁空间**。

### 2.4 SYNC1/SYNC0（寄存器 4/5）全镜像写入点

解析全部 56 个 `WriteReg` 调用点的 r0（寄存器地址）后，写寄存器 4/5 的**只有 4 处**：

| 调用点 | 寄存器 | 值 | 含义 |
|---|---|---|---|
| `0x0800B55A` | 4 (SYNC1) | 商 >> 8 | 同步字函数（原厂 ID→同步字） |
| `0x0800B562` | 5 (SYNC0) | 商 & 0xFF | 同上 |
| `0x0800C25E` | 4 (SYNC1) | `0xC3` | CC2500 初始化表（默认同步字高字节） |
| `0x0800C266` | 5 (SYNC0) | `0x68` | CC2500 初始化表（默认同步字低字节） |

- 初始化函数入口 `0x0800C230`，**全镜像唯一调用者 `0x0800487E`**；同一函数 `0x08004868` 在其后 `0x080048CE` 调用同步字函数 → **初始化早于同步字应用**成立。
- 无其他路径可绕过 WriteReg 写寄存器 4/5：`0x0800C554`（burst 写）只有 3 个调用点，分别写 PATABLE burst(0x7E)、TXFIFO(0x7F) 与 WriteReg 自身，未出现 0x44/0x45。
- 400 字节之后的 `0x0800C3B2..0x0800C3D8` 为初始化尾部：写 PATABLE burst → `strobe(0x33)` → `delay(1000)` → `strobe(0x39)` → `delay(1000)`。

### 2.6 C.Fn 结构与门控

- 8 项索引 `[0x20000190+0x17]`：dec 处理函数 `0x08004680..0x0800468E`（`0 → 7`）；inc 处理函数 `0x0800842E..0x0800843A`（`7 → 0`）。
- 最大值表 `0x0800DA64` 前 8 字节：`01 02 03 96 02 01 63 01` → item0..7 max = `1,2,3,150,2,1,99,1`；inc 处理函数 `0x08008410` 的字面量 = `0x0800DA64`，dec 处理函数 `0x08004690` 的字面量 = `0x0800DA64`。
- 门控字节（**原厂**）：

| 处理函数 | 地址 | 字节 | 反汇编 |
|---|---|---|---|
| dec | `0x08004674` | `06 2a e0 d1` | `cmp r2,#6` ; `bne 0x0800463A` |
| inc | `0x08008422` | `06 28 de d1` | `cmp r0,#6` ; `bne 0x080083E4` |

- 补丁：`0x08004677: D1→D3`、`0x08008425: D1→D3` → `BLO`（无符号 <6 才跳过），item 6/7 改值后都会执行 `bl 0x0800B548`。
- 两条 gate 都是“先存值、后判断”：dec 在 `0x08004672` 已 `strb`，inc 在 `0x08008418`/`0x08008420` 已 `strb`，所以 F8 新值在调用同步字函数前已生效。

### 2.8 持久化链

```
builder 0x08004410(记录指针)
  +0x00 = {0x5C 魔数, 0x200001A1, 0x200001A9, 0x20000191}
  +0x04/+0x08/+0x0C/+0x10/+0x14 = 其它状态字
  +0x18 = settings[0..3] 字   <-- 0x080044B6
  +0x1C = settings[4..7] 字   <-- 0x080044CA（F8 在最高字节 0x080044C4）
save 0x0800B38C(slot): builder(0x20000460) -> 拷贝 8 words -> 0x20000440
                        -> flash 写(0x0801F000 + slot*100)  ; 0x080056DC 固定写 8 words=32 B
load 0x0800AB6C: 槽号 0x14->0 递减；flash 读(0x0801F000+slot*100) -> 0x20000440
                 ; 校验记录[0]==0x5C；有效 -> 0x0800C814；无效 -> 默认初始化 0x080048EC
                 0x0800C814: 记录 +0x18 -> settings[0..3]；+0x1C -> settings[4..7]
                             settings[7] 回填指令 = 0x0800C8D0
0x0800AB6C 尾部 0x0800ACDA..0x0800ACF2: 按 max 表钳制 settings[0..7]（超限写 0）
```
- 由此保证：**加载后 item7 只可能为 0/1、item6(ID) 只可能为 0..99**。
- flash 记录实际负载 32 B，槽间距 100 B；默认初始化 `0x080048EC` 把 settings[7] 写 0（`0x0800492A`），其调用者：`0x08008864`（协议命令分支）与 `0x0800AC0A`（无有效 flash 记录时回退）。

### 2.9 时序（静态推断）

```
Reset(0x080030D4) -> __main(0x080030C0) -> 应用初始化 0x0800C910
  0x0800C98C  bl 0x0800AB6C   ; flash 参数加载（含 F8 回填 + max 表钳制）
  0x0800C990  movs r0,#1
  0x0800C992  bl 0x0800A6AC   ; 射频初始化入口
       0x0800A804  bl 0x0800B7B0
            0x0800B7F4  bl 0x08004868   ; 初始化表(0x0800C230) + 同步字(0x080048CE)
```
→ **启动时 F8 先从 flash 恢复，再执行 RF 初始化/首次同步字应用**（静态顺序推断，建议实机确认）。另外，`0x08004868` 内的同步字调用紧跟在初始化之后，因此运行期若再次触发 CC2500 初始化，也会立刻按当前 F8 重新应用同步字。

## 3. ⚠️ 与任务描述不一致 / 需要修正 / 需要注意的点

1. **⚠️ 第 5 条“item 7 的全部读者/写者”列表不完整。** 除列出的 6 个静态读者外，还有 **`0x080044C4`（参数记录 builder 读 settings[7]）**，以及 3 类**动态索引**访问：`0x0800466A/0x08004672`（“−”handler）、`0x08008412/0x08008418/0x08008420`（“+”handler）、`0x0800ACE2/0x0800ACEA`（加载后按 max 表钳制，循环 8 项）。6 个静态读者本身全部正确，写者也全部复现。
2. **⚠️ 第 4 条引用的最大值表字节串跨表。** `01 02 03 96 02 01 63 01 01 01 07 06…` 中，**只有前 8 字节**属于 8 项最大值表（`0x0800DA64..0x0800DA6B`）；第 9 字节起已经是相邻的另一张表，容易误读。
3. **第 2 条“初始化表（0x0800C2xx 区域）”需要更精确：** 初始化函数入口是 `0x0800C230`，写 reg4/reg5 的指令是 `0x0800C25E`（reg4=0xC3）与 `0x0800C266`（reg5=0x68），即默认同步字 `0xC368 = 50024`——这正好解释了同步字函数为什么用 50024 做被除数。
4. **第 5 条“0x0800B6C8 建议 NOP”：该指令是 2 字节 `strb`（半字 `0x71D1`）**，NOP 应写 `0xBF00`（不是 4 字节 NOP）。该路径除清 F8 外还会修改 `[0x20000190+0x11]` 与 `[+0x13]`，只 NOP 这条 `strb` 不会改变其它副作用，但会保留“电源/退出路径”的其余行为。
5. **第 2 条“50024 字面量唯一”成立，但需注意 `0x0800BB03` 处也有字节串 `68 C3`**——它跨越 `0x0800BB02`（`ldr r2,[r0,#4]`）与 `0x0800BB04`（`ldr r3,[r0,#0x1c]`）两条指令的编码字节，属巧合，不是常量引用。镜像中 32 位字面量 50024 确实只有 `0x0800B57C` 一处。
6. **（补充，任务未提及）启动顺序：** flash 参数加载 `0x0800AB6C` 在应用初始化 `0x0800C910` 中先于射频初始化 `0x0800A6AC/0x0800B7B0/0x08004868` 执行，因此开机时 F8 已被恢复，首次同步字调用能读到正确 flag。但若退出路径 `0x0800B6C8` 把 F8 清零而 flash 记录仍为 1，则 RAM 与 flash 会不一致（见风险 R3）。
7. **（补充，任务未提及）加载后的钳制：** `0x0800AB6C` 尾部 `0x0800ACDA..0x0800ACF2` 按最大值表把 settings[0..7] 中超过最大值的项写 0 → item7 只可能 0/1、ID 只可能 0..99；补丁按 `==1` 判断是安全的。

## 4. 风险点（静态审计无法覆盖，必须实机验证）

| # | 风险 | 说明 / 建议 |
|---|---|---|
| R1 | **无实机验证** | 私有同步字是否被发射器接受、C.Fn 菜单 8 项显示与按键流程、flash 写入寿命/掉电原子性、`0x0800B6C8` 清零路径的真实触发条件，均未在真机验证 |
| R2 | **F8 复用了原厂“稳定色温/固定校准表”功能** | F8=1 时原厂 6 个读者会同时进入另一套校准/功率/显示表分支（闪光输出、功率、显示都可能变化），不只是无线同步字开关；原厂用户打开“稳定色温”也会意外切到私有同步字。必须文档警示，或改用其它 C.Fn 项/代码洞方案 |
| R3 | **退出路径静默清零 F8（0x0800B6C8）** | 不 NOP → 特定电源/退出路径把 RAM 中 F8 清 0，而 flash 记录可能仍为 1，导致重启前后同步字与用户设置不一致；NOP → 失去原厂该路径的“清 F8”语义（功能取舍，且该路径还有别的状态修改） |
| R4 | **去掉 SCAL(uidiv 50024/(ID+1)) / 延时** | 原厂写 SYNC1/SYNC0 后 `delay(20) + SIDLE strobe(0x33) + delay(1000)`。补丁若省掉 uidiv/delay/strobe：(a) 失去 ID→同步字 的原厂映射；(b) 在 CC2500 处于 TX/RX 时改同步字可能不生效。建议至少保留 `strobe(0x33)` + 两段延时 |
| R5 | **56 字节空间限制** | `0x0800B548..0x0800B57F` 共 56 B（含 +0x34 的 4 B 字面量槽）。补丁（读 F8 + 两次 WriteReg + 条件分支 + 时序）必须 ≤56 B；>56 B 会覆盖下一函数 `0x0800B580`（其调用点 `0x0800865A` 会被破坏）。补丁生成后应断言写入长度 |
| R6 | **F8 语义应 `==1` 判断** | RAM 中 item7 只可能 0/1（UI max 表 + 加载钳制），但补丁仍建议 `cmp #1; beq`（与原厂 6 个读者一致），不要用 `!=0` |
| R7 | **门控补丁的副作用面** | 改 `0x08004677/0x08008425` 后 item7 改值会调用同步字函数，item6(ID) 行为不变；需实机确认 C.Fn 编辑时 item7 的 ± 能进入编辑分支（条件是 `[0x20000190+0x16]!=0`），以及菜单只有 8 项不会越界 |
| R8 | **固件整体校验未确认** | 未发现应用镜像自校验/签名，但不能排除烧录/升级流程中的校验；改造后的镜像能否通过官方升级通道需另测 |
