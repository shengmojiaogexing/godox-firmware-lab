# 私有密钥「可开关 + 兼容」设计（v3 = UI 版，用户已拍板）

> 版本说明：
> - **v1**：固定密钥（已完成验证，过渡版）。
> - **v2**：用现有 ID 菜单当开关（灯 ID=OFF→密钥；引闪器 ID=99→双发 ID99 普通帧）。见本文后半部分（历史设计，作为回退）。
> - **v3（当前目标，用户拍板）**：灯和引闪器都在**固件菜单里新增独立开关**；引闪器开密钥时按**当前 ID** 双发
>   （私钥帧 + 普通帧），能引闪"同频道、同 ID、没开密钥"的灯。
>   用户已确认：X3-C 新标签**自绘汉字字模**（密钥/广播），AD100 Pro / AD200 Pro 用英文缩写；广播入口放 **X3-C 快捷面板**。

## v3 最终行为

| 设备 | 开关位置 | 行为 |
|---|---|---|
| AD100 Pro / AD200 Pro | 灯菜单 C.Fn 新增一项（英文缩写；AD200 段码屏受限时用 F 编号 + ON/OFF） | 开=同步字用私有 KEY；关=原厂 50024/(ID+1)，设置持久化 |
| X3-C | 快捷面板新增「密钥」磁贴（自绘字模） | 开=每帧双发（先私钥帧、再按**当前 ID**的普通帧）；关=原厂单发 |
| X3-C | 快捷面板新增「广播」磁贴 | 广播页：范围（全频道 / 全频道+全ID）、功率用当前设置、造型灯用当前开关；执行后扫 CH1–32 广播引闪 |

### 引闪器双发（v3 核心）
```
if (KEY_ON_FLAG != 0):
    reg4/5 = KEY;        send(frame)      # 密钥灯
    pub = 50024/(RAM[0x20000055]+1)
    reg4/5 = pub;        send(frame)      # 同 CH/同 ID 的普通灯
else:
    send(frame)                            # 原厂行为
最后 reg4/5 = pub（供收包）
```
注入区：0x080EE000 起（fw-x3c）；UI/字模/广播注入区：0x080F0000 起（ui-x3c）。
`KEY_ON_FLAG` 地址由 ui-x3c 在 UI 状态结构里选定并写进 `keypatch/dev/x3c_ui/FEASIBILITY.md`。

## 1. 用户可见语义（用现有 ID 菜单当开关，零 UI 改动）

| 设备 | ID 设置 | 2.4G 同步字行为 |
|---|---|---|
| 灯 AD100 Pro / AD200 Pro（已打补丁） | **ID = OFF** | 密钥模式：只接受私有 KEY 同步字 |
| 灯（已打补丁） | ID = 1..99 | 普通模式：SYNC = 50024/(ID+1)（与原厂一致） |
| 引闪器 X3-C（已打补丁） | **ID = 99** | 密钥模式：每次发帧先发 KEY 帧（引闪密钥灯），再发 ID99 普通帧（引闪同 CH/同 ID99 的普通灯） |
| 引闪器（已打补丁） | ID = 0..98 | 普通模式：只发原厂 ID 同步字帧 |

推荐用法：
- 只用自己的灯：灯 ID=OFF，引闪器 ID=99。
- 用自己的灯 + 别人/备用灯（同 CH、ID=99）：同上，引闪器双发自动兼容。
- 完全普通模式：灯 ID=1..99，引闪器 ID=0..98（与原厂一致）。

> 注意：ID=OFF 在灯上不再表示"无 ID 的普通模式"，而是"密钥模式"。
> 灯/引闪器都刷了补丁后，必须用上表配对，否则收不到。

## 2. 灯端补丁（AD100 Pro / AD200 Pro 通用思路）

把"ID → 同步字"函数**整段改写**为：

```
sync = (id == 0) ? KEY : 50024/(id + 1);
WriteReg(4, sync >> 8);  WriteReg(5, sync & 0xFF);
delay_us(20);
return;                  // 去掉了原来的 SCAL + delay(1ms)
```

### 原位布局（正好 56 字节，不越界）

AD100 Pro：函数 0x0800B758，空间到 0x0800B790（下一个函数起点）。
AD200 Pro：函数 0x0800B9AC，空间到 0x0800B9E4。

```
+00  ldr  r2, [pc, #0x2C]     ; =KEY          （字面量在 +0x30）
+02  push {r4, lr}
+04  cmp  r0, #0              ; id == 0 ? 密钥模式
+06  beq  +0x10               ; -> keymode
+08  ldr  r2, [pc, #0x28]     ; =50024        （字面量在 +0x34）
+0A  adds r1, r0, #1
+0C  b    +0x14               ; -> go
+0E  movs r1, #1              ; keymode: 除数=1
+10  mov  r0, r2              ; go: 被除数
+12  bl   <__aeabi_uidiv>     ; r0 = r2 / r1
+16  mov  r4, r0
+18  lsrs r1, r0, #8
+1A  movs r0, #4
+1C  bl   <WriteReg>
+20  uxtb r1, r4
+22  movs r0, #5
+24  bl   <WriteReg>
+28  movs r0, #0x14
+2A  bl   <delay_us>
+2E  pop  {r4, pc}
+30  .word KEY (32 位)
+34  .word 50024 (32 位)
```

关键地址：

| 固件 | 函数入口 | __aeabi_uidiv | WriteReg(reg,val) | delay_us(n) |
|---|---|---|---|---|
| AD100 Pro V1.2 | 0x0800B758 | 0x080030F0 | 0x0800CD32 | 0x0800CAB8 |
| AD200 Pro V1.60 | 0x0800B9AC | 0x080030F0 | 0x0800CAA2 | 0x0800C828 |

参考实现（Lead 已验证 ID=0→KEY，ID=1/37/99→原厂值）：
`keypatch/dev/lead/toggle_proto.py`（含 Thumb 指令编码器、BL 编码、Unicorn 验证）。

### 为什么可以去掉 SCAL + 1ms 延时
原函数在写 SYNC1/SYNC0 后做 `delay(20us) → SCAL(0x33) → delay(1ms)`。
SCAL 是给频率合成器重新校准用的；本补丁只改同步字、不改 FREQ2/1/0，
不需要 SCAL。保留 20µs 建立时间即可。风险低，但需在 NOTES 注明。

### 灯端不变式（两条很重要）
1. CC2500 初始化仍写 0xC3/0x68，但 `RF_Init` 紧接着调用本函数覆盖；本补丁不改初始化表。
2. 全镜像只有本函数与初始化表写 SYNC1/SYNC0；没有其它运行期路径会重置同步字
   （已由 fw-ad100/fw-ad200 的静态复核确认）。

## 3. 引闪器端补丁（X3-C v1.38，代码注入）

### 目标
- 当前 ID == 99 时：每个要发的帧发两次 —— 先 KEY 同步字发一次，再按 ID=99 的
  原厂同步字（500）发一次。
- 当前 ID != 99 时：保持原厂行为（只发一次）。

### 已定位的发射路径（Lead 已核实）
| 地址 | 作用 |
|---|---|
| 0x080118B0 | `send_short(cmd)`：组 [0xD5, cmd]，调 0x0801712C |
| 0x0801184C | `send_property(group, key, value)`：组 [0xA9, r0, r1, r2]，调 0x0801708C |
| 0x0801712C | 低层：写 2 字节 TX FIFO、STX(0x35)、delay、0x3B、SIDLE(0x36) |
| 0x0801708C | 低层：写 4 字节 TX FIFO、同上 |
| 0x08023540 | `write_reg(reg, val)`（r0=reg, r1=val） |
| 0x08023536 | 写 FIFO/突发写辅助 |
| 0x08014814 | 设置信道 ch |
| 0x08014864 | 按 ID 设置同步字（原厂公式，本设计**保持原样**） |

实现办法：在固件空闲闪存里放一段注入代码，把 `send_short` / `send_property`
入口改成跳转；注入代码：
1. 读当前 ID（需先定位 RAM 地址；初始化时 `0x080161A2` 用 0 调 0x08014864，
   说明 ID 来自某 RAM 字节/设置区）；
2. 若 ID==99：`write_reg(4, KEY>>8); write_reg(5, KEY&0xFF);` → 调用原始函数体 → 
   `write_reg(4, 500>>8); write_reg(5, 500&0xFF);` → 再调用一次原始函数体；
3. 否则直接执行一次原始函数体。

原始函数体可整段复制到注入区（需重算其中的相对 BL，函数都很小）。

## 4. 全频道/全组别「广播引闪」功能（第二期）

进入方式建议（待用户确认）：长按 TEST / 新增菜单项 / 特殊模式。行为：
对 CH 1..32 逐个：设置信道 → 发功率属性帧（组 ALL=0x50，可再补 A-E）→
发造型灯属性帧（按当前造型灯开关状态）→ 发 TEST/引闪帧（密钥模式时双发）。
结果：32 个频道的灯全部被闪（密钥灯不区分 ID；普通灯需 ID=99 命中）。
物理上无法真正"同时"，是快速顺序扫描（约 1 秒级）。
